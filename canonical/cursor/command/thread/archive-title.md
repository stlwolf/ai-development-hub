# Archive Title

スレッドの会話内容を分析し、アーカイブ用タイトルを1つ生成してクリップボードにコピーする。

## 入力形式

- なし（スレッド内で実行。会話コンテキスト自体が入力）

## フロー

```
完了状態チェック → 会話分析 → タイトル生成 → pbcopy → 確認メッセージ
```

## Step 1: 完了状態チェック

タイトル生成の前に、スレッドがアーカイブ可能な状態かを確認する。

### 確認項目

- 未完了のTo-Doやタスクが残っていないか
- 最後のやり取りが「次の指示待ち」状態になっているか
- 途中で中断・放置されたタスクがないか

### 判定

- **アーカイブ可能**: 全タスク完了済み、または明示的に別スレッドへ移行済み → Step 2 へ進む
- **未完了あり**: 未完了の項目を簡潔にリストアップし、ユーザーに確認する:

```
⚠️ 未完了の作業があります:
- {未完了項目1}
- {未完了項目2}

このままアーカイブしますか？
```

ユーザーが続行を指示した場合のみ Step 2 へ進む。

## Step 2: 会話分析

スレッド全体の会話を分析し、以下を把握する:

- 主題（何についてのスレッドか）
- 主要な成果物・決定事項
- 扱った技術・ツール・対象
- **GitHub Issue**: 会話の中心となっている Issue 番号（`#123` 形式で言及されているもの、ブランチ名・PR・ドキュメントパスに含まれる番号など）

## Step 3: タイトル生成 + クリップボードコピー

### タイトル生成ルール

- **個数**: 必ず1個だけ生成する。複数案は出さない
- **文字数**: 最大40文字程度（Cursorサイドバーで切れない長さ）。`#番号` を含める場合は主題側を短くし、実質的な長さが目安に収まるようにする
- **言語**: 会話の主要言語に合わせる（日本語の会話なら日本語、英語なら英語）
- **スタイル**: 名詞句・体言止め。文にしない
- **内容**: スレッドの主題を表す（「何をしたか」ではなく「何についてか」）
- **Issue 番号（必須条件付き）**: スレッドの主目的が特定 Issue の調査・設計・実装・検証・クローズ・キックオフ等である場合は、タイトルに **必ず** GitHub 形式の `#<数字>` を1つ含める（例: `#38`）。複数 Issue が主要な場合は、ユーザーが明示した番号を最優先とし、なければ会話の中心となった **1件だけ** を選ぶ。Issue が主題でない雑談・一般質問のみのスレッドでは付けない
- **禁止**: 日付、スレッド番号、「アーカイブ」等のメタ情報は含めない（`#123` は Issue 参照として許可）

### 良いタイトルの例

- `Sentry調査とLaravel 12アップグレード`
- `cursor-thread-tools エクスポート機能改善`
- `V2 API Session認証のブラウザ連携`
- `RPAスクリプトのNuxt3移行デバッグ`
- `#38 Phase3 hooks 実装キックオフ`（Issue が主目的の例）

### 悪いタイトルの例

- `2026-02-25のスレッド` → 日付はメタ情報
- `APIの調査と修正を行いました` → 文になっている
- `スレッドアーカイブ用タイトル` → メタ情報

### クリップボードコピー

タイトルを生成したら、即座にクリップボードにコピーする:

```bash
echo -n "生成したタイトル" | pbcopy
```

`required_permissions: ["all"]` が必要（サンドボックス制約のため）。

### 出力フォーマット

クリップボードコピー後、以下の形式でユーザーに報告する:

```
📋 クリップボードにコピーしました: {タイトル}
```

これ以上の説明や代替案は出力しない。
