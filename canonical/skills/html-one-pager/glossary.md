# 用語集

人に見せて読んでもらう・答えてもらうページで使う言葉を、ここで1つに決める。ページを作る人もモデルも、ページの札・ラベル・固定の文は、この表の言葉だけを使う。

この用語集は5つの部分からなる。

- 「札の言葉と固定の文」は、`build.py` がページを作るたびに読む表である。データには英語の key を書き、ページにはこの表の言葉が出る。言葉を直すときは、この表だけを直せばよい。受け付ける key の集まりは `build.py` が持つので、この表の言葉を直しても、データとして受け付ける値は変わらない。ただし `recommend`（推奨の札）の言葉は、選択肢の名前の検査（E-Q2）にも使う。
- 「識別子の接頭辞」は、`build.py` が検証とページを作るたびに読む表である。ページの中の項目の識別子（`Q2`・`候補4`）の接頭辞の語を決める。この表の語を直すと、データとして受け付ける札と番号の形も変わる（前の語で書いたデータは止まる）。
- 「問いのカードの塊の題」は、`build.py` が検証のたびに読む表である。問いのカードの塊（`blocks`）の題の語を決める。この表の語を直すと、データとして受け付ける塊の題も変わる（前の語で書いたデータは止まる）。
- 「種別の名前」は、ページの種別（データの `kind`）を人が呼ぶときの名前である。`build.py` は読まず、ページにも出さない。
- 「和訳しない用語」は、人とモデルが読むための決まりである。`build.py` は読まない。

## 札の言葉と固定の文

表の書き方の決まりは次のとおりである。崩れていると `build.py` は終了コード 2 で止まる。

- 1行に1つの key を書く。key は `` ` `` で囲む。
- `build.py` が求める key は、すべて1回ずつ書く。足りない・重なる・知らない key があると止まる。
- 言葉の中で値を差し込む位置は `{n}` のように波括弧で書く。差し込みを持つ key は決まっている（右の列の `{…}`）。持つべき差し込みが無いとき、持ってはいけない差し込みがあるときも止まる。
- 言葉の中に `|` は書けない。

各 key の意味は次のとおりである。

- `evidence.*` は確かめた度合いの札である。`verified` は出典そのものを開いて確かめたこと、`sourced` は出典を挙げたが中身との対応は確かめていないこと、`guess` は出典の無い見立てであることを表す。
- `status.*` はページの状態の札で、ヘッダーの「状態」の行に出る。`awaiting` は答えを待っているページで、`{n}` には答えの選ばれていないカードの数が入る。`answered` は答えを回収し終えたページ、`live` は作ったあとも中身を更新していくページである。
- `severity.*` は指摘の重さ、`adopted.*` は指摘を採ったかどうかの札である。
- `recommend` は、推奨の選択肢に付ける札である。
- `text.head_*` はヘッダーの表の項目名である。`text.version` はヘッダーの「版」の行の値で、`{time}` には `2026-10-19 18:05 JST` の形の時刻が入る。`text.why` は、ページの目的の1文に付ける札である。
- `text.store_*` は保存の状態の文で、ページの JS が出す。
- `text.reply_*` と `text.copy*` は、保存できない表示で出す返答の文と、そのコピーのボタンの文である。`text.reply_heading` の `{title}` にはページのタイトルが、`{time}` には版の時刻が入る。
- `text.lane` は指摘の一覧の上に出す文で、`{lane}` にはどのモデルの指摘かが入る。
- `text.col_*` は指摘の一覧の列の見出しである。
- `text.req_*` は、レビューのページの「依頼したレビュー」の表の見出しと項目名である（対象・種類・経由・観点・なぜ）。
- `text.select_*` は、一覧から選ぶページの選び方のカードに出る、選ぶ数（`{min}`・`{max}`）と選んだ行（`{n}` は数・`{rows}` は番号の並び）の文である。`text.select_over` は、別の画面で選んだ行が届いて選べる数を超えたときに足す文（`{n}` は超えた数）である。`text.pick` は行のチェックの名前（読み上げに使う）、`text.reply_rows` は保存できない表示の返答の文と、畳んだ選び方のカードの答えの行に足す選んだ行の文である。
- `text.folded_answer`・`text.unfold`・`text.fold` は、カードの頭の下の開閉の行の文である。畳んでいるときは `text.folded_answer`（`{label}` には選んだ選択肢の名前か、`text.unanswered` が入る）と `text.unfold` が、開いているときは `text.fold` が出る。
- `text.tabs` は、タブの帯の名前である（読み上げで、帯とタブの並びの名前として使う。画面には出ない）。タブの名前の横の未回答の件数は、`status.awaiting` の言葉で出す。

## 識別子の接頭辞

ページの中の項目の識別子は、この表の接頭辞の語のあとに1以上の数字を続けて書く（`Q2`・`候補4`）。どの種別がどの語を使うか、書かなければ番号を振るかは、SKILL.md の「種別と部品」の表が決めている。表の書き方は「札の言葉と固定の文」の表と同じで、ほかに次の決まりがある。崩れていると `build.py` は終了コード 2 で止まる。

- 語は1文字以上の文字（英字・漢字・かな）からなる。数字・空白・記号（`-`・`#`・`・` など）を含めない。例外として、語の末尾にだけ `:` を1つ置ける（見取り図の `ID:` で、識別子は `ID:1` の形になる）。記号をこれだけに絞るので、ページの中の識別子は、外部の課題管理の ID（`OPS-41`）・`#N`・`PR #N` と同じ文字列にならない。
- 4つの語は重ねず、どの語もほかの語の頭に当たらないようにする（`Q` と `QA` は並べられない）。

| key | 語 |
|---|---|
| `prefix.question` | Q |
| `prefix.candidate` | 候補 |
| `prefix.item` | ID: |
| `tag.approval` | 承認 |

各 key の意味は次のとおりである。

- `prefix.question` は、問いのカードの札の接頭辞である（承認のページと判断ボード）。判断ボードでは、決まったカードを移した「決まったこと」の表の番号の列にも使う。
- `prefix.candidate` は、選ぶ表の番号の列の接頭辞である（一覧から選ぶページの表と、承認・束・判断ボードで選び方のカードが名指した表）。
- `prefix.item` は、見取り図のページの、表の番号の列の接頭辞である。
- `tag.approval` は、承認のページの、全体の承認のカードの札である。番号を付けず、この語だけを書く。

## 問いのカードの塊の題

問いのカード（認識合わせのカードと全体の承認のカードを除く判定カード）の塊（`blocks`）の題は、この表の語で書く。1つ目の塊の題は `block.ask`、2つ目は `block.recommend` にする。`block.alternatives` の塊を置くなら3つ目にする。4つ目からは自由な題の塊を置ける。どのカードが問いのカードかと書き方は、SKILL.md の「問いのカードの書き方」の節にある。表の書き方は「札の言葉と固定の文」の表と同じで、ほかに、3つの語を重ねず、差し込み（`{…}`）を持たない決まりがある。崩れていると `build.py` は終了コード 2 で止まる。ページの札の言葉ではないので、答える部品のあるページの埋め込みデータには入らない。

| key | 語 |
|---|---|
| `block.ask` | 何を決めるか |
| `block.recommend` | 推奨の中身 |
| `block.alternatives` | ほかの案 |

各 key の意味は次のとおりである。

- `block.ask` は、問いの前提を書く塊の題である。なぜいま決めるか・答えが何に効くか・何から選ぶかを書く。
- `block.recommend` は、推奨の選択肢を選んだら何がどうなるかを書く塊の題である。
- `block.alternatives` は、推奨のほかの案と、それぞれの弱いところを書く塊の題である。

## 和訳しない用語

人が読むページでは、定着した用語を独自に和訳しない。言い換えると、読む人が元の用語を思い浮かべ直す手間が増え、検索もできなくなる。次の用語は、この形のまま書く。

| 書く形 | 書かない形の例 |
|---|---|
| ブランチ | 枝・分岐 |
| コミット | 確定・記録 |
| プッシュ | 押し上げ・送り出し |
| マージ | 合流・統合 |
| PR | 取り込み依頼・プルリク |
| issue | 課題票・チケット（そのリポジトリが issue と呼んでいるとき） |
| レビュー | 査読・目通し |
| デプロイ | 打つ・展開 |
| リリース | 出荷・公開版 |
| worktree | 作業木・作業ツリーの複製 |

- 表に無い用語も、同じ考え方で扱う。そのリポジトリやチームがすでに使っている呼び方があれば、それに合わせる。
- 用語を増やすときは、この表に行を足す。
