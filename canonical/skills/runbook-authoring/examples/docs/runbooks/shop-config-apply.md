# shop の設定を反映する

作業のときは、この手順書だけを見て進める。なぜこの形かは、[shop の設定の反映の仕組み](../shop-config.md) にある。

## いつ使うか

- 種類: ずっと使う
- 使うとき: `config/shop.conf` を直した PR がマージされ、その設定を反映先に入れるとき。
- 使わないとき: 設定の中身を決めるとき。中身は PR のレビューで決める。
- かかる時間の目安: 5分。

## 前提

- 依存: bash（3.2 以上）と、`diff`・`cmp`・`sha256sum` か `shasum`。手順の1で確かめる。
- 資格情報: 環境変数 `SHOP_TOKEN` が要る（架空）。見本では長さを確かめるだけで、値は画面に出さず、どこにも送らない。期限は無い。自分の端末で、次のブロックで入れておく（入力した文字は画面に出ない。見本なので何を入れてもよい）。

```bash
read -rs SHOP_TOKEN && export SHOP_TOKEN
```

- 実行する場所: リポジトリの一番上。スクリプトは自分の置き場所から場所を決めるので、ほかのフォルダから実行しても動く。
- 1回だけの初期化: 要らない。反映先のフォルダが無ければ、手順の3が作る。
- 反映先: 環境変数 `SHOP_STATE_DIR` のフォルダ（`/` 以外の絶対パス）。無ければ一時の場所（`${TMPDIR:-/tmp}/shop-example-state`）を使う。

## 手順

1. 前提を確かめる
2. 差分を読む
3. 反映する（変える段）
4. 反映のあとを確かめて、記録を貼る

### 1. 前提を確かめる

依存・資格情報・反映先・設定ファイルの形を確かめる。何も変えない。

```bash
scripts/shop-config.sh check
```

期待する出力: `OK C1`〜`OK C4` の4行のあとに、次の行が出る。

```text
前提はすべて満たした
```

外れたら: `NG` の行の番号を「止まったときに読む表」で引く。何も変えていないので、直してからこの段をやり直す。

### 2. 差分を読む

反映先の今の版と、リポジトリの設定ファイルの差分を出す。何も変えない。変わるキーが、この回に変えたいキーだけかを読んで決める。

```bash
scripts/shop-config.sh diff
```

期待する出力: 差分（`diff -u` の形）のあとに、最後の行に `変わるキー:` と、変わるキーの名前が出る。

外れたら: 変えるつもりの無いキーが出たら、ここで止める。何も変えていないので、設定ファイルを直す PR に戻る。

ここが引き返せる最後の所である。

### 3. 反映する（変える段）

設定ファイルを反映先に入れる。変わるキーと戻し方と `実行する:` の行が出たあと、確認を待つ。

```bash
scripts/shop-config.sh apply
```

期待する出力: `反映するなら yes と入力する:` で止まる。中身を読んで `yes` と入力すると、`実行した:` の行のあとに、最後の行が次の形で出る。

```text
反映した: 版 <版>（前の版 <版>）
```

同じ版がすでに反映先にあり、中身も同じときは、`変わっていない:` の行が出て、何も変えずに終わる。中身だけが違うときは、中身を合わせ直す。

外れたら: 終了コードを見る。1 か 2 なら、何も変えていない（`NG` の行があれば、その番号を「止まったときに読む表」で引く）。3 なら反映先が変わったかもしれないので、「失敗や中断のとき」を読む。

### 4. 反映のあとを確かめて、記録を貼る

反映先の版と中身が、設定ファイルと同じかを確かめる。何も変えない。

```bash
scripts/shop-config.sh verify
```

期待する出力: `OK V1` と `OK V2` のあとに、次の2行が出る。最後の行を、作業の記録（反映した PR のコメント）に貼る。

```text
確かめた: すべて期待どおり
記録: shop の設定を反映した・版 <版>・反映先 <フォルダ>・時刻 <UTC の時刻>
```

外れたら: `NG` の行の番号を「止まったときに読む表」で引く。

## 確かめ方

- 手順の4の `記録:` の行の版は、手順の3の `反映した:` の行の版と同じか。
- 手順の2で読んだ `変わるキー:` は、この回に変えたかったキーと同じか。

## 止まったときに読む表

| 番号 | 意味 | 次の操作 |
|---|---|---|
| C1 | 依存の道具が無い | 道具を入れてから、手順の1をやり直す |
| C2 | `SHOP_TOKEN` が無いか空 | 資格情報を入れてから、手順の1をやり直す |
| C3 | 反映先に問題がある（`/` 以外の絶対パスでない・書けない・`current` がリンクでない） | 出た理由のとおりに `SHOP_STATE_DIR` か反映先のフォルダを直す |
| C4 | 設定ファイルの形が違う（キー=値でない行・キーの重なり） | 出た行の番号の所を直す PR に戻る |
| V1 | 反映先の今の版が、設定ファイルの版と違う | 手順の3が終わっていないか、その間にほかの人が別の版を反映した。下のブロックで今の版を見る |
| V2 | 反映先の中身が、設定ファイルと違う | 反映先の中身が手で書き換えられた。手順の3をやり直すと、中身を設定ファイルに合わせ直す |
| B1 | 戻す先の版が無い | 反映は1回しかされていない。戻さずに、設定ファイルを直す PR で対処する |

今の版と前の版を見る。何も変えない。

```bash
scripts/shop-config.sh status
```

期待する出力: `今の版:` と `前の版:` の2行が出る。

## 失敗や中断のとき

- 止まり方: スクリプトは、確かめが外れるか、確認で `yes` 以外が入ると、その場で止まる。終了コードが 1 か 2 なら何も変えていない。3 なら、最後に出た `実行した:` の行までは済んでいる。
- 再開の条件: 止まった原因を直したら、止まった段からやり直す。どの段も、何度実行しても同じ結果になる。手順の3は、済んでいない操作だけを実行する。
- あとかたづけ: 反映先の `releases/` の古い版は消さない。戻す先になるからである。見本の反映先を片付けるときは、作業した人が `SHOP_STATE_DIR` のフォルダを消す。

戻し方の早見表:

| いつ | 反映先の状態 | 戻し方 |
|---|---|---|
| 手順の1・2 | 何も変えていない | 要らない |
| 手順の3 の確認の前 | 何も変えていない | `yes` 以外を入力して止める |
| 手順の3 のあと | 新しい版になっている | 下のブロックで前の版に戻す |

前の版に戻す（変える）。今の版を前の版に合わせる操作なので、2回実行しても同じ結果になる。`実行する:` の行のあと `戻すなら yes と入力する:` で止まる。

```bash
scripts/shop-config.sh rollback
```

期待する出力: 最後の行に `戻した: 版 <前の版>（戻す前の版 <版>）` が出る。すでに前の版なら `変わっていない:` の行が出る。戻したあとは、設定ファイルも前の中身に戻す PR を出す。手順の4は、設定ファイルが戻るまで `NG V1` になる。新しい版に戻し直すときは、手順の3をやり直す。

## AI が実行するとき

- 非対話の形: 手順の3と戻し方は `--yes` を付けて実行する。`--yes` でも、確認のときと同じ表示が出る。
- 承認の取り方: 先に `--dry-run` で `実行する:` の行を出し、人に見せて承認を取る。手順の3は次のブロックである。

```bash
scripts/shop-config.sh apply --dry-run
```

- 実行する直前にもう一度 `--dry-run` を実行し、`実行する:` で始まる行が承認された行と文字列で同じかを比べる。同じなら、次のブロックを実行する。違えば止めて人に返す。

```bash
scripts/shop-config.sh apply --yes
```

- 実行したときに出る `実行する:` の行も、承認された行と比べる。
- 戻し方も同じ形で、承認を取るブロックと実行するブロックは次の2つである。

```bash
scripts/shop-config.sh rollback --dry-run
```

```bash
scripts/shop-config.sh rollback --yes
```

- 承認されたコマンドの文字列に手を入れない。出力を減らすフィルタも足さない。

## 間違えやすい所

- 手順の2を飛ばすと、変えるつもりの無いキーまで反映される。差分は毎回読む。
- `NG V1` は、手順の3と4の間にほかの人が別の版を反映したときにも出る。反映を2人で同時に進めない。
