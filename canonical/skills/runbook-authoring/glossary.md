# 用語の決まり

手順書と、スクリプトの出力で使う言葉を、ここで1つに決める。手順書を書く人もモデルも、この表の言葉を使う。同じことを2つの語で書くと、読む人は別のことかと迷い、検索でも見つからなくなる。

## 使う語と、その1つの意味

| 語 | 意味 |
|---|---|
| 手順書 | 人か AI が、端末やコンソールで操作を実行するための文書。ランブックのこと。本文ではこの語を使う |
| 実行する | コマンドやスクリプトを動かす |
| 反映する | 変更を、動いている環境（反映先）に入れる |
| 反映先 | 変更を入れる先の環境やフォルダ |
| 確かめる | 期待と同じかを見る。何も変えない |
| 止まる・止める | スクリプトや手順が、その場で先へ進まなくなる・進ませない |
| 戻す | 反映の前の状態に戻す |
| 段 | 手順の中で、人が1つのコマンドで進める単位 |
| 変える段 | 何かを変える段。手順書に「（変える段）」と書く |
| 引き返せる最後の所 | 変える段の直前。ここまでは何も変えていない |
| 確かめの番号 | スクリプトが出す確かめの行の番号（`C1` など）。「止まったときに読む表」をこの番号で引く |
| 記録の行 | スクリプトが最後に出す、作業の記録に貼る1行 |
| 前提 | 手順を始める前に満たしている必要があること |

## 使わない語

次の語は、手順書にもスクリプトの出力にも書かない。

| 使わない語 | 代わりの語 | 理由 |
|---|---|---|
| 打つ | 実行する（キーで入れる意味なら「入力する」） | 実行と入力の区別がつかない |
| 撃つ | 実行する | 比喩で、意味が人によって揺れる |
| 叩く | 実行する（API なら「呼ぶ」） | 比喩で、意味が人によって揺れる |
| 流す | 実行する・反映する | 実行と反映のどちらの意味か分からない |
| 出す（反映の意味） | 反映する・リリースする | 出力の意味の「出す」と区別がつかない。出力の意味で「行を出す」と書くのはよい |

## 和訳しない用語

定着した用語を、独自に和訳しない。言い換えると、読む人が元の用語を思い浮かべ直す手間が増え、検索もできなくなる。次の用語は、この形のまま書く。

| 書く形 | 書かない形の例 |
|---|---|
| ブランチ | 枝・分岐 |
| コミット | 確定・記録 |
| プッシュ | 押し上げ・送り出し |
| マージ | 合流・統合 |
| PR | 取り込み依頼・プルリク |
| issue | 課題票・チケット（そのリポジトリが issue と呼んでいるとき） |
| レビュー | 査読・目通し |
| デプロイ | 展開・投入 |
| リリース | 出荷・公開版 |
| worktree | 作業木・作業ツリーの複製 |

## 持ち込まない言葉

- **そのリポジトリだけの言い換え（内輪の呼び名）。** 説明なしに手順書に書かない。使うなら、手順書の一覧の「用語」で1回だけ説明する。
- **AI の運用の言葉。** AI どうしの役割の呼び名や、AI の作業の場所の呼び名を、手順書に書かない。手順書は人が読む。

表に無い用語も、同じ考え方で扱う。そのリポジトリやチームがすでに使っている呼び方があれば、それに合わせる。用語を増やすときは、この表に行を足す。
