# #284 episode の本文層と振り返り層の責務分離

## Context / なぜこの作業が始まったか

episode は phase の違う2つのものを1つの文書と1つのスキルで抱えている。作業中に随時追記する本文層と、PR レビュー後の closure でまとめる振り返り層である。`episode-retrospective` は冒頭で「本文の書き方は担当外・本文に構造を課さない」と宣言しているのに、Step 3「出力型 × 消費チャネル」は各行に「書く内容」列を持っていた。この宣言と実体の食い違いを解くのが本ユニットである。

## 作業ログ（随時追記）

### 2026-07-27 前段の経緯（plan-first・gate 1 と gate 2 を4周した）

本 episode の枠を作る前に、plan-first で4回の反証を通した。**この節は着手時点までの経緯を plan から書き起こしたもので、以降の節はリアルタイム追記である。**

着地までに設計が3回組み替わった。順に記録する。

- **gate 1（`predecision-exploration`）**: 統括の推奨案（案B = Step 3 を役割で割り「書く内容」列を本文層へ移す）を `oe-refute` 3レーンへ投げ、**3/3 が refuted**。3レーンとも独立に同じ代替形へ収束した（案G = Step 3 を移設せず宛先を明示し、本文層は型を持たない目的指示だけを持つ）。決め手は repo 自身の設計原則で、フリーフォーム本文には目的指示、構造化セクションには手段指示、と置き場が対応づけられており、「両方をフォーマット化すると書きアンカーが潰れる」と明言されていた。Step 3 の「書く内容」は手段指示なので、本文層へ移すのは原典が潰れると予告した方向だった。
- **gate 2 第1周**: 案G を投げて **2/3 refuted**（claude レーンは未返却）。核心は「新スキルの核が既存規範の再ポインタに縮退する」。案G が新スキルに持たせようとした4要素（失敗と撤回の経緯 / リアルタイム捕捉 / 前提の転回 / 棄却した選択肢）は、すべて spec の性質ガイド・ライフサイクル規範・方向転換の記録・既存スキル2本に着地済みだった。
- **測定（owner 裁定「先に測る」）**: 3周の設計論争が「原典の読み方はどちらが正しいか」に帰着していたので、実データで決着させた。結果は下記。
- **gate 2 第2周（絞った1周）**: 測定を受けて確定した案N の実装形（Step 4 の確認対象を episode 全体へ移す + 述語 P1〜P3）を投げ、**2/3 refuted**。核心は「**歯止めの向きが逆**」。述語は「closure の主張 → 本文」の参照整合性しか見ず、本文側の未参照事実（＝省略）を検出できなかった。本文に失敗 A と B があり closure が A だけを正しいアンカー付きで書けば全部 pass する。
- **着地 = 案N′**（反証レーン自身が出した代替）。座礁点（事実・失敗節）を移さず、その中身を pointer 許容にする。二重執筆は止まり、省略検出は落ちない。

## closure（gate 5・マージ前・リアルタイム追記＝`reconstructed` ではない）

**本 closure は、本 PR で導入した read/write 契約を自分自身に適用して書く。** 本文にある事実は再掲せず `` `本文: <見出し>` `` で指す。契約が実際に使えるかを自分で確かめるのが目的でもある。

### tier 判定

**heavy**。トリガに複数該当する — 実行中に失敗・撤回・方針転回があった（設計が3回組み替わった）/ 意図的に外部レビューレーンを起動した（gate 1 で1回・gate 2 で2回・gate 4 で2回）/ 非自明な設計判断を比較して棄却した（案A〜N′）/ 昇格候補がある。

### closure gate checklist

- **Context / なぜ**: 冒頭「Context / なぜこの作業が始まったか」節に自己完結で記載。
- **次の消費者**: (1) **後続ユニット（episode の内容基準・#217）の実施者** — 置き場が未決に戻ったので、その決定から始める。(2) **episode を closure する全エージェント** — read/write 契約が新しい消費対象。(3) **owner** — PR #285 のマージ判断と、canonical の sync 配布（gate 6）。
- **follow-up routing**（すべて行き先つき）:
  - **後続ユニットの内容基準の置き場** → **#217 の gate 0 で決める**（候補は spec の性質ガイド / `episode-retrospective` / 委譲固定節）。本ユニットでは決めない。空の受け皿も作らない。
  - **述語 P1〜P4 のバリデータ実装** → **本ユニットでは追わない**（soft のみの線を owner が引いた）。実装するなら push 時のリモート検査が素直で、リアルタイム測定は episode lifecycle の機械制御（#185）の領分。
  - **`episode-retrospective` Step 2 の「4 項目 + 条件付き 2 項目」という見出しが実際の条件付き3項目と合っていない** → **本 PR では追わない**（変更ハンク外の既存欠陥・gate 4 の cursor レーンが範囲外として報告）。ただし本ユニットが直している「宣言と実体の食い違い」と同型なので、次に同ファイルを触る単位への申し送りとして記録する。
  - **摩擦・見落とし率・skip 率の測定** → **追わない（理由確定）**。本ユニットは「二重執筆を止める」ことだけを主張し、チェッカー負荷の低減は主張していない。測るなら対照群設計が要り、単独 issue の規模になる。
  - **肥大の軸** → **追わない（理由確定）**。R3 が求めた対照群設計（同種タスクの追記型 vs 一括執筆）になっておらず、本ユニットの結論はこの軸に依存していない。**再開条件**を決めておく: 後続ユニット（#217）が本文の質を扱うときに同じコーパスを読むので、そのとき併せて測る機会があれば測る。単独では起票しない。
  - **P3 が短時間の作業では判別力を落とすこと** → **追わない（理由確定）**。バリデータを作らない以上、着地先は述語の但し書きであり、それは本 episode の「自己適用の結果」節に記録済みである。将来バリデータを実装する人がこの節を読む。宙に浮かせない。
  - **canonical の sync 配布** → **親 / owner（gate 6）**。worktree から実行すると `~/.claude` の symlink が worktree を指すので、マージ後に master worktree で行う。
- **status 確定**: `draft` → **`stable`**（達成度=**達成**。受け入れ基準 AC1〜AC10 を満たす）。
- **evidence anchor**: SO の verdict と material 指摘は本文へ転記済み（`tmp/oe-refute-*` と `tmp/oe-review-*` は gitignored の揮発パス）。gate 4 の reviewed_sha は round 1 = `2e20ebb`、round 2 = `c6038d7`。
