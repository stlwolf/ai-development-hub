# ライセンスの明示が無い外部の規則の文は、本文も要約も配らず、使うたびに URL で読んで当てる

## コンテキスト

owner は AI が書いた日本語を読みやすくしたい（#565）。調査で、いもす研の humanizer（規則の文のファイルを AI に読ませて直させる形）が、構成の重複や予告と言い直しを直すのに強いと分かった。ただし規則の文にはライセンスの明示が無く、hub は公開リポジトリなので本文を配布物に写せない。owner と統括は「URL を渡して読ませるなら、それを利用するスキルの形にすればいい」と決め、スキル `humanize-ja` を作った。この decision は、そのとき下した判断のうち、ほかの外部の規則の文（ライセンスの明示が無いもの・URL で公開されているもの）を hub で使うときにも同じ分岐に立つものを残す。手順と控えの値は SKILL.md が正本である。

## 決定

1. **ライセンスの明示が無い外部の規則の文は、本文も要約も配布物に入れず、使うたびに URL から読んで当てる。** 読んだ本文はその回の中だけで使い、ファイル（一時ファイルを含む）に書かず、ほかの文書に写さない。手元の写し（バックアップ）が要るなら hub の外（user 層）に日付付きで置き、配布しない。owner がゲート3 の Q57 で決めた（2026-11-04）。
2. **URL を読んだ結果は「全文を読めた」「途中まで」「読めなかった」の3つに分け、全文を読めたときだけ当てる。** 途中までと読めなかったときは本文を直さずに返し、理由を知らせる。別の規則や自分の知識で代用しない。404 やページの消失、規則でない本文への差し替えは、はっきり知らせる。
3. **規則の更新の検知は、本文の形（最上位の見出しの並び。生の本文を取れたときは行数と大きさも）だけを控えて比べる。** 紹介ページの日付は規則の改訂と一致しないので使わない。控えの更新は人の仕事で、スキルは自動で直さない。

## 根拠

### 決定1（本文も要約も配らない）

- 退けた案は、規則の本文を canonical に写す（案A。ライセンスの明示が無い）、hub の言葉で書いた要点の要約を同梱して読めないときに当てる（plan の初稿の DJ-3。設計SO が「要約の配布は実行時の取得と分けて評価すべきで、著者の利用案内は要約の配布の許諾ではない」と指摘し、owner が Q57 で同梱しないと決めた）、rules や出力の型に観点を足す（案D。owner の判定はスキル）、yomiyasu の語の一覧や CLAUDE.md の1行で呼ぶ（案E。hub の配布物にならない）である。
- 実行時に URL を読んで当てることは、著者が「URL を AI に熟読させて直させる」使い方を紹介しているので、著者の意図に沿う。一方、要約の配布についての許諾は未確認のままで、「URL なら配布ではない」という当初の判断も未検証の仮定だと設計SO に指摘された。配らなければ、この仮定に依らない。
- 当時の前提は「著者の許諾が無い」ことである。著者が明示のライセンスを付けるか、owner が著者に確かめて許諾を得たら、要約や本文を持つ形を再検討してよい。

### 決定2（読めたの3状態）

- 退けた案は、読めなかったときに控えた要点で当てる（Q57 で要点を持たないことになり消えた）、先頭と末尾の節があれば全文とみなす（実装SO が、途中の省略や末尾の直後の切断と競合すると指摘。省略の印と切断の兆候を加えた）である。
- 読めなかったときに自分の知識で直すと、利用者は「規則を当てた」と誤解する。規則を当てたことにできる条件を狭く決めておくほうが、道具が変わっても同じ振る舞いになる。
- この線は URL を読んで当てるほかのスキル（研究の取り込みなど）にも効くと見ている。ただし、この単位では humanize-ja でしか確かめていない。

### 決定3（更新の検知は形だけ）

- 退けた案は、紹介ページの最終更新日で見る（設計SO が、ページの日付と規則ファイルの改訂は一致しないと指摘）、本文のハッシュで見る（本文を保存せずに比べられるが、規則のどこが変わったかは分からず、ハッシュを控えるだけなら見出しの並びと変わらない）、道具が整形して返した表示の行数と大きさで判定する（道具によって違って見える。同じ本文で Codex の Web 閲覧は 444 行、Cursor の WebFetch は 511 行、curl は 510 行と出た）である。生の本文を取れたときの行数と大きさの差は知らせる。
- 見出しの並びは、どの道具で読んでも同じに見え、規則の構成が変わったことを人が読める形で知らせられる。行数と大きさは、生の本文を取れたときだけ比べ、違えば知らせる。道具が整形した表示の値では判定しない。
- 当時の前提は「規則ファイルが版を持たない」ことである。著者が版や更新日を本文に入れたら、それを使うほうがよい。

## 結果

- スキルは `canonical/skills/humanize-ja/` にあり、PR #568 で入る。マージのあとに sync で3つのツールへ配られる。
- 試用のあいだは名前で呼んだときだけ使う（owner の Q58）。常時にするかは、yomiyasu の試用の記録（hub の外）と一緒に見て決める。これは試用の期間の決めで、長く効く判断としては扱っていない。
- 規則の本文のバックアップは user 層に日付付きで置いた。配布物には入れていない。
