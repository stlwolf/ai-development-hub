# 語は「その分野の人がふだん何と呼ぶか」で選び、名前の側にだけ当てる

## コンテキスト

`output-format-rule.md` の §8 は「日本語が入る位置に英語を落とさない」を軸に書かれていた。それを読んだモデルは、ブランチ・バージョン・デプロイのような定着した外来語まで英語の側に数え、「枝」「版」「打つ」と和語に言い換えるようになった。owner は別のリポジトリで「PHP の版なんて言わない。バージョンだ」と指摘した（#571・2026-11-05）。どちらの読み方が効いたかは測っていないので、原因は統括の見立てである。

## 決定

1. **語を選ぶ基準は1つにする。その分野の人がふだん何と呼ぶかで選ぶ。** カタカナの外来語も日本語として扱い、和語に言い換えて独自の呼び名を作らない。迷ったら、その語で検索してその分野の文書が出てくるか、同僚が口頭でそう言うかで決める。
2. **基準は名前（道具・操作・成果物・概念）の側にだけ当てる。** 性質・程度・様子を表す語は、今までどおり日本語にする。§8 の2段の形（名前は分野の呼び方、性質を表す語は日本語）はこの判断から来ている。
3. **語の一覧は決まりにせず、基準を当てた例にとどめる。** 一覧に行を足して塞がない。一覧に無い語は基準で決める。持ち運ぶスキル（`html-one-pager`・`runbook-authoring`）は、§8 を参照せず、基準の1文を自分の中に持つ。
4. **和語を残すかの境界は、「何が変わったか」で分ける。** プログラム・道具・データの形式・反映した設定が変わった版はバージョン（または、指すものを直接書く）で、文書・ページ・記録の中身の改訂は「版」のまま残す（確定版・承認時の版）。番号があるかどうかでは分けない。コードの分岐の意味の「枝」は、git のブランチを扱う文書と混ざらないように「分岐」にする。

## 根拠

### 決定1・3（基準1つと、例にとどめる一覧）

- 退けた案は、§8 の例にブランチ・バージョン・デプロイを足すだけ（plan のゲート1 の G1。owner が「語は無数にあり、一覧を増やしても同じことが起きる」と退けた）、用語集を共通の1か所にまとめてスキルから参照する（G2。持ち運ぶスキルはほかを参照しない、という #467 の決まりと合わない）、言い換えを見つけたら止める hook（G4。owner が機械の検査は作らないと決めた）である。
- 例の語は増やさず差し替えた（コンフリクト・レビュー・コミットを外し、ブランチ・バージョン・デプロイにした・Q63）。例を伸ばすと、例が決まりに見えるからである。
- 当時の前提は「モデルが一覧を決まりとして読み、一覧の外では軸の文を強く読む」ことである。モデルが基準の文だけで語を選べるなら一覧は要らない。逆に基準の文が効かないと分かれば、一覧を広げる以外の手（発火の位置を持つ skill など）を考え直す。

### 決定2（名前の側にだけ当てる）

- 退けた案は、基準を「カタカナで書け」にする（G5）である。これは文書の改訂の「確定版」やコードの「分岐」まで言い換える逆の誤りを生む。§8 に残す和語の例（確定版・分岐・配置）を1行置いたのは、この誤りへの備えである。
- 「名前か、性質を表す語か」の区別を消すと、もとの問題（性質を表す語に英語を落とす）が戻る。§8 はもともとこの問題を直すために入れたので、区別は残した。

### 決定4（境界は「何が変わったか」）

- 初めは「番号があるか」で分けていた。html-one-pager の「前の版の `purpose`」は番号が無いので文書の改訂として残す、としていた。設計SO が「`purpose` を `kind` に替えたのは受け付けるデータの形式の変更で、文書の改訂ではない」と指摘し、実装SO が「拍動なしの版」「200 字で切っていた版」も前の実装を指すと指摘した。2回とも、番号の有無では正しく分けられなかった。
- 前の実装やコードの状態は「バージョン」と書くより、指すもの（変更前のコード・前の実装）を直接書くほうが読み違えない。

## 結果

- §8・出力の型・2つのスキルの用語集と、凍結していない母集団の「枝」と「版」は、PR #573 で直した。
- 凍結した記録（`docs/`・`projects/*/docs/` など）は書き換えていない。古い文を読んだモデルが言い換えを引き写す余地は残る。
- マージのあとに、新しい返答で言い換えが再び出ないかを確かめる工程は、この単位には無い（owner がゲート3 の補足で聞いた点。episode の follow-up に行き先がある）。

## 行動をどう変えるか

- 文書やスキルを書くとき、ある語を和語にするかカタカナにするかで迷ったら、§8 の基準（検索・口頭）で決める。一覧に行を足さない。
- 「版」「枝」のように同じ字が2つの意味を持つ語を直すときは、出現ごとに「何が変わったか（何を指すか）」で分ける。
