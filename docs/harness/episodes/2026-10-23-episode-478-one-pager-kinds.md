### P2: plan の初稿と、そこで下した判断の理由（2026-10-23）

plan の初稿を `docs/harness/plans/2026-10-23-plan-478-one-pager-kinds.md` に書いた。判断の中身と退けた案は plan の DJ-1〜DJ-10 とゲート1 の木にあり、ここには、初稿を書きながら材料から決まったことと、迷ったところだけを残す。

- **承認の種別の「全体の承認のカード」を必須にしなかった。** issue の候補の文は「問いごとのカードと、全体の承認のカード」である。必須にすると、実物の問いの束（16枚・承認のカード無し）と、いまの見本 `decide.json`（問い3つ・承認のカード無し）が止まり、承認のカードを足すという中身の直しを強いる。brief の (6)（止めすぎると無理に当てはめる元になる）に当たると判断した。代わりに、置くならページの最後に1枚という形だけを決めた。
- **一覧から選ぶ種別の「番号の列」を、すべての表には求めなかった。** 実物の一覧から選ぶページは、表の1つ目が上位5件を並べた表で、ほかの表の候補の番号を指していた。この表は候補を定義しないので、番号の列を持たせると同じ候補を2回定義することになる。「表の少なくとも1つが番号の列を持つ」にし、上位の表は `候補3・候補28` のように指してアンカーにする形にした。
- **「手番の1枚」を既存の部品の組み合わせで入れる案（B）を足した。** brief は「入れると決定4 と保存の形に触れる」と書いていたが、別のリポジトリの統括の報告を読むと、その統括は5つのずれを既存の部品で直していた（節を「いつまでに」で分ける・決まったカードを表へ移す・問いを1枚に1つ・本文をやめる）。この直し方を種別の決まりにすれば、決定4 に触れない。B では、カードの番号を位置で振ると、カードを表へ移すたびに残りの番号がずれて本文の参照が別の問いを指すので、`board` だけは番号を必ず書かせる形にした。
- **`purpose` は残さず `kind` に置き換える案を推した。** `kind` を必須にすれば古いデータはどのみち止まるので、`purpose` を残しても古いデータを通す役に立たない。`data-purpose` の属性は型（`template.html`）だけが書き、`page.css` と `page.js` のどちらも読まないことを grep で確かめた。種別から導いた値で残せば、既存の見本の出力が変わらない。
- **アンカーの飛び先のカードには、いまある id（`hp-card-<key>`）を使う。** カードはすでに id を持つので、カードの側の出力は変わらない。表の行は、番号の列を持つ表の行にだけ id を足す。これで、既存の見本のうち `table.json` の出力にだけ行の id が増える見込みになった。
- **接頭辞の語のうち、見取り図の行（`項目`）だけは実物にそろった例が無い。** 実物の見取り図は、手順・図・段のように中身ごとの語を使っていた。中身を問わない語として `項目` を推し、Q1 で owner に決めてもらう形にした。
