## P2: plan の初稿と、そこで下した判断の理由（2026-11-18）

- 状況のタブは、新しい部品 `status` にした。行ごとに状態を書き、`build.py` が4つの表に分けて描く。いまのサンプルは `table` の部品を状態ごとに4つ書き、件数を題に手で書き、色を本文の `style` で付けていた。この形だと、表の書き忘れ・並び・件数の数え違いを書き手に残す。#668 の「ばらつかせない」と「出来事で決まった行だけを書き換える」の両方に合うのは、行が状態を持つ形だった。
昇格の印: 状況を、行ごとに状態を持つ1つの部品にし、表の分け方・題・列・件数を型が決める判断
- 状況のタブを先頭に置くために、本文のタブをデータのタブより先に並べる決まり（#558 で入った）を、状況の部品にだけ外す形にした。並びの決まりそのものを外す形（本文をパネルごとに切って差し込む）は、本文の読み取りを位置まで広げる必要がある。本文の読み取りは直近に Python の版の違いで2回直している（PR #662・PR #664）ので、壊れる場所を増やさない側を選んだ。
昇格の印: 本文のタブを先に並べる決まりの例外を、状況の部品だけに置く判断
- 状況を型で必須にしなかった。必須にすると、いまの見取り図のデータ（どれも状態は随時更新）が直さないと止まり、統括の復帰の全体像のような説明だけのページにも状況を求めることになる。

## P2: ゲート1 と設計SO で変わったところ（2026-11-18）

- ゲート1（Codex 1レーン・選択肢拡張）は refuted だった。概要の案2 を「全部データ」から「骨格を型が持ち、図だけを名前の付いた本文の断片で差し込む」に置き換えた（最初の案2 は図が書けず、改めた案2 に負ける）。推奨は案1（本文のまま見出しを決める）のままにした。改めた案2 は、本文の新しい書き方とその読み取りが要り、上の理由と同じく壊れる場所が増えるためである。
- ゲート1 の指摘で、完了の題に「直近4日」と書くのをやめた。日付の範囲を検査しないのに範囲を言い切ると、古い行が残っていても「直近4日」と出る。題は件数だけにし、目安の日数は別の行に出す。
- 設計SO（Codex 1レーン）は refuted で、must が2件あった。1つは、CSS の全文と用語集の辞書の全体をどのページにも埋め込むいまの作りでは、`page.css` や用語集に足すだけで状況の無いページの HTML も変わる、というもの。初稿の「状況の無いページは変わらない」は、この作りを見落としていた。状況の CSS を別のファイルにして状況のあるページにだけ埋め込み、状況の語をページの JS のデータに入れない形にした。
昇格の印: 新しい部品の CSS と語を、その部品のあるページにだけ埋め込み、ほかのページの HTML を変えない判断
- もう1つの must は、見取り図でない種別に置いたときの規則が E-K2 と E-U2 で食い違っていたこと。同じ原因で規則を重ねない決まりにし、E-U1・E-U2 の担当を、いまの共通の規則（E-F2・E-F3・E-K2・E-N3・E-L1）と分けた。
- should の4件（部品の項目と手を入れる所・空の欄・受入の不足・`check` の結果の比べ方）も採った。知らない type を止める E-S1 の理由の文は `status` が増えて変わるので、例外として受け入れると plan に書いた。
- 2つの SO の記録は `tool_status=not_observed` だった。答えはどちらもファイルの行を挙げ、見本を検証したと書いているが、道具を使ったかの記録からは確かめられない。

## ゲート3 と、承認のあとの補正（2026-11-18）

- owner が判断ボード（Q132〜Q138）で答え、plan で進むことになった。7問のうち5問は推奨どおりだった。
- 推奨と違ったのは完了の日数（Q136）で、owner は「型が日数を決めて古い行を落とす」を選び、「いったん2日分ぐらいで十分」と補足した。推奨は「型は決めず、目安を題の下に出す」だった。推奨の理由は、日付の形を決める必要があり、行を出来事で書き換える仕組みと一緒に決めたほうがよい、というものだった。owner の答えを受けて、日付の項目を `YYYY-MM-DD` に決めた。これで、型が範囲を守れるようになった。ゲート1 の指摘「検査しない範囲を言い切らない」は、範囲を型が守ることで満たされ、題で「直近2日」と言い切れるようになった。
昇格の印: 完了の行を型が既定2日で落とし、日付の項目を YYYY-MM-DD に決める判断
- 色（Q137）は推奨どおりだった。owner の補足「状況以外の部分の視認性が低い」を受けて、DJ-15（状況のタブの外の見出しの見た目）を足した。状況の無いページの HTML を変えない受入（A5）と当たるので、効かせる先を「状況の部品のある見取り図の、ページのタイトルと各タブの節の題」に限る案を推奨にした。owner が見るまで実装しない。

## I1-1: 検証（2026-11-18）

- `build.py` に状況の部品（`status`）の検証を足した。行の状態・状態ごとの項目・空の欄・持っているセッションのペインの番号・日付の形を E-U1 で、置き場（2つ目・先頭でない・最初のタブでない・状況のタブにほかの部品）を E-U2 で止める。形の誤り（配列でない・状態の項目が無い・型の違い）は、いまの共通の規則（E-F2・E-F3）に任せた。
- 並びの検査（E-N3）は、状況の部品が最初のタブにあるときだけ、そのタブを本文のパネルのタブより先に置いてよいとした。状況が最初のタブに無いときは、そのタブを並びの判定から外した。初めは「最初のタブに無いときは、いままでどおりに並びを見る」形にしたが、それだと状況のタブが本文のタブのあとにあるだけで E-U2 と E-N3 が重なって出た。同じ原因の誤りを重ねない決まり（plan の DJ-11）に合わせて直した。
- 状況のタブにほかの部品を足すテストで、初めは唯一の表を状況のタブへ移したため、もう1つのタブが空になって E-N3（中身の無いタブ）も出た。壊し方が2か所を壊していたので、表を足す形に直した（検査の側の誤りではない）。
- 変更の前の検査は490件、いまは515件で、Python 3.13.5 と 3.9.6 の両方で通った。見本11件は `check` を通り、描画にまだ手を入れていないので HTML は変更の前と同じだった。

## I1-2: 描画と CSS（2026-11-18）

- 状況の部品を本文より上に描き、状態ごとの表・題の件数・0件の「なし」・完了を2日で落とす処理を入れた。状況の CSS は `status.css` に置き、状況の部品のあるページにだけ埋め込んだ。状況の語は、答えのページの JS に渡すデータ（`labels`）に入れない。この2つで、見本11件の HTML は変更の前とバイト単位で同じになった（設計SO の must の1つ目の直し方が効いたことを、比べて確かめた）。
- 列の見出しのうち「いつから」と「止めた日」は、同じ `since` の項目でも状態で意味が違うので、用語集の key を状態ごとに分けた。
- テストで2つ書き違えた。1つは、状態の表の範囲を `hp-state-waiting` の文字で切り出したら、CSS の中の同じ文字に当たったこと。もう1つは、「回答待ち」の文字が無いことを見ようとしたら、CSS か型の文に同じ文字があったこと。どちらもテストの側を、要素の class とヘッダーの「状態」の値で見る形に直した。
- owner がサンプルを見て、見出しの見た目（DJ-15）を「ok」とした。サンプルのとおり `status.css` に入れた。plan の「ゲート3 のあとの変更」節の entry 2（補正）に書いた。
- 古い出力を消してから書き出し直すコマンドが、安全の検査（変数を使った `rm`）で止まった。消さずに新しいフォルダへ書き出す形に変えた。

## I1-3: 見本と文書（2026-11-18）

## I2-1: 実装SO（2026-11-18）

- Codex の1レーンで実装SO を回し、refuted で must が2件あった。1つは、状況の部品の `tab` が文字列でないと、並びの判定で辞書を引いて例外で落ちること。型の誤り（E-F3）を記録したあとも、並びの判定に進んでいた。もう1つは、完了を下限の日付でしか絞っておらず、未来の日付の行が「直近2日」に入ること。どちらも、入力を作って確かめると再現した。
- 2つ目の状況の部品を状況のタブに置いたときに誤りが3件重なる件も直した。I1-1 で「誤りを重ねない」を直したときは、置き場の誤りを1つずつしか見ておらず、2つ目の部品から派生する誤りまでは見ていなかった。
昇格の印: 1つまでの部品の2つ目は、ほかの置き場の判定（同じタブ・並び）から外して、誤りを重ねない
- `tab` が文字列でないときに出る「中身の無いタブ」の E-N3 は、表の部品で同じことをしても出る、いまの振る舞いだった。テストの期待をそれに合わせた。
- 見取り図の E-K2 の理由の文が変わることは、設計SO で E-S1 の文が変わることに気づいたときに、同じ形の見落としがあった。理由の文に許可の一覧を並べている所は、部品を足すたびに文が変わる。
- 検査は 526件が 3.13.5 と 3.9.6 で通り、元からの見本11件の HTML は変更の前と同じだった。
