**検算の実行形と、配布物に載せる記載形をずらさない。** ずれると、検算は通るのに読者は踏む。

#390 の verb 解決規約に、足がかりから engine の `bin/` を引くコード例を載せた。

```bash
[ -x "$oe_bin/oe-handoff" ] || echo "足がかりから引けない（3 へ）"
"$oe_bin/oe-handoff" --help
```

説明には「引けなければ手順3 へ倒す」と書いた。**シェルは `echo` を出したあと、次の行をそのまま実行する。** 倒れない。

**自分の検算はこの誤りを踏まなかった。** 検算では `if [ -x ... ]; then ... else echo "3 へ"; fi` の形に手で分岐させて実行し、3通りの環境で期待どおりの出力を得ていた。**確かめたのは「考えていた分岐」で、「載せたコード」ではない。** 実装SO が1レーンで検出した。

## なぜ非自明か

**検算する側は、コードを読んで意味を取ってから実行する。** 意味のほうが頭にあるので、実行するときに自然と正しい形へ直してしまう。**直した形で通ったことが、載せた形の証拠になる。**

**しかも説明文は正しい。** 「引けなければ 3 へ」という記述と、スニペットの挙動だけがずれている。**説明とコードを別々に読むかぎり、どちらも正しく見える。**

## 行動をどう変えるか

**載せる形のまま、コピーして実行する。** 手で分岐させた検算は、その分岐が配布物に無い形である以上、検算になっていない。

**分岐を説明文で書いたなら、コードにも分岐を書く。** 「〜でなければ次へ」と書いたスニペットが `||` と `echo` だけで終わっていないかを見る。
