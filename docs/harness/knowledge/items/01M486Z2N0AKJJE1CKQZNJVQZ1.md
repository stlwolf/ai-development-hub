**非対話で子のセッションを起こして測るときは、起動の引数だけでなく、起動する場所の手元専用の設定の許可も効く。許可の外を断る試しを、本番の測定の前に1回打つ。**

#403 の dogfood で、`--allowedTools 'Bash(gh issue view *)'` と `--permission-mode dontAsk` を付けて、`gh issue view` だけを許したつもりで起動した。試しに `echo` と `gh issue list` を頼むと、どちらも実行された。起動した hub の checkout には、git の対象外の `.claude/settings.local.json` があり、許可の規則が125件入っていた。その中に `Bash(gh issue:*)` があり、**plan の形のまま測定していたら `gh issue comment`（本物の issue への投稿）も許されていた。**

`--setting-sources user,project` で手元専用の設定を読まない形にし、許可の外のコマンドと書き込み（一時ディレクトリへの `touch`）が断られることを確かめてから測った。

## なぜ非自明か

**許可を絞る引数を書いた本人には、封じたように見える。** 手元専用の設定は git の対象外で、リポジトリを読んでも見えない。足場の設計をレビューした外部の目（設計SO）も、「禁止の一覧では封じ切れない」とは指摘したが、手元の設定から道が開くことは挙げなかった。

## 行動をどう変えるか

**本番の測定の前に、許可の外のコマンドを1つと、無害な書き込みを1つ頼み、どちらも断られることを確かめる。** 断られなければ、起動する場所の手元専用の設定を疑い、読み込む設定元を絞る。書き込みの試しは、万一通っても害の無い相手（存在しない issue・一時ディレクトリ）に向ける。
