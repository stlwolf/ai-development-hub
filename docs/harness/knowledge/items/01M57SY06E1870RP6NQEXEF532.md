**Codex の PreToolUse hook は `"ask"` を返しても確認に回らない。** 公式の hooks の文書は、`permissionDecision: "ask"` を「parsed but not supported yet」とし、Codex は hook の失敗として扱って、そのツールの呼び出しを続けると書いている。止められるのは `permissionDecision: "deny"`（と古い `decision: "block"`）か exit 2 だけである。

#385 で、Claude Code では hook の `"ask"` が当たる allow 規則より先に効くことを、使い捨てのリポジトリで確かめた。その結果を「hub は3ツールへ同じ hook を配っている」と並べて書き、Codex でも同じだと読める形にしていた。設計SO がその一般化を突き、Codex の公式の文書を取り直すと、`"ask"` は止まらずに動くと書かれていた。Codex のユーザー層の allow の規則は sandbox の外で確認なしに動くので、hook が素通りすると、確認に回したつもりの強制 push のような操作がそのまま動く。

次にどう行動を変えるか。(1) Codex に配る hook で止めたい形は、deny か exit 2 で返す。(2) 「確認に回す」が目的なら、Codex の PreToolUse ではそのままの形では果たせない前提で、別の仕組みを決める。(3) Claude Code で確かめた hook の振る舞いを Codex に広げる前に、Codex の文書の PreToolUse の節で、返り値ごとの扱いを当て直す。(4) 試すときは、モデルの返答ではなく、hook の記録と Codex の stderr（「Command blocked by PreToolUse hook」など）で判定する。#385 の試験では、モデルが止めた仕組みを取り違えて答えた。
