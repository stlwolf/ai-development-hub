**decision の決定の文は、owner の判定の原文に1文ずつ当て直してから書く。** 推奨の表から縮めて書くと、表の中で隣にあった未決の範囲まで、決まったものとして入りやすい。

#385 で、owner の判定は「allow は hub の正本に置かない」と「狭める側の規則を配ることになったら、外した項目は知らせて手で消す」だった。decision の「正本に含めるもの」の段落では、これを「許可規則そのもの（allow・ask・deny・Codex の `prefix_rule`）は、どれも正本に含めない」と1文に縮めていた。狭める側を含めるかは owner が決めていない。decision への SO が「Q1 が除外したのは allow で、Q6 は将来配る場合の扱い」と突いて見つかった。同じ単位では、discussion の推奨の「本命は hook、別の issue で採否を決める」も、decision では「hook が正本に加わる」「Codex では deny で止める形になる」と、採否と方式まで決めたように書いていた。

次にどう行動を変えるか。(1) 決定の各文を書いたら、どの判定（問いと答え）から出たかを横に置き、原文に無い範囲が入っていないかを見る。(2) 判定が触れていない隣の範囲は、書かずに済ませるのではなく「決めていない」と明記する。(3) 「方向を決めた」と「採ることを決めた」を分けて書く。別の issue に回したものは、その issue で何を決めるかまで書く。
