**入口のスキルの description には、題材が決まる前でも先に読み込むことを書く。そして発火の測定に、題材の欠けた言い方を必ず入れる。**

#428 の `human-page` は、人に判断してもらうページを作るときに読み込まれてほしい入口のスキルである。`claude -p` で8つの言い方を測ったところ、「この3つの設計判断を owner に選んでもらうページを作って」だけが読み込まれなかった。モデルは題材のファイルを2回探したあと、返答の本文に「分かれば `human-page` スキルで判定ページを作ります」と書いて止まった。スキルの存在も一致も分かっていたが、「題材が決まるまで読み込まない」という順で動いた。題材が書かれていた他の5つの言い方では、最初の呼び出しで読み込まれた。

description に「何を載せるか（題材）がまだ決まっていなくても、ページを作る依頼を受けたら、題材を聞き返したり探したりする前に読み込む（何を聞けばよいかは、このスキルの部品の形で決まるため）」の1文を足すと、同じ8つで、陽性の6つがすべて最初の呼び出しで読み込まれた。1回目に題材を8回探してから読み込んだ別の言い方も、最初に読み込むようになった。

## なぜ非自明か

**一致しているかぎり読み込まれる、と考えやすい。** 実際には、モデルは「いま要る情報が足りない」と判断すると、道具の呼び出しより聞き返しを先にする。スキルの読み込みも道具の呼び出しなので、後回しの対象になる。**聞き返しそのものは正しい振る舞いに見える**ので、読み込まれていないことは、呼び出しの記録を見ないと分からない。スキルが聞き返しの中身（どの部品のために何を聞くか）を決めるものなら、読み込まずに聞き返すと、その聞き返しはスキルの決まりを通っていない。

## 行動をどう変えるか

**入口のスキルの発火を測る表に、題材の欠けた言い方を入れる**（「この3つを〜するページを作って」のように、対象の中身が会話に無い形）。受入は返答の中身ではなく、`Skill` の呼び出しの記録で見る。スキルが聞き返しの中身を決めるなら、description に「題材を確かめる前に読み込む」と、その理由を書く。
