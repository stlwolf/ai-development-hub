**安全の仕組みが情報を「読める」ことと、その情報を「照らしている」ことは別である。** 理由の柱を「読める」側に置くと、言い過ぎになる。

#407 で、`oe-*` の allow を配らない理由の柱を、草稿では「owner の発話と中継の文の両方を読めるのは、親の側の判定器だけである。allow はその唯一の照合を飛ばす」に置いていた。判定器が利用者の発話と道具の呼び出しを読むことは、公式の文書で確かめてあった。ゼロベースの代替探索（ゲート1）の SO が「読む入力の仕様は、照合の保証ではない」と突いた。同じ単位の再現の試験でも、owner が具体的な変更を名指していないのに、Claude が組んだ具体的な中継の文を判定器は通していた。理由の柱を「どのペインへも判定器を通さずに打ち込める」に移し、判定器は「見る機会が残る」に下げた。次の設計SO（ゲート2）は、さらに「PreToolUse hook も会話記録のパスを受け取るので、読めるのは判定器だけではない」と突いた。#385 でも、hook を「置き場所と関係なく効く唯一の案」と書き、ユーザー層の deny も同じく効くことを見落としていた。

次にどう行動を変えるか。(1) 安全の仕組みについて書くとき、「読める・受け取る」と「照らす・止める」を別の文に分け、後者には試験か文書の文の出典を付ける。付けられなければ「照らす機会がある」までにとどめる。(2) 「唯一」と書く前に、同じ情報を受け取る別の経路（hook の入力・別の層の規則・会話記録）を一覧にして当てる。(3) 推奨の理由の柱は、確かめた性質の側に置く。
