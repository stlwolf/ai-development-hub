**書き方の決まりを持つスキルは、その決まりをスキル自身のフォルダ全体にも当てる受入を置く。** 例外は、使わない語を挙げる表の行だけにする。

#467 の `runbook-authoring` は、手順書とスクリプトの出力に「打つ」「流す」などを使わない、という用語の決まりを持つ。見本の手順書はこの決まりで書いた。ところが、plan の段階で書いた description の初稿に「手順書の続けて打つコマンド」と書いていた。実装では、前例のスキルの用語集から写した「和訳しない用語」の表の「デプロイ」の行の「書かない形の例」に「打つ」が入っていた。2回とも、受入に「使わない語を、スキルのフォルダ全体に当てる grep（当たってよいのは使わない語の表の行だけ）」を置いていたので見つかった。同じ形で、本文の例に hub の運用の語（「委譲」）を挙げかけ、hub への参照を探す grep に当たることにも気づいた。

## なぜ非自明か

**決まりを書いた本人は、自分は決まりを守って書いていると思いやすい。** 決まりを当てる対象を「スキルが作るもの」（手順書・見本）と考え、スキル自身の文面を対象から外しやすい。description や本文の説明は、決まりの対象の文書とは別の層だと感じ、ふだんの言い方で書いてしまう。前例から写した表は、前例の決まり（別の語の一覧）で正しかったので、写した側の決まりに照らし直さない。配ったスキルの文面は、読んだモデルの手本になるので、違反がそのまま広がる。

## 行動をどう変えるか

**書き方の決まりを持つスキルの受入に、決まりの検査をスキルのフォルダ全体に当てる項目を足す。** 当たってよい行（使わない語の表）は、ファイルと行で明示して除く。前例のスキルから表や文を写したら、写した行に自分の決まりを当て直す。
