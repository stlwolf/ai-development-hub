**見せる先が「見える」ことを確かめるときは、画面に入るかでなく、ほかの要素に隠れていないかで確かめる。貼り付く帯があるなら、見せる先の上端が帯の下端より下に来ることを条件にする。**

#478 で `html-one-pager` の本文の識別子を、ページの中のカードや行へのアンカーにした。手元の Playwright の確かめ（A12）は、アンカーを押したあと「URL の `#` のあとが合う」「飛んだ先が画面に入る（上端が 16px）」「`:target` の枠が付く」を見て、すべて通った。ところが、private の artifact に公開した見本を Chrome で開いて同じリンクを押すと、カードの題が、上に貼り付く帯（全部推奨どおりの案内と保存の状態・`position: sticky`）の下に隠れていた。帯は答える部品のあるページにだけあり、高さは 84〜128px だった。飛んだ先の上端 16px は帯の中で、「画面に入る」の条件はそれを区別しなかった。

## なぜ非自明か

**「画面に入る」は、見えることの必要条件にすぎない。** 確かめを書く人は、スクロールの仕組み（`scroll-margin-top` やブラウザの既定の位置）が正しく動くかを見ようとして、条件をスクロールの結果の位置に置く。重なりは別の要素の性質なので、確かめの対象から外れやすい。しかも、貼り付く帯はページの種類（この単位では答える部品のあるページ）でだけ出たり、文の長さで高さが変わったりするので、帯の無いページや短い文のときの確かめでは問題が出ない。

## 行動をどう変えるか

**見せる先の確かめに、隠れていないことの条件を入れる。** 貼り付く要素の下端を測り、見せる先の上端がそれより下に来ることを見る（`document.elementFromPoint` で見せる先の中の点を当てる形でもよい）。貼り付く要素の高さが中身や画面の幅で変わるなら、いちばん高くなる場合（長い文・狭い画面）で測る。手元の確かめが通っても、公開する先の表示で1回は実物を見る。
