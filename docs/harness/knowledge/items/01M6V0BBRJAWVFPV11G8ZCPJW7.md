**作業記録に時刻を書くときは、その場で `date` を実行するか、直前のツールの出力（commit の時刻・ファイルの更新時刻・ログ）から取る。見積もらない。**

#582 で、episode の節の見出しに時刻を書いた。最初の1回だけ `date` を見て、あとは「手順がいくつか進んだから数分経った」と見積もって 21:35・21:37・21:40・21:42・21:44 と書いた。実際の時刻は commit が 21:34、SO の起動が 21:35 で、見積もりは最大で9分先に進んでいた。commit の時刻を見に行ったときに食い違いに気づき、見出しを実際の時刻に直した。

## なぜ非自明か

時刻を書くこと自体は簡単なので、確かめる手順だと感じない。手順を進めた数や読んだ量で経った時間を見積もると、モデルの感覚では長く感じるが、実際のツールの呼び出しは数秒から数十秒で終わる。見積もった時刻は見た目では本物と区別がつかず、あとで commit の時刻と並べるまで誤りに気づかない。

## 行動をどう変えるか

episode に時刻つきの節を立てる前に `date '+%H:%M'` を実行して、その値を書く。commit や SO の記録の時刻を書くときは、`git log -1 --format=%ci` や出力ファイルの時刻を読んで写す。見積もりしか無いときは「頃」を付け、確かめた時刻と区別する。
