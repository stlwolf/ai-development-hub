# #456・#463・#470 issue-intake の出力を3点直す（本文の数と状態・issue の URL・修正範囲）

## 背景

`issue-intake` の出力に、owner と委譲した子が別々に見つけた抜けが3つ溜まった。

- **#456**: #401 の認識合わせは、issue 本文の「宣言は3項目」を、いまの宣言（すでに4項目）に当て直していなかった。委譲した子が plan の途中で気づき、「5項目目」と読み替えた（2026-10-18・#401 の episode の「認識合わせの抜け」節）。いまの固定の問い3つは、本文に書かれた数や状態が書かれた時点から変わっていることを拾う形になっていない。
- **#463**: owner が認識合わせの提示を読んで issue をたどりたくなったが、提示に issue の URL が無かった（2026-10-19）。hub の関連リンクの規則（`output-format-rule` の §5）は「作った・更新したもの」が対象で、見せるだけの場面は抜けていた。
- **#470**: owner が #407 の認識合わせを読んで、望む結果とは別に「今回どこを触るか（ドキュメントかコードか・どのファイルか）」が分かると「ここを変えてこれを達成する」が読める、と言った（2026-10-20）。

3つとも `canonical/skills/issue-intake/SKILL.md` の隣り合う節を直す。分けると順にマージ待ちになるので、統括が1つの委譲の単位・1つの PR にした（#470 の確定版。owner は4件とも確定で応えた）。

**この plan は、3つの確定版の「やること」と、brief の scope を正本として扱い、覆さない。** この plan が決めるのは、スキルの文面（直す箇所と直し方）・受け入れ基準と、brief が DJ の例として挙げた点への答えである。brief と確定版のあいだの食い違いが1つあり、確定版に従う形を DJ-7 に書いてゲート3 で確かめる。

**この plan は設計SO（ゲート2・Codex 1レーン）の指摘で直した。** 何を採り何を退けたかは「設計SO（ゲート2）」節に書く。

## 確定版と brief の各点への答え

brief は、plan で決める DJ の例として5つを挙げた。それぞれの答えと、どの DJ で決めたかを先に置く。

- **4つ目の問いの文言と短い名前**: 2節の固定の問いの4つ目として、ほかの3つと同じく issue に向けた問いの形で書く。対象を「issue 本文が前提として書いている、そのときの数や状態」のうち「やることや受け入れ基準に効くもの」に限り、終わったあとに目指す数や状態（目標）を外すことを問いの文に入れる。短い名前は「本文の数と状態」。（DJ-1）
- **「修正範囲」の粒度の書き方と例**: 「望む結果」のあとに小箇条を1つ足し、(a)(b)(c) の順と、調査から入る issue の書き方を書く。例は、4節の「別モデル」の行の例と同じく、出力の形の例のすぐあとに4行の例のブロックとして置く。（DJ-4）
- **URL を添える位置の一般の文と hub の補足**: 一般の文は「添える」で、5節の提示・5節の依頼元へ渡すもの・6節の投稿の報告の3か所に書く。出力の形の例では最後の行に置く。関連リンクの先頭という位置は補足の節に書く。（DJ-3）
- **20行の目安の直し方**: 20行のまま、「修正範囲」の行と添える issue の URL の行を括弧に足す。（DJ-5）
- **受入の検出項目と番兵の設計**: #450 の形で、期待の全文との一致（F1）を主にし、変更ごとの新しい行（D）・消える行（N）・位置（P）・番兵（S）を issue ごとに分ける。（DJ-6）

brief の受け入れ基準の各項目への答えは、下の「受入」節の最後の対応表に置く。

## 設計判断

### DJ-1 固定の問いの4つ目は、ほかの3つと同じ形の問いにし、対象の線引きを問いの文に入れる

- **置き場**: 2節の「固定の問い」の4つ目にする。#456 の確定版の推奨のとおりで、「文脈の置き場」の行に含める案は退ける。含めると、当てた結果が「読んだもの」の列挙に混ざって見えなくなる（確定版）。
- **文言**: 「issue 本文が前提として書いている、そのときの数や状態（項目の数・件数・行番号・ある／ない・開いている／閉じている）のうち、やることや受け入れ基準に効くものは、いまのリポジトリに当て直しても同じか。」
  - brief は「当て直したか」と書くが、ほかの3つの問いは、作業の済み・未済ではなく issue の性質を問う形（「どこか」「何か」「何の数で見るか」）である。同じ形にそろえて「当て直しても同じか」にする。問いに答えるには当て直すしかないので、作業は落ちない。
  - 対象の線引き（やること・受け入れ基準に効くもの）は確定版の「書いていないが要ること」にある。線引きを問いの文の外に書くと、本文のすべての数を当て直す読みが残るので、問いの文に入れる。
  - **前提と目標を分ける**（設計SO の指摘1で直した）: 最初の案は「issue 本文に書かれた数や状態」としていた。これでは、終わったあとに目指す数（たとえばスキル自身の例の「人が手を動かすのは2回で、それを0回にする」の「0回」）も当て直す対象に入る。目標はいまのリポジトリと一致しないのが当然なので、それを「issue に書いていないが要ること」に書くと、まだ作っていない目標を「本文が古い」と取り違える。そこで、当て直す対象を「本文が前提として書いている、そのときの数や状態」に限り、問いの最後に「終わったあとに目指す数や状態（目標）は、当て直す対象に入れない。」を足した。#401 で起きたのも、前提の数（宣言の項目は3つ）が変わっていたことである。
  - 問いの直後に理由の1文（「issue は書かれた時点のリポジトリを前提にしていて、着手までに変わっていることがある。」）を添える。ほかの3つの問いには理由が無いが、この問いだけは「何と比べるか」（書かれた時点ではなく、いま）を示さないと、本文の中の整合だけを見る読みが残る。
- **短い名前**: 「本文の数と状態」。ほかの3つの短い名前（完成後の人手の残り・暗黙の工程・達成を見る数）と同じく、名詞句で問いの対象を指す。
- **食い違いの書き先**: 「issue に書いていないが要ること」に1行で書く（C6・確定版のとおり）。C6 の文も「issue 本文が前提とする数や状態」と書き、問いの線引きとそろえる。「どの観点で見たか」の行には、何を当てて結果がどうだったかだけを書き、食い違いの中身は差分の行に任せる（C9）。同じ中身を2か所に書くと20行の目安を食う。
- **確かめられなかったとき**（設計SO の指摘6で足した）: 当て直す対象はあるのに、ファイルが読めないなどで確かめられないときの書き方が、最初の案の C9 に無かった。「当て直すものなし」と書くと、確かめを省いたことが見えなくなる。C9 の行に「確かめられなかった（理由）」を選択肢として足した。
- **2つの形の例に入れる**: 出力の形の例（C9）と確定版の形の例（C15）の「どの観点で見たか」に1行足す。確定版の形の例は観点の行を `- …` で畳んでいるので、`- …` と `- 本文の数と状態: …` と `- …` の3行にして、ほかの観点のあいだに入ることを示す。
- **棄却した案**: 「文脈の置き場」の行に含める（上記）。1 節の手順の1つ（たとえば 1-5）にする（ゲート1 の案B）。

### DJ-2 8節の実例は、本文に hub の番号を剥がした1文で置き、番号は補足に置く

- 確定版は「8節の行き先1の実例として、この issue を1行で残す」と書く。brief は「スキルの文は hub 固有のパスや言い方を剥がしても成り立つ形にし、hub の具体例は補足の節に書く」と書く。issue の番号は hub の外では意味を持たないので、両方を満たすために分ける。
  - 8節の行き先1の箇条の末尾に、番号の無い実例を1文足す（C17）。何が起き、なぜこの行き先にしたかが分かる形にする。
  - 補足の節の「後から見つかった抜け」の行の末尾に、出どころの番号（#401・#456）を1文足す（C21）。新しい箇条は立てない。
- 「1行で残す」は、8節に足す文が1文であることで満たす。
- **棄却した案**: (a) 8節に issue の番号つきで書く。hub の外のリポジトリで読むと、番号が別の issue を指す。(b) 補足の節にだけ置く。8節を読む人に実例が見えない。

### DJ-3 issue の URL は「添える」と一般の形で書き、出力の形の例では最後の行に置き、位置の決まりは補足に置く

- **一般の文を足す3か所**（確定版の「やること」のとおり）:
  - 5節の提示（C12）: 「見せるときは issue の URL を添える。」に、理由の1文を添える。
  - 5節の、応答する人がいないときに依頼元へ渡すもの（C13）: 「渡すものにも issue の URL を入れる。」確定版の「書いていないが要ること」の2つ目（子からの提示も最後は owner が読む）に当たる。
  - 6節の投稿の報告（C16）: 「issue の URL とコメントの URL を出力に書く。」と、「issue の URL はコメントの本文には入れない（コメントは issue の中にある）。」
- **出力の形の例の最後の行に `issue: <issue の URL>` を置く**（C10）。確定版は「出力の形の例に issue の URL の行を1つ入れる」と書き、位置は決めていない。最後に置くのは、hub が置く関連リンクが応答の末尾にあるのと並びがそろうためである。先頭に置くと、補足の「関連リンクの先頭」と例の位置が食い違って見える。
- **hub の補足に2つ足す**: 関連リンクの先頭に置くこと（C19・確定版の「書いていないが要ること」の1つ目）と、子が依頼元へ渡す `.oe/question-<issue>-<n>.md` にも入れること（C18）。
- **9節の表は直さない**: 「依頼元へ返す手段の取り決め（委譲された側）」の行は「最終の応答として3つの出力を返し、止まる」と書く。この行は 5 節の C13 と同じ箇条から呼ばれ、C13 が先に「渡すものにも issue の URL を入れる」と書くので、渡す手段の違いによらず URL は入る。表の行に足すと、同じ規則を2か所に持つことになる。この判断は設計SO に確かめさせる。
- **確定版の形の例には入れない**: 確定版のとおり。brief の受入との食い違いは DJ-7。

### DJ-4 「修正範囲」は「望む結果」のあとの小箇条にし、「最後に」の言い方を移し、書き方の例を出力の形の例のあとに置く

- **位置**: 「この issue でやること」の小箇条で、なぜ・やること本体・望む結果のあとに置く（C5）。確定版のとおり。見出しにはしない（見出しの数は変えない・受入の S2）。
- **「最後に」を移す**: いまのスキルは「望む結果」を「最後に」置くと2か所で書く（親箇条と小箇条）。そのまま「修正範囲」を足すと、この2か所が新しい行と食い違う。注入された knowledge item `01M486Z2ND07GQWV1GHS1SVB0J` が予測する打ち消す側で、同じ変更で直す。
  - 親箇条（C3）: 「前に置く『なぜやるか』の1文と、後ろに置く『望む結果』の1文と『修正範囲』の1行は、この文数に含めない。」

## ゲート1（ゼロベース代替探索）

方向は3つの確定版で決まっているので、ゼロベースでは、やり方そのものの代替を次のとおり挙げた。設計SO の選択肢拡張で出た案は、この下に追記する。

def load(ref):
    if not ref:
        return open(c.F, encoding="utf-8").read()
    if os.path.isfile(ref):
        return open(ref, encoding="utf-8").read()
    return subprocess.run(["git", "show", f"{ref}:{c.F}"], check=True, capture_output=True, text=True).stdout

def sections(text):
    out, name = {}, "(front)"
    for line in text.split("\n"):
        if line.startswith("## "):

        out.setdefault(name, []).append(line)
    return out

    return []

def text_block(lines, nth=0):
    """節の中の nth 番目の ```text ブロックの中身。"""
    blocks, cur, f = [], [], False
    for l in lines:
        if not f and l == "```text":
            f, cur = True, []; continue
        if f and l == "```":
            blocks.append(cur); f = False; continue
        if f:
            cur.append(l)
    return blocks[nth] if len(blocks) > nth else []

        if "<!-- issue-intake:confirmed v1 -->" in l:
            f = True
        if f and l == "  ```":
            break
        if f:

    return blk

    return None

    def chk(i, issue, e, a, note=""):

    # F1: 期待の全文との一致
    chk("F1", "全体", 1, int(text == exp), "期待の全文と一致しない")

    for cid, issue, scope, desc, _, _ in c.CHANGES:
        bsc, esc, tsc = sec(bs, scope), sec(es, scope), sec(ts, scope)
        for k, line in enumerate(c.new_lines(cid), 1):
            chk(f"D-{cid}.{k}", issue, tsc.count(line), esc.count(line), f"[{scope}] {line.strip()[:36]}…")
        for k, line in enumerate(c.old_lines(cid), 1):
            chk(f"N-{cid}.{k}", issue, tsc.count(line), esc.count(line), f"[{scope}] 旧: {line.strip()[:36]}…")

    def idx(lines, prefix):
        for i, l in enumerate(lines):
            if l.startswith(prefix):
                return i
        return -1
    order = [idx(s3, "  - 最初に **なぜやるか**"), idx(s3, "  - やること本体のあとに **望む結果**"),
             idx(s3, "  - 最後に **修正範囲**"), idx(s3, "- **issue に書いていないが要ること**")]
    chk("P1", "#470", 1, int(all(x >= 0 for x in order) and order == sorted(order)), "3節の小箇条の順（なぜ・望む結果・修正範囲・書いていないが要ること）")
    ob = text_block(s3, 0)
    chk("P2", "#470", "- 修正範囲:", (after_line(ob, "- 望む結果:") or "")[:len("- 修正範囲:")], "出力の形の例で望む結果の直後")
    chk("P3", "#470", "issue に書いていないが要ること:", after_line(ob, "- 修正範囲:") or "", "出力の形の例で修正範囲の直後")
    chk("P4", "#456", "- 本文の数と状態:", (after_line(ob, "- 達成を見る数:") or "")[:len("- 本文の数と状態:")], "出力の形の例で達成を見る数の直後")
    chk("P5", "#456", "- テンプレート:", (after_line(ob, "- 本文の数と状態:") or "")[:len("- テンプレート:")], "出力の形の例で本文の数と状態の直後")
    chk("P6", "#463", "issue: <issue の URL>", ob[-1] if ob else "", "出力の形の例の最後の行")

    chk("P7", "#470", "  - 修正範囲: …", after_line(cb, "  - 望む結果:") or "", "確定版の形の例で望む結果の直後")
    chk("P8", "#456", "  - 本文の数と状態: …", after_line(cb, "  ### どの観点で見たか") and cb[cb.index("  ### どの観点で見たか") + 2] if "  ### どの観点で見たか" in cb and len(cb) > cb.index("  ### どの観点で見たか") + 2 else "", "確定版の形の例で観点の2行目")

    # S: 番兵（変更前後とも PASS）
    bl, cl = base.split("\n"), text.split("\n")
    sm = difflib.SequenceMatcher(None, bl, cl, autojunk=False)
    removed = [l for tag, i1, i2, _, _ in sm.get_opcodes() if tag in ("delete", "replace") for l in bl[i1:i2]]
    unexpected = [l for l in removed if l.strip() and l not in c.all_old_lines()]
    chk("S1", "番兵", 0, len(unexpected), "想定外に消えた行: " + " | ".join(u[:30] for u in unexpected[:3]))
    body = "\n".join(l[2:] if l.startswith("  ") else l for l in conf_block(s6))
    try:
        out = subprocess.run(["jq", "-r", JQ], input=json.dumps([{"body": body, "author_association": "OWNER", "html_url": "U"}]),
                             capture_output=True, text=True, check=True).stdout.strip()
    except Exception as e:
        out = f"jq error: {e}"
    chk("S2", "番兵", "confirmed\t4\tU", out, "1-2 のコマンドの jq を確定版の形の例に当てた結果")
    desc = [l for l in cl if l.startswith("description: ")]
    chk("S3", "番兵", [l for l in bl if l.startswith("description: ")], desc, "description が変わった")
    chk("S4", "番兵", (1, 1), (text.count("<!-- issue-intake:confirmed v1 -->"), text.count("<!-- issue-intake:pending v1 -->")), "印の版")
    chk("S5", "番兵", 0, sum(1 for l in cb if "issue の URL" in l or l.strip().startswith("issue:")), "確定版の形の例に issue の URL の行がある")
    chk("S6", "番兵", 1, text.count("一覧は次の4つからなる。"), "2節の一覧の4つ")
    keep = [k for k in bs if not any(k.startswith(p) for p in ("## 2.", "## 3.", "## 5.", "## 6.", "## 8.", "## 補足"))]
    diffsec = [k for k in keep if bs.get(k) != es.get(k)]
    chk("S7", "番兵", [], diffsec, "直す節の外（front・いつ使うか・いつ使わないか・1・4・7・9・限界）に差分がある")
    keep_lines = [l for l in bl if l.startswith("- **最後の認識合わせのコメントが有効である。**")]
    chk("S8", "番兵", keep_lines, [l for l in cl if l.startswith("- **最後の認識合わせのコメントが有効である。**")], "6節の通し直しの文が変わった")
    return res

if __name__ == "__main__":
    ref = sys.argv[1] if len(sys.argv) > 1 else ""
    res = run(load(ref))
    fail = 0
    for i, issue, ok, e, a, note in res:
        if not ok:
            fail = 1
        print(f"{'PASS' if ok else 'FAIL'} {i} [{issue}]" + ("" if ok else f" (expected {e!r}, got {a!r}) {note}"))
    n = len(res); nf = sum(1 for r in res if not r[2])
    print(f"--- {n} 項目・FAIL {nf}")
    sys.exit(fail)
