# #536 html-one-pager の問いのカードの書き方・答えたカードを畳む・一覧から選ぶ問いを同じページに置く

## 背景

`html-one-pager` は、人に見せて答えてもらうページを作るスキルである（#428・#469・#478）。2026-10-24、#466 の判定ページ（26問・承認）を見た owner が「何を聞いているのか分かりづらい。今までのは判断できていたが、これは判断できない」と指摘した。たとえば Q1 は、題が「判断のページの種別」、推奨の選択肢が「推奨どおり」、要点が「回ごとに作る」だけで、何を決めるのか、推奨が何を意味するのかを読み取れなかった。統括が同じ URL に出し直した版2 では、題を問いの形にし、カードの塊を「何を決めるか」「推奨の中身」「ほかの案」の3つにそろえ、ボタンを中身の言葉にした。owner はこの版で26問すべてに答え、同じ書き方の判断ボードで9問に答えた。

同じ日に owner は、問いが16を超えると縦に長いので、答えたカードを畳んで題だけにできるとよい、と述べた（必須ではない・自動でなくてもよい）。さらに #466 の判定（Q32）で、一覧から行を選ぶ問いを同じページに置く直しを、別の issue にせずこの issue に入れると決めた。#466 の決定12 は「答え方の形でページを分けない」で、いまのスキルでは一覧から選ぶ問いは一覧から選ぶ種別（`pick`）のページにしか置けない。

## この plan の範囲

1つの PR で、`canonical/skills/html-one-pager/` に次の3つを入れる（owner 2026-10-24「強大な機能を実装するわけじゃないから、一つで」）。

1. **問いのカードの書き方**: 題を問いの形にする。「何を決めるか」「推奨の中身」「ほかの案」の塊と、中身を書いた選択肢の名前をそろえる。ほかの文書の符号（1A・4B' など）を説明なしで使わない。長い文書の節を指すリンクに節のアンカーを付ける。
2. **答えたカードを畳む**: 答えたカードを畳み、題と選んだ答えだけを出す（押すと開く）。
3. **一覧から選ぶ問いを同じページに置く**: #466 の discussion の 13.5 節の9項目。今の一覧から選ぶページの書き方を狭めない。開いた問いが0枚の判断ボードに、番号の列の無い表だけを置けるようにする。

触らないもの（brief の指定）:

- SKILL.md の「答えを受け取る」節の直し（会話で名指しした答えを正とする・#466 の決定16 など）と、判断ボードでの受け付けと回収の手順は #538 の範囲である。この単位は、判断ボードの「更新のしかた」の節に、選び方のカードを表へ移すときのページの決まりだけを足す（DJ-12）。
- 保存の形 `{key, choice, note, at}` と、一覧の行の答えの doc id `<カードの key>--<番号の数字>` は変えない。
- `template.html` と、完成した HTML の外部の読み込みの検査（E-B1）は変えない。

## 設計判断

### DJ-1 問いのカードの範囲と、書き方の決まり

**問いのカード**を、判定カードのうち、認識合わせ（`confirm`）のカードと承認のページの全体の承認のカード（札 `承認`）を除いたもの、と定める。承認・判断ボードの問い、束のカード、一覧から選ぶページの選び方のカード、レビューのページに足した判定カードがこれに当たる。

| 決まり | 当てるカード | 中身 |
|---|---|---|
| 題は問いの形 | 認識合わせのカードのほかのすべて（全体の承認のカードも含む） | 題の末尾の空白と、末尾に続く括弧書き（`（…）`・`(…)`。入れ子と連続を含む）を除いて、「か」「？」「?」で終わる。題だけで問いが分かるなら短くてよい |
| 選択肢の名前は中身を書く | すべてのカード | 選んだら何をするかを書く。推奨のボタンには「推奨」の札が付くので、「推奨どおり」「推奨の案で進める」のように推奨の語で始まる名前にしない。括弧書きだけの名前にもしない。括弧書きの中は見ない（「答えない（Q27 で推奨の形を選ぶ）」のように別のカードの推奨を指す書き方があるため）。推奨の語で始まらない名前（「非推奨 API を置き換える」）は中身を書いた名前として扱う |
| 中身は3つの塊に置く | 問いのカード | 1つ目の塊の題は「何を決めるか」（問いの前提・何に効くか）、2つ目は「推奨の中身」（推奨を選んだら何がどうなるか）。「ほかの案」を置くなら3つ目にし、それぞれの案の弱いところを書く。4つ目からは自由な塊を置ける。平らな要点（`points`）は置かない |
| ほかの文書の符号を説明なしで使わない | すべてのカード | discussion の案の符号（`1A`・`4B'`・案2b）や plan の `DJ-4` を、題・選択肢の名前・塊に、それが何かを書かずに使わない。カードの札にほかの文書の番号を書かない決まり（今の SKILL.md）を、カードの文の全体に広げる |

- 全体の承認のカードを塊の決まりから外すのは、問うことが「上の答えを入れた plan で進むか」に決まっていて、「何を決めるか」を書くと題の言い直しになるためである。平らな要点（「Q2 を入れないにしたときは…」）はそのまま置ける。題の形と選択肢の名前の決まりは当てる。
- 認識合わせのカードを外すのは、題が確かめる対象の名前で、答えが「確定」か「違和感がある」かに決まっているためである。認識合わせの塊は、今のとおり自由な題で必ず持つ。
- 推奨の行・根拠の行・塊の並びは変えない。カードの中は、題 → 推奨の行 → 根拠（書いたとき）→ 塊 → 選択肢、のままにする。owner は版2 でこの並びのまま答えている。

### DJ-2 決まりを何で支えるか

- **推奨: 塊（`blocks`）の形はそのままにし、塊の題の語を用語集に置き、検査で止める。** 用語集に新しい節「問いのカードの塊の題」を作り、`block.ask`（何を決めるか）・`block.recommend`（推奨の中身）・`block.alternatives`（ほかの案）の3つを置く。`build.py` はこの節を、識別子の接頭辞の節と同じく検証のときに読む。ページに出す札の言葉ではないので、答える部品のあるページの埋め込みデータには入れない。
- 退けた案は2つある（ゲート1 の木）。「SKILL.md の書き方の決まりと見本だけにする」は、統括が 10-24 から版2 の書き方を memory を頼りに手で守っている状態（確定版の「暗黙の工程」）を変えない。版2 の前の判定ページも、スキルの見本も、題が問いの形でなかった。「専用の欄（`ask`・`detail`・`alternatives`）を足し、スクリプトが塊に組み立てる」は、塊の題を書き間違えようがないが、カードの中身の書き方が `points`・`blocks` に加えて3つ目になる。#478 の decision の決定1 は、同じ部品に2つの書き方ができる形を退けている。

### DJ-3 書き方の検査の規則（E-Q1〜E-Q3）

新しい規則の組「E-Q」（問いのカードの書き方）を足す。

| 番号 | 何を弾くか | 見る条件 |
|---|---|---|
| E-Q1 | 題が問いの形でない | 種別が決まった値で、認識合わせでないページのカード。題が空でない文字列のときだけ見る（空なら E-C5 だけ・型が違えば E-F3 だけ） |
| E-Q2 | 選択肢の名前から括弧書き（入れ子を含む）を除いた残りが、空か、推奨の札の言葉（用語集の `recommend`）で始まる | すべてのカード。名前が空でない文字列のときだけ見る。種別に頼らない。対になっていない括弧は括弧書きとして除かない |
| E-Q3 | 問いのカードの塊の誤り（`blocks` が無い・1つ目の題が「何を決めるか」でない・2つ目の題が「推奨の中身」でないか塊が1つしかない・「ほかの案」が3つ目でない）と、問いのカードの `points` | 種別が決まった値のページの問いのカード。`blocks` が配列でないか空なら題は比べない（E-F3・E-C5 だけ）。題の比べは位置ごとに行い、その位置の塊がオブジェクトで題が文字列のときだけ見る（4つ目の塊の題が壊れていても、1つ目の題の食い違いは出る）。1つ目と2つ目の食い違いはそれぞれ出す。「ほかの案」が3つ目でないことは、読める題の中に「ほかの案」があるときだけ見る。`points` があることは塊と別に出す |

- **E-Q1 と E-Q2 は表記の規則である。** 題が問いの形でも何を決めるかが分かるとは限らず、選択肢の名前が推奨の語で始まらなくても中身があるとは限らない。検査が止めるのは、owner が指摘した形（話題の名前の題・「推奨どおり」のボタン）だけで、中身の質は書き手と見本が持つ。SKILL.md にそう書く。
- 同じ原因の誤りを重ねない抑止は、上の「見る条件」のとおり、親の値（種別・題の文字列・塊の配列・その位置の塊）に頼る判定だけを省く。knowledge item `01M5CFZVG82GHHBQYWZXNDP427` に従い、「重ねない」検査（壊した親だけで1件）と「隠さない」検査（親と関係の無い誤りを同時に入れて2件とも出る）を両方置く。たとえば、題を空にして選択肢の名前に「推奨どおり」と書くと E-C5 と E-Q2 が出る。種別を知らない値にして選択肢の名前に「推奨どおり」と書くと E-H3 と E-Q2 が出る。4つ目の塊の題を数にして1つ目の題を違えると、E-F3 と E-Q3 が出る。
- 受入の例にする名前と題: `推奨どおり`（止まる）・`推奨の案で進める`（止まる）・`（推奨）`（括弧書きだけで止まる）・`推奨（どおり`（括弧が対でなく止まる）・`非推奨 API を置き換える`（通る）・`答えない（Q27 で推奨の形を選ぶ）`（通る）・`答えない（Q27（推奨））`（入れ子で通る）・`実施する（推奨どおり）`（括弧の中は見ないので通る。限界に書く）。題は `どう持つか（前の Q1 の続き）`（通る）・`（前の Q1）`（括弧書きだけで止まる）・`一覧から選ぶページで、表の行ごとに選べるようにする`（止まる）。
- 符号を説明なしで使わない決まりと、題だけで問いが分かるかは、検査しない。`2FA`・`3D` のような普通の語と符号を見分けられず、意味は読まないと分からない。SKILL.md の限界に書く。
- 認識合わせの見本の選択肢「この内容で確定」「直してほしい（補足欄に）」は、どの規則にも当たらない。

### DJ-4 長い文書の節を指すリンク

- **推奨: SKILL.md の決まりにする（検査はしない）。** 関連リンク（`links`）で長い文書（節がいくつもある discussion や plan）を指すときは、答えに要る節の見出しのアンカーまで付け、`label` に節の名前を書く（例: `13.5 一覧から選ぶ問いの直し`）。アンカーは、GitHub で見出しの横のリンクから写す。見出しの文字から手で作ると、記号（`.`・`:`・括弧）の扱いで外れる。
- 検査しないのは、リンク先の文書の長さも、アンカーが実在するかも、ネットワークを使わないスクリプトでは分からないためである。限界に書く。

### DJ-5 畳む表示の作り

- **推奨: カードの頭（札・題・確かめた度合いの札）は今のまま外に置き、その下の中身を、ブラウザの開閉の要素（`<details>` と `<summary>`）で包む。** 作りは次のとおりにする。

  ```text
  article.hp-card#hp-card-<key>
  ├── div.hp-card-head（札・題の見出し・確かめた度合いの札。題の中の #N などのリンクもここ）
  └── details.hp-fold（開いているときは open）
      ├── summary.hp-fold-toggle
      │   ├── span.hp-fold-ans#hp-fold-<key>.ans（畳んでいるときだけ見える「答え: <選んだ選択肢の名前>」。key に使えない `.` で区切り、開閉の要素の id と重ならないようにする）
      │   ├── span.hp-fold-open（畳んでいるときだけ見える「開く」）
      │   └── span.hp-fold-close（開いているときだけ見える「畳む」）
      └── 推奨の行・根拠・塊・選び方の行・選択肢・補足欄・保存の印
  ```

  一覧から選ぶカードの答えの行には、選んだ行（`選んだ行: 候補2、候補5`）も添える。答えの無いカードを畳むと、答えの行は「未回答」になる。言葉は用語集に足す（`text.folded_answer`・`text.fold`・`text.unfold`）。
- 開閉はブラウザが受け持つので、押す・Tab で移って Enter か Space で開け閉めする・読み上げに開いているかを伝える、が JS なしで動く。題の見出しとリンクを `<summary>` の外に置くのは、`<summary>` の中の見出しは読み上げで見出しとして扱われないことがあり（推測）、中のリンクを押す操作と開閉の操作が混ざるためである。カードの id（`hp-card-<key>`）は外側の要素に残すので、本文の `Q2` のリンクの飛び先は変わらない。帯に隠れないかは、今の余白（`scroll-margin-top` の固定値）が畳んだカードでも足りるかを受入 A12 で測る。
- 退けた案（ゲート1 の木）: 「頭を `<summary>` の中に置き、題を押すと開閉する」は押す場所が大きいが、上の見出しとリンクの理由で退けた（設計SO の指摘6）。「JS で開閉のボタンを描き、答えのあるカードにだけ出す」は、答えの無いカードを畳めなくできるが、開閉の状態を JS が持つことになり、#428 の decision の決定2（描くのはスクリプトで、JS は答え・保存・回答待ちの件数だけを持つ）を崩す。「畳まず、答えたカードをページの下へ並べ替える」は、Q 番号の順が崩れ、#478 の決定4 の「番号の順に読む」と合わない。
- 答えの無いカードも手で畳めるが、それでよいとする。畳んだカードに「答え: 未回答」が出て、ヘッダーの回答待ちの件数も残る。

### DJ-6 いつ畳むか・種別ごとに効く時期

- **推奨: ページを開いたとき、答えのあるカードを畳んで出す。そのあとに選んだカードは、押したときだけ畳む。**
  - 回答待ち・随時更新のページでは、`page.js` が保存先の答えを最初に読み終えたとき（今の `synced` が立つとき）に1回だけ、選んだ答えのあるカードを畳む。そのあとに届いた答えでは畳まない（読んでいる最中に、ほかの画面で選んだカードが動かないように）。保存できない表示（artifact の外・`db` の無いページ）では保存先の答えが無いので、何も畳まない。
  - 最初の答えが届く前に、読む人がそのカードで選んだか補足欄に書いたとき（手元で変えた回数が0でないとき）と、そのカードの中の要素（補足欄・選択肢のボタン・リンク）にフォーカスがあるときは、そのカードを畳まない。保存先の答えより手元の操作を残す今の決まり（`page.js` の `isDirty`）に合わせ、入力中や操作中の要素を隠さないためである（設計SO の指摘6・Copilot の指摘）。選んだ行が選べる数を超えている選び方のカードも畳まず、畳んだあとに超えたときは開閉の行の答えの文に外すよう知らせる文を足す（外すよう知らせる文を隠さないため・Copilot の指摘）。
  - 回答済みのページでは、`build.py` が `answers` に選んだ答えのあるカードを、畳んだ形で描く（JS に頼らない）。「未回答」のカードは開いたまま描く。
  - 選んだその場では畳まない。選んだあとに補足欄へ書くことがあり、その場で畳むと補足欄が隠れる。
- 退けた案: 「押したときだけ畳む」は JS を足さずに済み、決定2 のままだが、判断ボードのように答えてから回収するまで残るページでは、読み込み直すたびにすべて開き直す。「選んだら自動で畳む」は補足欄が隠れる。
- 推奨の形は、`page.js` が答えに応じて開閉の状態を1回だけ動かすので、#428 の決定2 の「JS は答えだけを持つ」を「答えに応じて答えたカードを畳む」まで広げることになる（Q2）。knowledge item `01M5PKRS6WECYZTYFC4WXANW50` に従い、黙って広げず、承認の問いにする。

| 種別 | 畳む表示が効く時期 |
|---|---|
| 承認・認識合わせ・一覧から選ぶ・束・レビュー（判定カードを足したとき） | 回答待ちのあいだ（読み込み直すと、答えたカードが畳まれる）と、回収して回答済みにしたあと（答えたカードを畳んだ形で描く） |
| 判断ボード | 答えてから、統括が回収してカードを「最近決まったこと」の表へ移すまで。表へ移したあとは表の行なので、畳むものは無い |

### DJ-7 一覧から選ぶ問いを置ける種別と、カードと表の結び付き（13.5 の1・4）

- `select` を、承認（`approve`）・束（`bundle`）・判断ボード（`board`）のカードにも置けるようにする。一覧から選ぶページ（`pick`）は今のまま置ける。レビューの判定カードには置かない（13.5 の対象に無く、指摘の採否を行で選ぶ実例が無い）。
- 表の部品に任意の `key`（カードの key と同じ形・ページの中の表どうしで重ねない）を足す。選び方に `tables`（表の key の並び・1つ以上）を足し、どの表の行を選ぶかを名指す。
  - 一覧から選ぶページでは `tables` は任意で、書かなければ今のとおり、ページの番号の列のあるすべての表の行を選べる（`examples/pick.json` のように1枚の選び方のカードで3つの表を扱う書き方を狭めない）。書けば、名指した表の行だけを選べる。
  - 承認・束・判断ボードでは `tables` は必須である。1ページに、選び方のカードと表の組をいくつ置いてもよい。
  - 1つの表を名指せるのは、1枚の選び方のカードだけである。1枚のカードの `tables` の中でも同じ表を2回書かない。名指す表は番号の列を持つ。
  - 行の答えの key（`<カードの key>--<番号の数字>`）は、ページのほかのカードの key と重ねない。カードの key は `-` を含めるので、選び方のカード `tools` の候補1 と、別のカード `tools--1` は同じ保存先になる。今は一覧から選ぶページにカードが1枚しかないので起きないが、ほかの問いと混ぜると起きる（設計SO の指摘1）。重なれば E-C1 で止める。
- 一覧から選ぶページの「選び方のカードは1枚」は変えない。1枚の候補の一覧から選ぶページという種別の形を保つ。2つの一覧から別々に選ばせたいときは、承認か判断ボードに置く。
- 退けた案: 「表の側に、どのカードの表かを書く（`table.select_card`）」は、1枚のカードが複数の表を扱う今の一覧から選ぶページの形と向きが逆で、カードに推奨の行を書く今の形と離れる。「表の位置（何番目の部品か）で名指す」は、部品を足したり除いたりすると指す先がずれる。

### DJ-8 番号の列・接頭辞・番号の書き方（13.5 の2・5）

- `select` が名指した表（以下「選ぶ表」）は、種別に関係なく番号の列を置け、接頭辞は `候補` である。承認と束で番号の列を置けるのは選ぶ表だけである。判断ボードでは、選ぶ表の番号は `候補<数字>`、ほかの番号の列（決まったこと）は今のとおり `Q<数字>` である。
- 承認・束・判断ボードの選ぶ表では、番号を必ず書く（自動で振らない）。行の答えの doc id は `<カードの key>--<番号の数字>` なので、表を足したり除いたりして番号が振り直されると、保存された答えが別の行を指すためである。一覧から選ぶページは、今のとおり書かなければ振る。
- 候補の番号は、ページの中で表をまたいで重ねない（束の group の中の表も含めて、カードの札とほかの番号の列とも合わせて見る）。判断ボードでは、候補の番号も問いの番号と同じく使い直さない（表へ移した行の「候補2」が、あとで足した別の表の候補2 へのリンクにならないように）。版をまたいだ使い直しは検査では止められないので、SKILL.md に書く。
- 選ぶ表の行は、今の番号の列と同じく、本文から飛べるアンカーになる。束の group の中の選ぶ表の行もアンカーにし、group の中の文（カード・group の目的・表の欄）からも、ページの文からも飛べるようにする。#478 の decision の決定3（ページで定義した識別子はそのカードや行へのアンカーにする）に例外を作らないためである（設計SO の指摘8）。group の中の `#N` などのリンクは今のとおり group の送り元で作り、アンカーだけはページの中の行を指す（アンカーは送り元に頼らない）。
- 番号を3つ以上並べる書き方（E-I3）の検査は、選ぶ表のあるページでは `候補` の接頭辞も見て、束の group の中の文も見る。
- この直しは、#478 の decision の決定2（接頭辞の語は種別ごとに決める）を「種別と、選ぶ表かどうかで決める」に広げる。13.5 の5 のとおりで、owner は Q32 でこの直しを #536 に入れると決めている。

### DJ-9 並び（13.5 の6）

- 承認と判断ボードでは、判定カードの節の**直後**に、その節の選び方のカードが名指した表を、続けて置く。並びは、節の中の選び方のカードの順、1枚のカードの中は `tables` の順とする。この区間にほかの部品を挟まない。選ぶ表でない表は、今のとおり最後の判定カードの節のあとに置く（設計SO の指摘7）。
- 区間が上の並びと違うと E-K3 で止める。カードと表が離れると、owner は下まで読んでから上のカードへ戻ることになる（#478 の決定5 を作ったときの owner の指摘）。並びを1つに決めるのは、同じ節に2枚の選び方のカードがあるときも、どの表がどのカードのものかを位置で読めるようにするためである。
- 一覧から選ぶページの並び（選び方のカードの節が先頭・表はそのあと）は変えない。
- 承認のページで全体の承認のカードを最後に置く決まりと、選ぶ表を節の直後に置く決まりは両立する。選び方のカードを全体の承認のカードと別の節に置けばよい（見本は判断ボードで示す。DJ-15）。

### DJ-10 束の選ぶ表（13.5 の3）

- **推奨: 選ぶ表を group の中に置く。** group に任意の `tables`（表の部品と同じ形で、`key` は必須）を足し、group のカードのあとに描く。`tables` の並びは、DJ-9 と同じく、group の中の選び方のカードの順、1枚のカードの中は `tables` の順とする（違えば E-K3）。表の中の `#N`・`PR #N`・外部の課題管理の ID は、group の送り元でリンクにする（group の中のカードと同じ）。行の番号はアンカーになる（DJ-8）。group の表を名指せるのは、同じ group の選び方のカードだけである。group の表はすべて選ぶ表で、名指されていない表は置けない。
- 退けた案: 「選ぶ表を束の部品のあとに、ページの部品として置く」は、表の識別子がページの送り元でリンクになり、別のリポジトリの group の候補が間違ったリポジトリを指す。カードと表のあいだにほかの group が挟まり、DJ-9 の「直後に置く」が束では作れない。

### DJ-11 描画と埋め込み（13.5 の7）

- `build.py` の `pick_info` を、選び方のカードごとの組の並びにする。選び方の行（「表の行を2つまで選ぶ」「選んだ行」）は各選び方のカードに、チェックは各組の表の行の番号の欄に描く。埋め込みデータの `picks` には組をすべて入れる。
- `page.js` は `picks` を配列で回していて、返答の文も組ごとにカードの下へ選んだ行を足す作りなので、一覧の行の扱いは変えない。変えるのは DJ-6 の畳む処理だけである。
- 行の id は、ページの表は今の `hp-row-<部品>-<行>`、group の表は `hp-row-<部品>-g<group>-t<表>-<行>` にし、重ならないようにする。

### DJ-12 回収と止め方（13.5 の8）

- 判断ボードで選び方のカードを回収して「最近決まったこと」の表へ移すときは、そのカードが名指した表も、同じ出し直しでページから除く。除いた表の行は押せなくなる（13.5 の8 の「行の入力も止める」）。除き忘れると、判断ボードでは名指されていない `候補` の番号の列が問いの番号の形でないので E-I1 で止まり、承認と束では名指されていない番号の列が E-K2 で止まる（誤りの文に「選ぶ表なら選び方の `tables` で名指す」を添える）。
- 移した行には、選んだ行を番号と名前で書く（`候補2（LogCollector B）・候補5（Notifier E）を試す`）。表を除くので、番号だけでは何を選んだか分からなくなるためである。
- **回収のときに上限を確かめる経路: 推奨は `check` に `--answers <回収した答えの JSON>` を足すこと。** 判断ボードは `answers` をページに書かない（#428 の決定4 の追補・#466 の決定3）ので、今は上限を機械で確かめる経路が無い（13.5 の8）。入力の決まりは次のとおりにする（設計SO の指摘2）。
  - 渡すのは、保存先から読んだ文書をすべて、`answers` と同じ形（`{"<key>": {"choice", "note", "at"}}`）に写したものである。絞り込まずに渡す。
  - ページに無い key（前の回収で表へ移したカードの答え・除いた表の行の答え）は、見ずに数だけを標準エラーに出す。同じ URL の保存先には、移したカードの答えが残り続けるためである（SKILL.md の「公開する」節・判断ボードの更新のしかた）。保存先から写したものなので、打ち間違いの key は入らない前提である。
  - ページにある key（カードと行の答え）は、今の `answers` の検査（E-A1: 選択肢の key か `null`・`note` と `at` が文字列・選び方のカードごとに選んだ行の数が上限を超えない）で見る。ページの状態（回答待ち・随時更新・回答済み）に関係なく見る。
  - 回収するカードと表を除く**前**のデータに当てる。除いたあとのデータに当てると、そのカードの答えはページに無い key として数えられるだけになる。
  - ページに `answers` があるとき（回答済みのページ）は、ページの `answers` を今の決まりで、渡した答えを上の決まりで、それぞれ見る。
  - 承認のページでも、`answers` に写す前に同じ確かめができる。
- 退けた案: 「SKILL.md に、行の数を数えて確かめると書くだけ」は、#478 の決定5 で「回収した答えが上限を超えていたら止める」としたのと同じ確かめを、判断ボードだけ人の目に戻す。「判断ボードにも `answers` を書けるようにする」は #466 の決定3（表の行と台帳を正とする）と食い違う。
- 回収の手順（いつ読み、どの順に移し、台帳にどう書くか）は #538 で決める。この単位が SKILL.md に書くのは、判断ボードの「更新のしかた」の節の、選び方のカードを移すときのページの決まり（表を除く・行の書き方・`check --answers` で確かめる・候補の番号を使い直さない）だけである。

### DJ-13 検査の規則（13.5 の9）

| 規則 | 直し |
|---|---|
| E-K2 | `select` を置けない所を「認識合わせのカード・レビューのカード・一覧から選ぶページの2枚目のカード」に変える。承認と束の、選ぶ表でない表の番号の列を止める。束の group の、名指されていない表を止める |
| E-K3 | 承認と判断ボードで、判定カードの節の直後の選ぶ表の区間が、DJ-9 の並びと違うことを止める |
| E-C1 | カードの key が、ほかの選び方のカードの行の答えの key（`<key>--<数字>`）と重なることを止める |
| E-C6 | 選ぶ数の検査のうち、`min` が選べる行の数を超えることを、組ごとの行の数で見る |
| E-C7（新） | 選び方の表の名指しの誤り: `tables` が無い（承認・束・判断ボード）・空の配列・1枚の中で同じ表を2回書く・名指した表がページに無い・番号の列が無い・2枚のカードが同じ表を名指す・束で別の group の表を名指す。`tables` の型の違い（配列でない・要素が文字列でない）は E-F3 |
| E-I1 | 選ぶ表の番号を `候補<数字>` で見る。承認・束・判断ボードの選ぶ表で番号を書いていないことを止める。推奨の行は、その組の表で定義された番号かを見る |
| E-I2 | 候補の番号の重なりを、group の表も含めてページ全体で見る |
| E-S3 | 表の `key` の形と、表どうしの重なりを見る |
| E-A1 | 選んだ行の数の上限を組ごとに見る（今の検査は組が1つ）。`check --answers` で渡した答えにも当てる |

- 同じ原因の誤りを重ねない: 抑止は、判定が何に頼るかで分ける（設計SO の指摘5）。
  - 表への参照に頼る判定（推奨の行がその組の表で定義されているか・`min` が選べる行の数を超えるか・行の答えの key の登録）は、その組の名指しに誤り（E-C7）があれば見ない。
  - 選び方の中だけで決まる判定（`min` が `max` より大きい・推奨の行が `max` を超える・推奨の行が重なる・`max` と `min` の型）は、名指しの誤りがあっても見る（今の `select` の検査のまま）。
  - 名指した表の列が壊れているときは、番号の列が無いことの誤りを出さない（E-S3 だけ）。
- 「隠さない」検査として、次を同時に入れて2件とも出ることを確かめる。名指しの誤り（E-C7）と、別の組の推奨の行の誤り（E-I1）。無い表の名指し（E-C7）と、同じカードの `min > max`（E-C6）。
- 今の一覧から選ぶページの書き方を狭めていないことは、正しいデータの検査で確かめる。`select` の無い選び方のカード・`tables` を書かない `select`・番号の列のある表が3つ・番号を書かない・番号を書く、の5つが今のとおり通る（設計SO の指摘7）。
