# #558 html-one-pager に、1枚のページを長さや中身で分けるタブの部品を足す

## 背景

`html-one-pager` は、人に見せて読んでもらう・答えてもらうページを作るスキルである（#428・#469・#478・#536）。いまの SKILL.md の「限界」には「長いページのタブの部品は、まだ無い」とある（`canonical/skills/html-one-pager/SKILL.md:524`）。

2026-10-26 に owner が、判断ボードが長くなったときの分け方として「URL 1枚にしつつ、タブでページの粒度自体を分割する」案を出した。2026-10-28 には、ある統括の見取り図（13の節・約100KB）で owner が「下に長いからタブ形式にできるか」と言い、統括が `--body` に CSS だけのタブ（radio の `input` と `label`・JS なし）を手で書いた。続けて余白の直しが2回来た（16px → 28px・24px → 36px）。同じ日に owner は、段ごとに1行・左に段の名前・URL の `#` でタブを開ける資料のページを作っている。owner によると、長いページは頻繁に出る。

確定版（related の2つ目）で、owner は9項目を推奨どおりに決めた。この plan は、その9項目をそのまま前提にし、確定版の「要ること」の残り（幅の狭い画面・既存のページを変えないこと・キーボードとスクリーンリーダー・切り替えても答えが失われないこと）を満たす作りを決める。

## この plan の範囲

1つの PR で、`canonical/skills/html-one-pager/` に、タブの部品を足す。

- データの部品（`sections`）にタブを割り当てる形と、`--body` の本文に決まった class のパネルを書く形の両方を、同じ見た目と振る舞いで持つ。
- `build.py` の検証（タブの書き方・段の上限・種別）と描画、`page.css`、タブの切り替えの JS（新しいファイル）、`page.js` の未回答の件数、`glossary.md`、検査、見本、SKILL.md を直す。SKILL.md の「限界」からタブを外す。
- hub の側の変更は `canonical/CATALOG.md` の html-one-pager の行1つである。

触らないもの（brief の指定）:

- 判断ボードの作業の表と4層の文書の列（#539 の本体）。
- 図の部品（Mermaid など）。`--body` に `pre.mermaid` を置く書き方は今のままにする。
- `judgment-board-flow`。
- 保存の形 `{key, choice, note, at}`・行の doc id・`template.html`・完成した HTML の外部の読み込みの検査（E-B1）。

## 設計判断

### DJ-1 データの形

ページに任意の項目 `tabs` を足し、タブを1つずつ定義する。部品（`sections` の各要素）には任意の項目 `tab` を足し、どのタブに入るかを書く。

```json
{
  "tabs": [
    {"key": "now", "label": "いま決めること", "row": "判断"},
    {"key": "values", "label": "もらう値", "row": "判断"},
    {"key": "done", "label": "決まったこと", "row": "記録"}
  ],
  "sections": [
    {"type": "decisions", "tab": "now", "title": "…", "cards": []},
    {"type": "table", "tab": "values", "title": "…", "columns": [], "rows": []},
    {"type": "table", "tab": "done", "title": "決まったこと", "columns": [], "rows": []}
  ]
}
```

- `key`（必須）は URL の `#` の名前で、英小文字で始まり、英小文字と数字だけが続く20文字までにする（`-` と `_` を使えない理由は DJ-5）。ページの中で重ねない。
- `label`（必須）はタブに出す名前である。空にしない。平文で、書式（コード・リンク）は効かない。
- `row`（任意）は段の名前である。確定版の「段の名前はデータでタブに付ける」のとおり、タブごとに書く。書くなら全部のタブに書く。
- 部品の `tab` は、`tabs` の `key` のどれかである。`tabs` を書いたページでは、すべての部品が `tab` を持つ。`tabs` の無いページでは、どの部品も `tab` を持たない。
- 1つのタブの部品は続けて並べ（あいだに別のタブの部品を挟まない）、タブの順は `tabs` の順と同じにする。こうすると、データの並び・描く並び・JS が動かない表示の並びが1つにそろい、種別の並びの検査（E-K3）を今のまま当てられる。
- タブの中の部品の並びと種別の決まり（承認の全体の承認のカードは最後・判断ボードは判定カードの節が先、など）は、今のままページ全体の並びで見る。
- 選び方のカードと、そのカードが名指した選ぶ表は、同じタブに置く（設計SO の指摘6）。ページ全体の並び（選ぶ表は選び方のカードの節の直後）を守ったまま、節と表のあいだでタブを切ると、問いと候補の一覧が別のタブに分かれ、今は同時に見えるものが見えなくなるためである。

### DJ-2 本文（`--body`）でタブを書く形

本文では、タブの中身（パネル）だけを書く。タブの名前・段・`#` の名前は、本文を使うときもデータの `tabs` に書く。

```html
<style> /* 本文の CSS */ </style>
<section class="hp-tabpanel" id="overview">…</section>
<section class="hp-tabpanel" id="steps">…</section>
```

- パネルは class `hp-tabpanel` を持ち、`id` がそのタブの `key` である `section` か `div` の要素にする。ほかの要素（`p` など）を使えなくするのは、ブラウザが暗黙に閉じる要素だと、`build.py` の読み取り（標準の `html.parser`）とブラウザの読み取りで、中身がパネルの中か外かが食い違うためである（設計SO の指摘3。`<p class="hp-tabpanel"><div>…</div></p>` を `html.parser` は `p` の中の `div` と読み、ブラウザは `div` の前で `p` を閉じる）。
- タブのあるページでは、本文の一番外に置けるのはパネルと `style`・`script` の要素だけにする（空白とコメントはよい）。パネルの外に置いた中身は、どのタブを選んでも出続けるためである。パネルを別の要素の中に入れない（入れ子のパネルを作らない）。同じ `key` のパネルを2つ書かない。
- タブのあるページの本文では、空の要素でない要素を `/>` で閉じる書き方（`<div/>`）と、1つの要素に同じ属性を2回書く書き方を止める。前者は `html.parser` が空の要素と読み、ブラウザは開いたままにする。後者は `html.parser` が後ろの値を、ブラウザが前の値を使う（P2 で `html.parser` に当てて確かめた）。どちらも、パネルの判定がブラウザとずれる形である。
- 1つのタブの中身は、本文のパネルかデータの部品のどちらか片方にする。本文とデータを1つのページで混ぜることはできる（10-28 の参考のページは、本文のタブとデータの表のタブを混ぜていた）。本文は部品の上に出るので、`tabs` の順は、本文のパネルのタブを先に、データの部品のタブをあとに並べる。
- 本文に `hp-tabpanel` を書いたのに `tabs` が無いとき、`tabs` のタブに中身が無いとき（本文にもデータにも無い・`check` に `--body` を付け忘れた）は止める（DJ-13）。

この形にしたのは、帯をデータから描けば、本文の HTML を `build.py` が書き換えずに済むためである。本文だけでタブを宣言する形と、帯も本文に手で書く形は、ゲート1 の木で退けた。

### DJ-3 タブを置ける種別

- 確定版のとおり、`map`（見取り図）・`board`（判断ボード）・`approve`（承認）・`bundle`（束）に置ける。`confirm`（認識合わせ）と `pick`（一覧から選ぶ）には置けない。
- `review`（レビュー）は、確定版の列挙に無いので置けない（「確定版に無い判断」の N4）。
- 本文を置ける種別は今のまま（`approve`・`map`・`bundle`・`review`）なので、本文のタブを使えるのは `map`・`approve`・`bundle` である。判断ボードは本文を置かないので、データの部品のタブだけを使う。
- 束のページは、いまは束の部品（`bundle`）を1つしか置けない。タブで分けるには部品が2つ以上要るので、`tabs` のある束のページでは、束の部品をタブごとに1つまで置けるようにする（N3）。カードの key・表の key・候補の番号がページ全体で重ならない決まりは今のままである。

### DJ-4 段と上限

- 1つの段に置けるタブは6つまでにする（確定版の「目安6」）。7つ目で `check` が止まり、段に分けるよう知らせる。
- `row` を書かないページは、全体を1つの段として数える。タブが7つ以上なら、段に分けるまで止まる。これで、ページを作る側に指示が無くても、多いときは段に分ける。
- 同じ段の名前は続けて並べる（あいだに別の段を挟まない）。段の名前を書いたタブと書かないタブを混ぜない。
- タブは2つ以上にする。1つだけのタブは何も分けない。
- 段の数には上限を置かない（N8）。段が多いと貼り付く帯が高くなる。I1-5 で幅 400px・高さ 約800px の高さを測って episode に残し、画面の高さの 40% を超えたら、PR の前に統括へ問いを送って待つ（A6・N13）。

### DJ-5 `#` の名前と要素の id

- パネルの要素の id は、タブの `key` そのものにする（`id="now"`）。URL の `#now` が、JS が動かない表示でもそのパネルへのふつうのリンクになる。
- `key` は英小文字と数字だけにする。`build.py` が描く要素の id は、どれも `hp-` で始まり `-` を含むので、`key` から作った id はそれらと重ならない（knowledge item `01M5PTAXJ7H0WFZ5C83HXD4RZ4` の「key に使えない文字で区切る」の形）。
- タブのリンクの id は `hp-tab-<key>`、未回答の件数の要素の id は `hp-tab-<key>.n`、段の名前は `hp-tabrow-<段の順>`、すべての段を包むタブの並びは `hp-tabset`、帯は `hp-tabbar`、埋め込みのデータは `hp-tabs-data` にする。`hp-tab-` のあとは `key`（`-` を含まない）なので、ほかの作り方の id（`hp-tabbar`・`hp-tabset`・`hp-tabrow-…`・`hp-card-<カードの key>` など）と重ならない。件数の要素の区切りの `.` は、`hp-opt-<key>.<選択肢>` と同じく key に使えない文字である。
- タブのあるページでは、本文の要素の id に次の3つを止める（E-N4・`check` に `--body` を付けたとき）: `key` と同じ id（そのタブのパネル自身を除く）・`hp-` で始まる id・本文の中で2回現れる id。`hp-` は `build.py` が描く要素の id の頭なので、本文には使わせない。こうすると、本文に `id="hp-tab-now"` や `id="hp-tab-now.n"` を書いて、JS が操作する要素を取り違える形（設計SO の指摘2）も止まる。描く要素の id をすべて数え上げて本文の id と比べる形より、決まりが1行で済み、描く id の作り方を足したときにも検査を直さずに済む。
- `hp-` の頭を本文に使わせない決まりは、タブの無いページには当てない。タブの無いページの本文にも同じ危険（本文の `id="hp-store"` など）は今もあるが、当てると今の単位の範囲を広げ、通っていたページを止めうる。episode の follow-up に残し、決めるのはその仕組みを扱う単位にする。
- 描いた要素の id どうしが重ならないことは、検査の `ElementIds` をタブの見本にも当てて確かめる。

### DJ-6 描く形

- **帯の置き場**: タブの帯（`nav.hp-tabbar`）は、上に貼り付く箱（`.hp-bar`）の中に描く。答える部品のあるページ（回答待ち・随時更新）では、全部推奨どおりの案内と保存の状態の下に帯を足す。回答済みのページは、いまの「回収済みのページです」の知らせ（貼り付かない）のあとに、帯だけを入れた貼り付く箱を置く。答える部品の無いページ（見取り図）は、帯だけを入れた貼り付く箱を置く。2つの貼り付く帯を重ねて置かないためである（N7）。
- **帯の中**: 段ごとに1行で、段の名前を左に置き、段の中のタブは1行に並べて、収まらなければその段の中だけを横に送る。タブはリンク（`<a class="hp-tab" href="#<key>">`）として描く。選んだタブには下線を付ける（JS が `aria-selected` を付けたとき）。段の名前の無いページでは、名前の列を出さない。帯には `aria-label`（用語集の新しい言葉 `text.tabs`「ページの中の切り替え」）を付ける。
- **パネル**: データの部品のタブは、`build.py` が `<section class="hp-tabpanel" id="<key>">` で、そのタブの部品を包む。本文のパネルは書き手が書いたまま出す。
- **見出しの重なり**（確定版の「見出し」）: タブの中の最初の部品の題が、タブの名前と同じ（前後の空白を除いて文字列が一致する）なら、その題の `h2` に class `hp-tab-same` を足す。JS が動いているあいだだけ、この見出しを隠す。JS が動かない表示では、すべてのパネルが縦に並ぶので、見出しを残してパネルの区切りにする。本文のパネルでも、同じ class を付ければ同じに動く（SKILL.md の「本文の見た目」の表に足す）。本文では `class="hp-sec-title hp-tab-same"` と、部品の見出しの class と一緒に書く。素の `h2` に `hp-tab-same` だけを付けると、class の無い要素に当たる見た目（`h2:not([class])`）が外れるためである（設計SO の注意）。
- **余白**（確定版の「余白」）: 帯の下の線から、最初に見える部品の上端までを 28px にする。パネルの中の部品どうしは 36px にする。どちらもタブのあるページの中だけに効かせ、タブの無いページの余白は変えない。本文のパネルの中の要素どうしにも 36px が付く。
- **件数**: 回答待ちと随時更新のページでは、判定カードのあるタブの名前の横に、未回答のカードの数を「回答待ち N 件」（用語集の `status.awaiting`）の札で出す。0件のタブでは隠す。回答済みのページでは出さない（N5）。最初の値は `build.py` が描き、そのあとは `page.js` が書き換える（DJ-9）。

### DJ-7 JS の形

- タブの切り替えは、新しいファイル `tabs.js` に書き、`tabs` のあるページにだけ入れる。`page.js` には入れない。答える部品の無いページ（見取り図）にも切り替えは要るが、保存のコードは入れない決まり（#428）を守るためである。
- `tabs.js` が引く要素は、`getElementById` と、`parentNode` をたどって見つけるものだけにする（聞く出来事は、タブの `click` と `keydown`、`document` の `click`、`window` の `hashchange` と `resize`）。必要な一覧（タブの `key` の並び・段の数）は、`build.py` が `<script type="application/json" id="hp-tabs-data">` に埋め込む。`page.js` と同じ形の node の台で、振る舞いを検査できるようにするためである。
- **1つの入口**: タブを選ぶ処理を1つの関数（選ぶタブと、見せたい要素と、`#` を書き換えるかを受け取る）にまとめ、押す・キー・ページを開いたときの `#`・`hashchange`・ページの中のリンクを押す、のどれもその関数を通す（設計SO の選択肢拡張の「1つの状態遷移」）。入口ごとに分岐を書くと、同じ `#` をもう一度押す場合のような組み合わせで抜けが出るためである。
- **スクリーンリーダーの印**（設計SO の指摘5）: 段がいくつあっても、意味の上ではタブの並びを1つ（帯の中の、すべての段を包む要素に `role="tablist"` と帯と同じ言葉の `aria-label`）にする。段は見た目と横送りの単位で、段の要素は `role="none"` にし、段の名前は各タブの `aria-describedby` で伝える（段の名前の文字は `aria-hidden="true"` にして、タブの並びの中の余計な文字として読ませない）。選ぶものも、Tab キーで止まる所も全体で1つで、左右の矢印キーが段をまたぐ動き（N10）と、読み上げの上の集まりがそろう。タブに `role="tab"`・`aria-controls`・`aria-selected`・`tabindex`（選んだタブだけ 0、ほかは -1）を、パネルに `role="tabpanel"`・`aria-labelledby`（そのタブのリンク）・`tabindex="0"` を付ける。パネルに `tabindex="0"` を付けるのは、本文だけのパネルのように最初の要素で止まれないパネルにも、Tab キーで入れるようにするためである。
- 始めたときにすること: 帯に `data-on` を付ける（タブとして動いている印。見出しの重なりを隠す CSS と、選んだタブの下線がこれで効く）。上の印を付け、貼り付く箱の高さを測る（下）。そのあとに選ぶタブを決める。
- 選ぶタブ: URL の `#` がタブの `key` ならそのタブ、`#` が指す要素がどれかのパネルの中にあればそのパネルのタブ（DJ-8）、どちらでもなければ最初のタブを選ぶ。選ばないパネルには `hidden` を付ける。
- タブを押したとき: そのタブを選び、`history.replaceState` で URL の `#` をタブの `key` に書き換える（履歴を積まず、ページも飛ばない。N6）。帯が貼り付いている（ページを帯の元の位置より下まで読み進めている）ときは、パネルの上端が帯のすぐ下に来るように送る。そうでないときは送らない。`replaceState` が使えない表示（投げる）では、`#` を書き換えずにタブだけを切り替える。
- キー: 左右の矢印キーで、段をまたいで前後のタブへ移り、そのタブを選ぶ（端では反対の端へ回る。N10）。Home と End は最初と最後のタブへ移る。Space でもタブを選ぶ（Enter はリンクとして押される）。
- 貼り付く箱の高さ: `tabs.js` は貼り付く箱（帯の親）の高さを測り、ページの根の要素に CSS の変数 `--hp-bar-h` で渡す。高さが変わったら（`ResizeObserver` があれば箱の大きさの変化で、無ければ画面の大きさの変化で）測り直す。CSS は、ページの中のリンクで飛ぶ先（パネル・カード・表の行・本文の `:target`）の `scroll-margin-top` に、貼り付く箱の上端の位置（`env(safe-area-inset-top)`。いまの `.hp-bar` の `top` と同じ）と、この高さと、16px を足した値を使う（設計SO の指摘7）。JS が動かない表示では、決まった値（帯の高さの見込み）を使う。
- 移ったあとに箱が高くなったとき: 保存の状態の文が長くなる（接続できず「この表示では保存できません」に変わる）などで、移ったあとに箱が高くなると、見せた要素の上端が箱に隠れうる（設計SO の指摘7）。リンクやページを開いたときの `#` で要素を見せたあと 3秒のあいだに箱の大きさが変わり、見せた要素の上端が箱の下端より上に来たら、その差だけ送り直す。読む人が自分でページを送ったら、送り直さない。
- #428 の決定2（ページの JS は答え・保存・回答待ちの件数だけを持つ）を、タブの切り替えまで広げることになる。確定版で owner が「小さな JS で切り替える」と決めた。DJ-16 に書く。

### DJ-8 隠れたタブを指すリンク

- 確定版のとおり、隠れたタブの中を指すリンク（本文の `Q2`・`候補4` のページの中のアンカー、本文の `#…` のリンク）を押したら、そのタブに切り替えてから移る。

### DJ-13 検査の規則

新しい規則の番号を `E-N`（ページの中の切り替え）にする。

| 番号 | 何を弾くか |
|---|---|
| E-N1 | タブの定義の誤り（`key` の形が合わない・重なる、`label` や `row` が空、タブが2つ未満（空の配列を含む）） |
| E-N2 | 段の誤り（段の名前を書いたタブと書かないタブが混ざる・同じ段の名前が離れて現れる・1つの段のタブが6つを超える・段の名前を書かずにタブが6つを超える） |
| E-N3 | タブと中身の対応の誤り。データの側は、`tabs` のあるページで部品に `tab` が無い・`tab` が定義に無い・`tabs` の無いページの部品に `tab` がある・同じタブの部品が離れている・タブの並びと中身の並びが違う・選び方のカードと名指した選ぶ表が別のタブにある。本文の側は、本文のパネルの id が定義に無い・同じ `key` のパネルが2つある・パネルが `section` か `div` でない・本文の一番外にパネルと `style`・`script` 以外の要素か文字がある・パネルの中にパネルがある・空の要素でない要素を `/>` で閉じている・1つの要素に同じ属性が2回ある・本文に `hp-tabpanel` があるのに `tabs` が無い。両方にまたがるのは、中身の無いタブ・1つのタブに本文のパネルとデータの部品の両方がある |
| E-N4 | タブのあるページの本文の id の誤り（タブの `key` と同じ id・ただしそのタブのパネル自身を除く／`hp-` で始まる id／本文の中で2回現れる id） |

- タブを置けない種別（`confirm`・`pick`・`review`）の `tabs` は、種別に置けない補足として E-K2 で止める。束の部品の数の決まりは、`tabs` のある束のページでは「1つのタブに束の部品は1つまで」（E-K2）にする。
- 型の誤り（`tabs` が配列でない・タブがオブジェクトでない・`tab` が文字列でない）は今までどおり E-F3、知らない項目は E-F2 で止める。
- 同じ原因の誤りを重ねない（設計SO の指摘11）: タブの `key` が形に合い重ならないものを「引けるタブ」とする。`label` や `row` の誤りは、そのタブを引けないものにしない。部品の `tab` と本文のパネルの id は、引けるタブの `key` にだけ当てる。`key` の誤りで引けないタブを指す部品は、「定義に無い」を重ねて出さない（引けないタブの `key` の文字列と一致する `tab` は見ない）。`tabs` が配列でないときは、E-N2・E-N3 を見ない。種別がタブを置けないときは E-K2 だけを出し、タブの中身は見ない。どれも、2つを同時に壊した壊したデータの検査で、出してはいけない誤りが出ないことを確かめる。
- 本文を読むのは標準の `html.parser` で、`--body` を渡したときだけである。本文の文字列は `Validator` が受け取り、`validate`・`check_collected`（`check --answers` の経路）・`check` と `build` のコマンドのすべてから渡す（設計SO の指摘10。`check --answers` は `validate` を通らずに `Validator` を作る）。今の `has_body` は残す。同じ崩れた本文が、`check`・`check --answers`・`build` で同じ誤りで止まることを検査する。
- 要素の閉じ方は、終わりの印で、同じ名前の開いた要素まで戻る形で読む（閉じ忘れた `p` のような正しい HTML を誤りにしない）。対応する開いた要素の無い終わりの印は無視する。

## リスク・未確認事項

- **貼り付く帯の高さ**: 答える部品のあるページで、幅 400px・保存できない表示の長い文・段が3つのとき、帯の合計の高さが画面の高さの多くを占めうる。I1-5 で測って episode に残し、画面の高さの 40% を超えたら、PR の前に統括へ問いとして送る（A6）。段の数の上限や帯の詰め方は、この単位では決めない。
- **artifact の外の URL**: `replaceState` で書き換えた `#` が、artifact の表示の外側の URL（共有するリンク）に届くかは、表示の側の作りによる [speculation]。開いたときに外側の URL の `#` が中のページへ渡ることは、10-28 の参考のページで owner が使っている [unverified-summary]（確定版の「要ること」の行）。手元の確かめは、手元で開く完全な文書（`--standalone`）でだけできる。公開したサンプルで統括か owner が確かめる（DJ-15 の「保証の範囲」）。
- **`ResizeObserver` が無い表示**: 画面の大きさの変化でだけ測り直すので、保存の状態の文が変わって帯の高さが変わったとき、リンクで移った先の余白がずれうる。今のブラウザはどれも `ResizeObserver` を持つ [speculation]。
- **本文の読み取り**: `html.parser` はブラウザの読み取りの決まり（暗黙に閉じる要素・表の中身を表の外へ出す読み方など）を持たない。パネルの要素を `section` と `div` に絞り、`/>` で閉じる書き方と同じ属性の2回を止めて、パネルの内か外かがずれる形を減らす。それでもずれうる形（表の中にパネルを書くなど）は残るので、崩れた本文の検査を、`p` のパネル・`/>` で閉じたパネル・閉じ忘れたパネル・余分な終わりの印・同じ属性の2回の5つ置き、ブラウザでも見本の本文のパネルが `main` の直下にあることを確かめる（A6）。
