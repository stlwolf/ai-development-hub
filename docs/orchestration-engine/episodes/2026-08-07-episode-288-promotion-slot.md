## Context（なぜこの作業が始まったか）

## M3. gate 3 — owner が「多重アンカー」で範囲を決めた

owner の整理（`.oe/addendum-288-marker.md`）:

- 昇格と closure はもともと一緒になるよう設定されたものではない。昇格は4層ドキュメントのフローの話。
- closure は episode の品質を高めるために採用したもので、役目は「AI が作業を終えたと思った後から、マージされて人間の承認が出るまでに起きたこと」を振り返ること。随時追記とは離れた立て付け。
- **それでも closure に昇格の判定が乗っているのはおかしくない。** 理想はゲートが1個の常に動くコンポーネントとして毎回判断してくれることだが、そうはならなさそうなので、**それで動かなかった場合に最後にもう一度確認するフロー**として立て付けられているから。
- アンカーは多い方がよい。**ただしマーカー式は難易度が高いので、マーカーだけに賭けない。**

これを受けて rev.3 の差分は1点に絞った — **その場で印を置く側を足す。**

### P0-1: 裸行であることを正本が言っていなかった（2レーン独立）

**最も重い指摘。** 正本はコードブロックで形を例示していたが、「Markdown 装飾を付けない裸行」という規範を**言葉で書いていなかった**。

**直した**: 正本の先頭箇条に「行頭の裸行として置く。囲まない」と、囲んだ場合は印にならないことを明記。あわせて「語彙に言及するときは逆に囲んで区別する」も書いた。委譲固定節にも「**行頭の裸行**（囲むと印にならない）」を足した。

### P0-2: 「導入日」が値として存在せず、self-complete でなかった（2レーン独立）

不在の解釈規則は「本節の導入日より前なら対象外」と書いていたが、**その導入日がどこにも値として無かった。** 配布された canonical だけを読む消費者は git 履歴を見ないと境界を計算できない。**配布物は self-complete という制約に違反していた。**

しかも正本は「言えること」として「不在を3通りに切り分けられる」と書いており、**成立しない主張を正本に書き込んでいた**（前版の gate 2 で同じ型を指摘されたばかりである）。

**直した**: `date` が `2026-08-07` より前、と具体日を節に書いた。あわせて**日単位の粗さ**（導入日当日の episode は対象外に落ちない）を限界として明記した。

### P1-3: checklist の「該当なし」と `promotion: []` の写像が無かった（cursor）

必須項目は「該当なし」は正当と書いているだけで、`[]` との対応が無い。**放置すると「全部 not-required だったから該当なし → `[]`」と読まれ、rev.1 で SO に潰された故障が再発する。** checklist 本文は触れないので、隣接節に写像を1行足した。

### P1-4: 印と `promotion` エントリの対応規則が無かった（codex）

「印を分母の候補として使う」としか書いておらず、**各印が実際に検討されたかを後から言えない**。`subject` の一意性規則も無かった。隣接節に「印1件につきエントリ1件（同じ判断の重複印はまとめてよい）」「closure 側と同じ1行要約を使う」を足し、正本側に `subject` の一意性を書いた。

### 過大主張2件を弱めた（codex）

- 「配布物に入らなければ**一次アンカーが発火しない**」→ 子が正本を開く経路・親が個別指示する経路が残るので、「固定節だけを読む委譲では**発火しにくく被覆が落ちる**」に弱めた。
- 「固定節のインラインコードは印として拾われない」→ **正本に裸行規則が無い時点では先走りだった**ので、規則を足したうえで「正本の定義を外れるから」と条件付きにした。

### 問題なしと判定された点

### わかったこと

- **`verdict: required | not-required | unknown` は YAML では1本の文字列にパースされる**（`ruby -ryaml` で確認）。規約のテンプレートに値域を並べて書くと、未編集コピーがスキーマ違反にならずに通る。
- **固定接頭辞は語形の変化で正しく外れる** — 既存の `振り返り不要:` は変形の `振り返り不要の補足:` を拾わない。一方 enum 値の grep は無関係な別 enum を拾う。

### 原則（Pattern / Anti-pattern）

- **Anti-pattern**: 規約のテンプレートに値域を `A | B | C` と並べて書く。→ **Pattern**: テンプレートには実値を1つだけ書き、値域は表かコメントで示す。**未編集コピーが合法な値として通る経路を塞ぐ。**
- **Anti-pattern**: 「導入日より前は対象外」のように、**配布物の外（git 履歴）を参照しないと計算できない境界**を規約に書く。→ **Pattern**: 境界の値を規約の中に直接書く。self-complete でない規約は、配られた先で実行できない。
