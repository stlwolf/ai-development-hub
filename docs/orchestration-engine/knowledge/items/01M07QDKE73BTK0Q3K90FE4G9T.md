**走査の健全性を対照で確かめるとき、対照は走査パターンの外から選ぶ。** 同じパターンから選んだ対照は、そのパターンが持つ盲点をそのまま共有する。

#340 で踏んだ。`so-compare.sh` の切り詰め欠陥と同型の箇所が repo に他にあるかを調べ、`head -c` と `${var:0:N}` の2パターンで走査して「無防備なのは1箇所だけ」と結論した。**計測器の健全性は確かめていた** — 既知の2箇所（欠陥そのものと、既に手当て済みの `session-name.sh:106`）が両方ヒットすることを対照にした。

**その2箇所はどちらも `head -c` で書かれている。** つまり対照は走査パターンに合致することが最初から分かっているものだった。**この検査は「パターンが動くこと」しか示さず、「パターンの外に対象が無いこと」は何も示さない。** 実際、設計SO のレーンに促されて `cut -c` を足したら `notify.sh:86` が出た。同型の無防備な箇所は1箇所ではなく2箇所だった。

「0 件・緑を不在と読むな」の一段先である。**0 件ではなく「N 件見つかった」でも同じ穴が開く** — 見つかった件数が0でないことは、見落ちが0であることの証拠にならない。しかも対照を通してあるため、記録は「計測器の健全性を確認済み」と読める形で残る。

次にどう行動を変えるか。(1) **網羅を主張するなら、対照を走査パターンの外から1つ選ぶ**（別の書き方で同じことをしている箇所を1つ思い出して、それが引っかかるかを見る）。思い出せないなら、それは網羅の主張が根拠を持てない合図である。(2) **パターンを増やす方向に1手かける** — 同じ目的を達する別の書き方を列挙してから走査する（切り詰めなら `head -c` / `cut -c` / `${var:0:N}` / `awk substr` / `perl substr`）。(3) 報告では「走査したパターン」と「その結果」を分けて書き、**網羅の主張はパターンの列挙に対してのみ行う**（「repo に他に無い」ではなく「この5パターンでは他に無い」）。
