# リサーチ系スキルの根拠リンク・検証ステータス規律（TIL×AI記事より）

元記事は個人 TIL（Today I Learned）の AI 活用法だが、本ノートの主眼は **記事のパターンを自分のリサーチ系メタスキル（`research-intake` / `oss-research-session`）の補強に転用すること**。当初の「知識ベース応用」観点ではなく、「リサーチのピックアップ／深掘りスキルそのものをどう強化するか」というレンズで再マッピングした結果を記録する。

## 1. 記事情報と要約

- **タイトル**: AIにメンテを任せて、人間は理解に集中する。新時代のTIL（Today I Learned）活用法
- **URL**: https://techracho.bpsinc.jp/yosuke2/2026_05_29/158232
- **著者/組織**: yosuke2 / BPS株式会社（TechRacho）
- **公開日**: 2026-05-29
- **種別**: ブログ記事

TIL（その日学んだことの Git/Markdown 記録）は有用だが、記録量が増えるとファイル分割・ディレクトリ分類・相互リンクといったメンテナンスコストが重くなる。著者はここに Agent Skill（自作「TILスキル」）を当て、「○○についてtilスキルで教科書を作って」の一声でディレクトリ整理・ファイル分割・mermaid図・相互リンク・参照リンク付与までを自動化する構図を提案。人間は「正確性の担保」と「読んで理解すること」に集中する。ハルシネーション対策として、(a) 自分の気づきを文章化し AI に整形させる、(b) 一次情報を参照させ根拠リンクを貼らせる、(c) 重要点のみ自分で検索確認（部分受容）の3手を挙げ、「成果を出力するコーディング」と「知識を入力するTIL」を同じ AI 活用形式の両輪と位置づける。

## 2. 本質的パターンと詳細

| # | パターン名 | 本質 | 種別 |
|---|-----------|------|------|
| 1 | メンテ/理解の責務分割 | 知識ベースの「分類・分割・整形・相互リンク」はAI、「正確性の担保・理解」は人間。両者を明示的に分ける | 設計原則 |
| 2 | 知識キュレーション Skill | 「○○についてまとめて」の一声で、ファイル分割・ディレクトリ整理・mermaid図・相互リンク・根拠リンク付与を自動実行する Agent Skill | ワークフロー |
| 3 | ハルシネーションの段階的制御 | 一次情報参照+根拠リンク必須 / 自分の気づきを起点にAIは整形のみ / 重要点だけ人手検証（=確実性のトレードオフを意図的に選ぶ） | 評価手法 |
| 4 | 対話の教科書化（closure 蓄積） | 「今までの対話をまとめて教科書を作って」で、セッションの生対話を構造化知識へ昇格させる | ワークフロー |

### 各パターンの詳細

- **パターン1（責務分割）**: 記事の核心。AI が得意な機械的整備（分類・分割・整形・リンク維持）と、人間が担うべき正確性保証・理解を分離する。「AI に生成させるだけでは意味がない」「ちゃんと読んで理解することは楽にならない」と明記。本リポの `research-intake` が既に Gate A/B でこの構図を体現している点と接続する。
- **パターン2（知識キュレーション Skill）**: TIL スキルは markdown 出力・必要に応じた mermaid 図・トピック別ファイル分割・既存内容確認とディレクトリ整理・参考リンクと根拠の記載を一括で行う。「相互リンクの自動維持」が肝で、これは本リポの `ideas/connections.md`（凍結スナップショットの相互リンクを手動集約するファイル）の維持作業と構造同型。
- **パターン3（ハルシネーション制御）**: 3手の段階的対策が具体的。(a) 人間の気づきを起点に AI は整形のみ、(b) 一次情報を参照させ根拠リンクを貼らせる、(c) 重要点のみ人手検証し残りは部分受容を明示。**「全部は検証しない、重要点だけ検証して残りは部分受容を明示する」**という確実性トレードオフの言語化が、本ノートで最も転用価値が高い。推測比率/確実性モデル（`ideas/20260218`）の操作変数に対応する。
- **パターン4（対話の教科書化）**: セッションの生対話を構造化知識へ昇格させる素朴な実装形。本リポの層3（生ログ）→層2（構造化ナレッジ）抽出パイプライン（既存研究で「未実装のボトルネック」とされる箇所）の一例。今回の主軸（リサーチスキル補強）からは外れるため深追いしない。

## 4. 資産マッピング（リサーチ系スキル観点で再マッピング）

当初は記事の TIL パターンを知識ベース／永続化資産にマッピングしたが、ユーザー指示により **「リサーチのピックアップ（`research-intake`）と深掘り（`oss-research-session`）スキルの拡張・補強」** という観点へ切り替えた。こちらの方が実装可能で痛みに直結する接続が得られた。

確認した現状（一次確認済み）:

- `oss-research-session` の親エージェント検証は `canonical/skills/oss-research-session/SKILL.md:82` の「先頭(frontmatter)と末尾をざっと確認」1行のみ。主張↔ソース突合の規律なし。
- `research-intake` は実装参照候補に `確認元` 列を持つが、本質抽出（Step 2）の主張には根拠リンク/検証ステータスがない。
- `ideas/` には相互リンク集約の `connections.md` があるが、`docs/research/` には存在しない（README は静的な仕様書）。
