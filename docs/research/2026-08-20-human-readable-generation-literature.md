# 生成文章の人間可読性 — 会話面の自由文を読める形にするための文献調査

## 中心の問い

AI の会話面（チャット応答）の自由文が人間に読みづらい。会話面は基本的に人間が読むためのインターフェースである（ただし「人間しか読まない」は観測ではなく設計意図 — 所見6）。フォーマット節（output-format-rule の枠）は外から順序を強制するので保たれるが、自由文には枠がなく、生成した順のまま出てくる。この読みづらさがどこから来て、何で直せるのかの証拠を集めた。

読者(b)（他モデル）の軸は `docs/research/2026-07-16-register-portability-eval.md` が実測済みで、本ノートの守備範囲ではない。本ノートは読者(c)（人間）の軸と、両者の境界線を扱う。

> メタ注記（本ノート自身への適用）: ソースの本文確認は WebFetch（取得器の要約を介する）で行った。`[verified]` は本文を取得して主張を確認したもの、`[unverified-summary]` は検索結果またはSOレーンの回答止まりのもの、`[speculation]` は本ノートの推論。本ノートは v1 公開後に純粋SO（発散型・3レーン: codex=gpt-5.6-sol / cursor=grok-4.6-high / claude=fable-5 文脈なし対照）へ投入し、崩された導出を差し替えた v2 である。反証ログの正本は `ideas/20260820/discussion-logs/`、取り下げの一覧は末尾の改訂記録にある。

## 結論

各項に検証状態を付す。

1. 読みづらさは3軸に分解する: **内容選択**（量・重複・何を出さないかの失敗）、**順序**（導出順で書かれ、読者が必要な順ではない）、**表面の癖**（記号圧縮・体言止め・対句・rule-of-three）。一番よく測れている欠陥（所見2の重複 65.7% / padding 69.1%）は内容選択の軸に属する。v1 はこれを2軸としており、測定済みの軸を落としていた [speculation・分解自体は整理]。
2. 生成側と読解側の最適は非対称である [verified・構造化形式での測定]。ただし外挿には限界が2つある: レジスタ指示（結論先出し・語彙）への税は未測定で、closed-weight モデルでは税がほぼゼロだった。会話面（closed-weight）では生成時の表示契約を先に試し、文書生成では後段の整形に置くのが、測定と待ち時間の両方に整合する [speculation・SO反証を反映]。
3. 電報体の害について、v1 の「識別子除去と構造的に同型」という導出は**取り下げる**（3レーンが独立に同じ欠陥を指摘。改訂記録参照）。現在の見立ては「**走査に最適化されたレジスタを、精読される文脈に誤適用している**」[speculation・SO由来]。記号圧縮（`→` `＝` による関係の無名化）だけは名前を潰す操作に近く、段階1実測でコストが出た層と一致する。
4. 意味の層（モデル横断で意味を運ぶ層）は自然言語が**有力な既定**である [verified・文献の3理由]。ただし「最適」の証明ではない（必要条件と最適の混同を SO が指摘）。制御自然言語（CNL）という中間層が、今回の2レーンと #263 他族SOの計3系統から独立に出ており、第三項として残す [unverified-summary]。
5. ハーネス上の未使用の制御点として output styles がある [verified・公式doc]。読みづらさの主因を RLHF の長さバイアス（preference-tuning の副作用）と置く対抗仮説が2レーンから独立に出ており、#348 の検証はこの因果仮説の判別実験を兼ねられる [speculation・SO由来]。

## 所見1: 悩みは普遍、市場の対策は editor 型に偏る

「AI っぽくて読みづらい」への対策スキルは市場に多数ある。エンジニア界に限らない。

| 名前 | 狙い | 状態 |
|---|---|---|
| De-Slop / Stop Slop / Humanizer | puffery・rule-of-three・前置き・em dash・単調構造の除去 | [unverified-summary]（検索要約のみ） |
| Anti-AI Writing Engine | 相関構文・hedge の禁止、SUCKS フレームワーク | [unverified-summary] |
| Prose Writing & Style Guide | Strunk & White を editor として強制 | [unverified-summary] |
| avoid-ai-writing | 表面の癖に加えて順序と情報密度も検査 | [verified]（SKILL.md 本文確認） |

avoid-ai-writing は順序を明示的に検査項目にしている [verified]: 段落を並べ替えても気づかれないなら接続が無い（bridge sentence を足す）、claim の前で止まる前置きを弾く、前提の言い換えだけで前進しない段落を treadmill effect として検出する。

**この偏りの説明は v1 から差し替えた。** v1 は「生成時点では結論がまだ無い（自己回帰の構造要因）」としたが、SO 3レーンが独立により強い説明を出した: **市場のスキルが後編集なのは、第三者が重みにもシステムプロンプトにも触れないという配布上の制約の帰結**である [unverified-summary・SO由来]。反例も複数ある — ハーネスのシステムプロンプト自体が生成時レジスタ指示の塊であること、plan-then-write や生成時スタイル条件付けの実務、reasoning モデルは可視応答の開始時点で thinking 内に結論を持てること（所見4の thinking-first +9.2pp はまさに生成側の組み替えによる回復）。市場観察から構造的必然を導いた v1 は選択バイアスを負っていた。

日本語圏の対策記事は逆に「体言止めや倒置を適度に使え」と勧めるものが多い [unverified-summary]。目的が違う（AI 判定の回避 vs 一読可能性）ためで、「AIっぽさ」という同じ語が別問題を指している。

## 所見2: 読みづらさの計測 — over-answering（内容選択の軸）

LLM の回答を core とそれ以外に分解して測った研究がある（HDL の QA ドメイン）[verified]:

| 指標 | LLM | 人間の専門家 |
|---|---|---|
| 重複した代替案を含む回答 | 65.7% | 4.4% |
| 余分な padding を含む回答 | 69.1% | 5.8% |

重複には multi-agent debate、padding には task-aware compression と、別問題として別の対処を当てている [verified]。ドメイン限定のため数値の一般化は不可。

この測定が属するのは順序でも表面の癖でもなく、**内容選択（量・重複）という独立の軸**である。読みづらさの体感のかなりの部分が padding 由来である可能性は、この軸を立てないと対処先を持たない。

## 所見3: 順序の先行技術は AI の外にある

結論を最初の一文に置く BLUF（米陸軍 AR 25-50、1988）と Minto の Pyramid Principle が、読み手の負荷を下げる目的で順序を規定した先行技術 [unverified-summary]。さらに古い先行として、逆ピラミッド（結論先出しの報道文体）と telegraphese（電報体）が**同じ電信から生まれた**という史実の指摘が SO から出た [unverified-summary・SO由来]。圧縮と結論先出しは対立物ではなく同根であり、「電報体 vs 読みやすさ」という対置自体が歴史的には粗い。

## 所見4: 生成と読解の非対称（format tax）

生成中に構造化形式を課すと推論精度が落ちる。The Format Tax の測定 [verified]:

| 測定 | 値 |
|---|---|
| open-weight モデルの平均劣化 | -3.9pp |
| MATH-500 の形式平均 | -9.9pp |
| LaTeX 指定時の文章品質 | -7〜-18.6pp |
| プロンプト指示だけで発生した割合（分母=有意な劣化39件） | 92% |
| decoder 制約が追加で足す劣化 | -1.6pp |
| 自由生成→後整形（2ターン）の回復 | +6.8pp |
| 思考を先に走らせる方式の回復 | +9.2pp |
| closed-weight モデル（Claude 等）の劣化 | ほぼゼロか正 |

帰結（v2 で二分した）:

- **文書生成**（時間の制約が緩い・機械契約が要る）: 生成を縛らず後段に整形・検証層を置くのが安い [speculation]。
- **会話面**（closed-weight・ライブ）: 測定上は税がほぼゼロのモデルで悩みが起きているので、「生成時指示は高くつく」は当てはまらない。後編集は待ち時間の二パスにもなる。**生成時の表示契約（結論を先に・導出は畳む・案を増やさない）を先に試すべき** [speculation・SO反証を反映]。
- 測定対象は JSON や LaTeX などの構造化形式であり、レジスタ指示が同じ税を課すかは未測定のまま [speculation]。

## 所見5: 読解側は言葉に依存する — 「何を削るか」で分解し直す

読解側の測定。プログラムの構造と挙動を保ったまま識別子名だけを潰すと、LLM の理解が大きく落ちる（When Names Disappear）[verified]:

| タスク | 落ち幅 |
|---|---|
| コード要約（ClassEval・クラス単位・GPT-4o） | 87.3 → 58.7（-28.6pt） |
| 実行予測（ClassEval・DeepSeek・曖昧識別子） | 90.0% → 69.3% |
| 実行予測（LiveCodeBench・Llama・曖昧識別子） | 80.2% → 56.4% |

同論文の解釈では、識別子は理解の助けというより記憶した型を引き出す検索キーとして働いている [verified]。一方、入力形式（JSON/YAML/XML/Markdown/TOON）の違いは理解精度をあまり動かさず、動くのはトークンコストである [unverified-summary]。

**v1 の導出の取り下げ**: v1 はここから「電報体は識別子除去と構造的に同型であり、書き手最適化である」と推論したが、SO 3レーンが独立に同じ欠陥を指摘したため取り下げる。操作が逆である — names-disappear が削るのは**名前**（検索キー）で、体言止め・助詞落ちが削るのは**述語と文法の接着**であり、名前は残る。「名前が痛い」という論文自身の解釈を使うなら、名前を残す圧縮は同型ではない。

v2 の分解（何を削るかで別の欠陥として扱い、束ねない）[speculation・SO由来]:

- **名前を削る**（識別子の難読化、`→` `＝` による関係の無名化）: 測定上、読解に高くつく。段階1実測でコストが出たのもこの層（gemini の記号 decode 失敗・file:line 参照）で、整合する。
- **接着を削る**（体言止め・助詞落ち・高密度化）: 名前は残るため、names-disappear からは害を導けない。段階1でも未検証のまま（「本集合では検出されなかった」止まり）。
- **量を削らない**（padding・重複案）: 所見2の軸。削る話ではなく、出さない選択の失敗。
- **順序を読者と逆にする**: 所見3の軸。

段階1実測（電報体でも内容プローブ全○）との関係も、これで「層が違う」という v1 の逃がし方より素直になる: 名前が残っていたから復元できた、という読みが成立する。さらにアクセスパターンによる整合（明示事実の取り出し=走査タスクは通り、要約=精読タスクで落ちる）という仮説が SO から出ており、所見7で扱う。

反証条件も明確になった: **名前を保存したまま体言止め・高密度化だけを施した文書で、要約（精読）課題の精度が有意に落ちれば**、接着削りにも害があることになる。この実験は段階1ノートが再測定改善(5)として既に処方しているものと同じ [verified=段階1ノートの記載]。

トークン節約についても v1 の「買っているのは書き手の利得だけ」は言い過ぎだった: 長いセッションではトークン量は読み手のコンテキスト予算を直接消費する（段階1のプレーン化は 9.7k→17k で約75%増）[verified=段階1ノートの記載]。

## 所見6: AI 側の境界 — 意味の層は自然言語が有力な既定

会話面を for-AI に最適化すべきかの境界確定として、AI 同士の通信の証拠を置く。

- latent 通信（LatentMAS）は実在し強い: 出力トークン -70.8〜83.7%、text ベース多エージェント比で精度最大 +4.6%、4〜4.3倍速 [verified]。ただし実験は Qwen3 同一系列のみで、KV cache の層連結はアーキテクチャが違うモデル間では成立しない [verified]。
- 「なぜ自然言語か」を正面から扱った論文は、一時的な事故ではなく構造的と結論する [verified]。理由は3つ: 学習コーパスが人間言語（母語）、独立に訓練されたエージェント間の共通基盤、人間が監視・介入できること。
- エージェント集団に言語を進化させるとトークン効率は上がるが人間が読めなくなり、副題どおり oversight evasion に向かう [verified]。この事実の含意は「for-AI 最適化の理由が無い」ではなく「**逃げる圧力が実在するからこそ監視のために自然言語へ抑える**」である（SO 指摘による訂正）[unverified-summary・SO由来]。
- 実運用の protocol（A2A/MCP）は「routing する部分は schema、意味を運ぶ部分は自然言語」で線を引いている [unverified-summary]。

帰結の3層分割: transport と envelope は schema でよい（既に for AI）。意味の層は自然言語が**有力な既定**（3つの独立な理由。ただし最適性の証明ではなく、CNL 等の中間層は排除されない — SO 指摘）。モデル内部は latent が強いが同一系列限定。

会話面の位置づけは v1 から言い直す: 「人間しか読まない」は観測ではない（会話面の文は引用されて SO に載り、次ターンの文脈になり、親子間で抜粋される）。会話面が平易な散文であるべき理由は「人間専用だから」ではなく「**常に精読される面だから**」に置く方が強い [speculation・SO由来。アクセスパターン仮説は所見7]。

補足: 学習しやすい形式の研究（WRAP）は、web テキストを整った文章に書き換えてから学習させると事前学習が約3倍速くなることを示す [unverified-summary]。書き換え先に選ばれたのは機械向け形式ではなく整った人間の文章（Wikipedia 風）である点が示唆的だが、学習時の知見であり読解への直接転用は推論。

| 執筆過程 | Hayes & Flower の改稿モデル、NLG 古典（Reiter & Dale: 内容決定/構成/表層化）、スタイル転送研究（GYAFC 等） | 後編集は自己回帰の宿命ではなく人間の執筆過程の写し。editor 試作の設計根拠 |

## 改訂記録（v1 → v2）

v1 公開後、純粋SO（発散型・3レーン）の反証を受けて改訂した。ログは `ideas/20260820/discussion-logs/`。取り下げ・差し替えは次のとおり。

- **取り下げ**: 「電報体は識別子除去と構造的に同型 → 書き手最適化・利得はトークン節約だけ」（3レーン一致の反駁: 操作が逆・名前は残る・読み手の文脈予算も動く）。
- **差し替え**: editor 型偏在の説明を「自己回帰で生成時点に結論が無い」から「配布上の制約」へ（反例: ハーネスの sysprompt・reasoning モデル・thinking-first の回復）。
- **差し替え**: 「生成を縛るより後段が筋」の一律適用を、文書生成/会話面の二分へ（closed-weight で税ほぼゼロという自前の記載と矛盾していた）。
- **拡張**: 2軸分解 → 3軸（内容選択を独立軸に。所見2の測定が宙に浮いていた）。
- **弱め**: 「意味の層は自然言語が最適」→「有力な既定」（必要と最適の混同・CNL の第三項）。「会話面は人間しか読まない」→「常に精読される面」（観測でなく設計意図だった）。
- **可読性の修正**: 3レーンが一致して最負荷とした旧所見5の突合段落を箇条書きに展開。結論の各項にステータスを付与。断定→撤回の順序をやめ、限定つきの主張を一度で述べる形に直した。
