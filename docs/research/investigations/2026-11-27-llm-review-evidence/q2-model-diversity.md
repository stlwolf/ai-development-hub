# レビューアのモデル多様性は効くか（計測された証拠の調査）

> この文書は、調査役（Claude Opus 5.5）が書いたメモの原文である。取りまとめは `docs/research/investigations/2026-11-27-llm-review-multi-reviewer-evidence.md` にある。この文書の中の `verified` は調査役の申告で、取りまとめた側が照らしたものではない。数字は、使う前に原典で確かめる。

- 調査日: 2026-11-27
- 問い: ソフトウェアのレビュー（コードレビュー、バグ発見、計画や設計の批評）で、別ベンダー（別のモデルファミリー）のレビューアは、同じファミリーのレビューアが見落とす問題を見つけるか。それは「同じモデルに新しいコンテキストを与えて読ませる」こととどう比べられるか。
- 方法: WebSearch（必要に応じて extended）で探し、一次資料（arXiv の abstract と HTML 本文、Zenodo の PDF）を開いて確認した。2026 年の資料を優先し、次に 2025 年の資料を見た。

## 証拠の印の付け方

- `[verified]` は、一次資料を開き、その数値や文が原文にあることを確かめたものに付けた。WebFetch は小さなモデルの要約を介して本文を返すため、論文本文（HTML）の数値は「原文の引用を返させる 2 回目の取得」で照合できたものだけを verified とした。arXiv の abstract ページにある短い記述は、1 回の取得でも verified とした。Zenodo の 2 本は PDF を自分で読んだ。
- `[unverified-summary]` は、一次資料を開いたが、本文の数値を要約で 1 回読んだだけで原文の字句と照合していないものに付けた。出典は付けてあるが、数値の細部は誤っている可能性がある。
- `[speculation]` は、出典が直接は支えていない、私の解釈や推測に付けた。

## 先に要点

- 2 人目のレビューアを足すと見つかる問題が増える、という結果は複数の研究で一貫している。ただし「2 人目が別ベンダーであること」そのものの効果は、どの研究でもまだ分離できていない。
- 唯一の対照実験（Song, arXiv 2610.01471）では、上位の別ベンダーモデル（GPT-5.4）単独のレビューは、同じモデル（Claude Opus 4.6）を新しいセッションで動かしたレビューと F1 に有意差がなかった。組み合わせたときの網羅率 56.7% 対 42.7% の差は有意だったが、上位の別ベンダーモデルを 2 回使った場合とは有意差がなく、著者は「モデルの違い」と「レビューアの能力」が分離できていないと書いている。さらにコードのカテゴリに限ると、別ベンダーのどの条件も同じモデルの新セッションを上回らなかった。
- Stone の実務データ（Zenodo）は v2（2026-07-13）で計算をやり直した。v2 では「2 人目のレビューアで網羅率が約 47% から約 72% に上がる」とし、これは「別ベンダーであることではなく、レビューアの人数についての曲線」だと著者自身が明記している。依頼文の 33.6% から 57.1% は v1 の数値で、v2 はこの種の全体プールの計算を「露出の偏りによる人工物」として訂正している。
- 軽量なモデルを別ベンダーとして足しても効かない、弱いレビューアは強い書き手の成果を壊すこともある、という結果が複数ある。効いているのは「上位のモデルを独立に足すこと」であり、「ベンダーを変えること」だけでは足りない、というのが現時点での読みである。
- フロンティアモデルの誤りは、ベンダーが違っても強く相関するという大規模な計測がある。多様性の効果には上限があると見ておくべきである。

### 1. Song, "When Does a Second Model Help? Cross-Model Review in LLM Verification"（arXiv 2610.01471）

- 書誌: 単著。v1 は 2026-10-01、v2 は 2026-10-06。cs.CL、cs.AI、cs.SE。2603.12123 の続報である [verified] (https://arxiv.org/abs/2610.01471)。
- 設定: 生成モデルは Claude Opus 4.6 で、30 の成果物（コード、文書、発表原稿。韓国語）に 150 の誤りを埋め込んだ。10 条件で計 900 回のレビューを行った。同じモデルの条件は SR（同じセッション）、SR2（同じセッションで 2 回目）、SA（サブエージェント）、CCR（新しいセッションで成果物だけ）である。別モデルの条件は GPT-5.4（上位）、Gemini 2.5 Pro（中位）、Gemini 2.5 Flash（軽量）で、それぞれ要件を伏せた -R 版がある [verified] (https://arxiv.org/html/2610.01471v2)。
- 主な数値: F1 は XMR-GPT 32.3%、XMR-GPT-R 32.1%、XMR-GePro-R 29.0%、CCR 28.6%、SR 27.1%、XMR-Ge-R 27.0%、XMR-GePro 26.8%、XMR-Ge 24.0%、SA 23.8%、SR2 21.7% である [unverified-summary] (https://arxiv.org/html/2610.01471v2)。このうち XMR-GPT 32.3%、CCR 28.6%、XMR-Ge 24.0%、SR 27.1% は原文で照合した [verified]。
- 主要な検定: CCR に対する 9 比較を Holm 補正した主検定で、CCR と有意に違ったのは SR2 だけだった [verified]。
- 重なり（発見単位の Jaccard）: 同じモデルで別セッションの CCR 同士は 52.2%（90 ペア）、同じモデルでコンテキストが違う CCR と SR は 59.9%、CCR と XMR-GPT は 46.1%、CCR と XMR-Ge は 36.5% だった [verified]。著者は「コンテキストを変えても重なりは下がらず、モデルを変えると下がる」と述べるが、検出率や発見数の違いでも重なりは下がるので記述的な支持にとどまる、とも書いている [unverified-summary]。
- カテゴリ別: コードでは F1 が CCR 40.7%、XMR-GPT 37.2%、XMR-GPT-R 29.8% で、別モデルの条件は CCR を上回らなかった。文書では別モデルの 6 条件すべて（30.1〜42.1%）が同じモデルの 4 条件すべて（17.4〜24.5%）を上回った [verified]。カテゴリ別の推定には不確かさの幅が付いていない [unverified-summary]。
- 和集合についての注意: 著者は「不完全で同一でない 2 つの検出器なら、和集合の再現率は機械的に上がる」と書き、観測された和集合は独立を仮定した参照値より低かったと報告している。相乗効果は主張していない [verified]。
- 3 モデルの和集合（CCR + XMR-GPT-R + XMR-GePro-R）は 58.0% で、2 モデルの和集合より 1.3 ポイント高いだけだった [unverified-summary]。
- 外部チェック: ReaLMistake の公開出力で、混合ペアの和集合再現率は同じモデル 2 回より +0.5 ポイント（95% CI −1.2〜2.2）で、主結果を再現も否定もしなかった [unverified-summary]。
- 限界: 生成モデルは 1 つで、各階層のレビューアも 1 つずつなので、能力とモデルの違いが交絡している。埋め込んだ誤りは独立に注釈されておらず、照合器も人手で監査されていない。14 回の失敗セッションを除外している。データとスクリプトは著者への依頼で入手する形である [unverified-summary]。
- 引用: "does not establish equivalence"

### 2. Song, "Cross-Context Review: Improving LLM Output Quality by Separating Production and Review Sessions"（arXiv 2603.12123）

- 書誌: 単著、2026-03-12 の v1 [verified] (https://arxiv.org/html/2603.12123v1)。
- 設定: モデルは Claude Opus 4.6 だけである。API の予算不足で、計画していた Sonnet 4.6 から Claude Code の Agent ツール（親セッションと同じモデル）に切り替えた。30 の成果物に 5 つずつ、計 150 の誤りを埋め込み、4 条件 × 30 × 3 回 = 360 回のレビューを行った [unverified-summary]。
- 条件の定義: SR は生成した同じセッション（全履歴あり）、SR2 は同じセッションで 1 回目のレビューも見えた状態、SA は新しいセッションに生成時の依頼文と成果物を渡す、CCR は新しいセッションに成果物とレビュー用の依頼文だけを渡す [verified]。
- 数値: F1 は CCR 28.6%、SR 24.6%、SA 23.8%、SR2 21.7% である。SR 対 CCR は p = 0.008（d = 0.52）、SA 対 CCR は p = 0.004、SR 対 SR2 は p = 0.107 で有意でない [verified]。重大度別では Critical の検出率が CCR 40%、SR 29% で、差は重大な誤りで大きく、軽微な誤りでは消える [unverified-summary]。
- 限界: モデルが 1 つだけである。誤りは人工的に埋め込んだもの。SR と SR2 は韓国語で、CCR と SA は英語でレビューしており言語が交絡している [verified]。検定は Run 1 だけで行っている [unverified-summary]。
- 続報での変化: 2610.01471 では SR の 1 回分を出所が確認できないとして除外し、SR の F1 は 27.1% になった。そのうえで CCR と有意に違うのは SR2 だけになった [verified] (https://arxiv.org/html/2610.01471v2)。したがって「新しいセッションは同じセッションの自己レビューより良い」という結論は、同じ著者の続報では強く支えられていない。
- 引用: "CCR reached an F1 of 28.6%"

### 3. Kim ほか, "TeamBench: Evaluating Agent Coordination under Enforced Role Separation"（arXiv 2605.07073）

- 書誌: Yubin Kim（MIT、Google Research）ほか。2026-05-08 の v1 のみ。査読前の preprint [verified] (https://arxiv.org/abs/2605.07073)。
- 設定: 計画役、実行役、検証役を別コンテナに分け、OS の権限で役割を強制する。13 モデル（Anthropic、Google、OpenAI、Alibaba）。課題の多くは GitHub のバグ報告で、採点は決定的なシェルスクリプトである [unverified-summary] (https://arxiv.org/html/2605.07073v1)。
- 検証役の誤承認: 評価器で不合格の提出の 49.4% を検証役が承認した。判定が欠けた 942 件を失敗とみなすと 22.3% になる [verified]。モデル別では GPT-5.4 Mini 36.3%、Gemini-3 Flash 77.0%、Haiku 4.5 は約 60%（論文の表から計算した値）で、TeamBench-Verified の部分集合では 38.7% である [unverified-summary]。
- チームと単独: 平均の上積みは +0.5 ポイント（p = 0.20）で、Solo が弱い五分位では +15.7 ポイント、上位の五分位では Solo を下回る。検証役を外すと部分点が 5.5 ポイント上がった [verified]。
- 別プロバイダの役割混合: 25 タスク、27 構成、3 シードで、上位 3 構成は 4 ポイント以内に収まり信頼区間が重なる。最も費用対効果が良いのは GPT-5.4 Mini だけの構成である。論文は同じファミリーと混合の形式的な比較をしていない [unverified-summary]。
- 位置づけ: 検証役が「既定で合格を返す」ことの計測としては強いが、別ベンダーの検証役のほうが誤承認が少ないかどうかは答えていない。
- 引用: "The Verifier approves 49.4% of submissions that the grader rejects"

### 4. Tony Stone, "A Single LLM Is an Incomplete Code Reviewer"（Zenodo）

- v1（record 20519585、2026-06-03）: 1 つの組織の実務のコードレビュー記録から、人が照合した答えのある 18 の成果物と 154 件の確定指摘を使った。5 プロバイダ 8 モデル版（Opus 4.6/4.7/4.8、GPT-5.4/5.5、Gemini 3.1、Kimi k2.6、Qwen3.7-max）を比べている [verified] (https://zenodo.org/records/20519585)。
  - 単独の再現率の上限は約 64% で、154 件のうち 56.5%（87 件）は 1 モデルだけが見つけた。ペアごとの Jaccard の中央値は約 0.37 である [verified]。
  - プロバイダ数ごとの期待網羅率（Table 3）は 33.6%、57.1%、74.6%、88.7%、100.0% である [verified]。依頼文の数値はこの表と一致する。
  - 引用: "the largest marginal gain from adding the second, different-provider model (33.6% → 57.1%)"
- v2（record 21328807、2026-07-13、v1 を置き換えると明記）: 33 成果物、294 件、8 プロバイダ 15 モデル版に広げた [verified] (https://zenodo.org/records/21328807)。
  - 網羅率は成果物ごとに、その成果物を実際にレビューしたモデルだけで計算し直した。1 人 47.2% [42, 53]、2 人 72.3% [68, 77]、3 人 89.4%、4 人 97.3%、5 人 100.0% である [verified]。
  - 著者は、旧版の全体プールの計算は「レビューしていない成果物の欠陥まで見落としとして数えた露出の人工物」だったと訂正している。ただし v2 が旧版の値として書く「約 22%」は v1 の 33.6% と一致しない。どの版を指すのかは本文からは分からない [verified]。数値の食い違いの理由は不明である [speculation]。
  - 著者は、この曲線はレビューアの人数についてのもので、別プロバイダが同じプロバイダより役立つかどうかはこのデータでは言えないと明記している。推奨も「別プロバイダは妥当な既定だが、再実行や同じプロバイダの別モデルに勝つとは示せない」に弱めている [verified]。
  - 1 モデルだけが見つけた割合は 56.8%（167/294）で、乱数で並べ替えた帰無分布（平均 35.3%）より 9.7 標準偏差高い。一方で、Jaccard の中央値 0.29 は、各レビューアが約 45% を独立に見つけるだけでも出る値（p/(2−p)）に近く、プロバイダ固有の盲点の証拠にはならないと著者は書いている [verified]。
  - 引用: "this is a curve over reviewer count, not provider identity"
- 共通の限界: 答え合わせの鍵は Claude が下書きし、Claude 系もレビューアに含まれる（利益相反）。同じモデルの同一入力での再実行がないため、「同じモデルに新しいコンテキストで読ませる」との比較はできない。Anthropic 以外のモデルは別の道具で動かし、版は日付から推定している。単一組織、単一コードベースである [verified]。

## Part 2: 追加の証拠

### a) モデルファミリー間の誤りの相関、発見の重なり

- Kim ほか, "Correlated Errors in Large Language Models"（ICML 2025, arXiv 2506.07962）: 350 を超える LLM を HELM（71 モデル）、HuggingFace Open LLM Leaderboard（349 モデル）、履歴書の選考課題で比べた。HELM では両方が誤ったとき 60% の確率で同じ誤答を選ぶ。回帰では「同じ会社」が誤りの一致率を +0.066（HuggingFace）、+0.022（HELM）押し上げ、「同じアーキテクチャ」は +0.076（HuggingFace）だった [verified] (https://arxiv.org/html/2506.07962v1)。正確なモデルほど、とくに両方が正確なほど誤りが相関し、それはアーキテクチャやプロバイダが違っても成り立つ [verified] (https://arxiv.org/abs/2506.07962)。引用: "using multiple different models is not a panacea"
  - 読み方: 同じ会社であることの上乗せは数ポイントで、一致率のほとんどは会社の違いと関係なく共有されている [speculation]。
- Hossain ほか, "Agreement Overstates Evidence: Error Dependence in LLM Judge Consensus"（arXiv 2609.22512, 2026-09-18）: RewardBench v2 などで審査役の誤りの相関を測った。別プロバイダのフロンティア審査役（GPT-5.6-sol、Claude Opus 5、Grok 4.5）のペア平均の誤り相関は 0.42 で、Gemini 同士の 0.40 とほぼ同じだった。能力の階層を混ぜる（フロンティアにオープンウェイトを足す）と実効的な独立審査役の数は 1.88 から 3.83 に増えたが、多数決の正答率はフロンティアだけの 0.933 に対し混合は 0.915 だった [verified] (https://arxiv.org/html/2609.22512v1)。GPT、Claude、Grok の 3 審査役の実効数は 1.41 である [unverified-summary]。引用: "Judges from different providers are about as correlated as judges from the same provider."
- Goel ほか, "Great Models Think Alike and this Undermines AI Oversight"（arXiv 2502.04313）: 誤りの重なりに基づく類似度 CAPA を提案し、能力が上がるほどモデルの誤りが似てくると報告した [verified] (https://arxiv.org/abs/2502.04313)。本文の数値は確認していない。
- Song 2610.01471 の重なり: 同じモデルの別セッション同士 52.2%、別モデルとの組み合わせ 36.5〜46.1% で、モデルを変えたほうが重なりは低い。ただし著者はこれを検定ではなく記述としている [verified] (https://arxiv.org/html/2610.01471v2)。
- Stone v2 の重なり: Jaccard の中央値 0.29。ただし前述のとおり、独立なレビューアでも出る水準であり、プロバイダ固有の盲点の証拠ではないと著者が書いている [verified] (https://zenodo.org/records/21328807)。
- Martian ほか, "CodeReviewBench"（arXiv 2611.26942, 2026-11-20）: 道具立て（ベクトル検索、tree-sitter、lint、11 のサブエージェント）を固定した最小のレビューエージェントを 3 つのモデル構成（OpenAI、混合、Claude）で動かすと、3 つとも同じ 48 件の正解指摘を見つけたが中身は違い、PR ごとの件数は 50 件中 34 件で違った [verified] (https://arxiv.org/html/2611.26942)。総量は同じで、見つける部分集合が違うという形である。
- Kumar ほか, "Bigger Isn't Always Better"（arXiv 2606.15689）: 5 モデル（Sonnet 4.6、Haiku 4.5、GPT-5.4 mini、Minimax M2.7、GLM-5 Turbo）を 150 サンプルで比べた。150 件中 19 件はどのモデルも何も見つけず、55 件は全モデルが何かを見つけた。Haiku に他モデルの発見を足した和集合は F1 が 0.365 から 0.304〜0.333 に下がり、再現率まで下がっている [unverified-summary] (https://arxiv.org/html/2606.15689v1)。和集合で再現率が下がるのは計算上おかしく、論文は説明していないので、弱い証拠として扱う [speculation]。審査役は Claude Opus で、有意性の検定はない [unverified-summary]。
- Ding, "When LLMs Agree, Are They Right?"（arXiv 2607.08065）: 一致は正しさの弱い予測因子にとどまり、最も一貫したフロンティアモデルは GPQA の項目の 77% で高い一致を示し、そのうち 48% が誤りだった。自信のある誤りはプロバイダをまたいで繰り返されると報告している（探索的な確認）[verified] (https://arxiv.org/abs/2607.08065)。

### b) 同じモデルによる自己レビューの偏り（自己選好）と、別ファミリーで消えるか

- Panickssery ほか, "LLM Evaluators Recognize and Favor Their Own Generations"（arXiv 2404.13076, 2024）: モデルは自分の出力をある程度見分けられ、見分ける能力と自己選好の強さには線形の相関がある [verified] (https://arxiv.org/abs/2404.13076)。
- Spiliopoulou ほか, "Play Favorites"（arXiv 2508.06709, 2025）: 9 つの審査役で、GPT-4o と Claude 3.5 Sonnet が自分の出力にも、同じファミリーの他モデルの出力にも高い点を付けた [verified] (https://arxiv.org/abs/2508.06709)。効果量は本文を開いておらず確認していない。
- Awuni ほか, "Who Judges Matters"（arXiv 2609.17857, 2026-09-15）: 審査役が自分の出力を採点しない設計で、同じファミリーへの上乗せを測った。全体で 0.067（95% CI 0.053〜0.084、並べ替え検定 p = 0.0002）、Gemma 0.084、Llama 0.034 である。パネルに候補と同じファミリーの審査役が 1 人入ると、ペア比較の結果の 18.5% が変わる [verified] (https://arxiv.org/html/2609.17857)。ただし Qwen を審査役から外すと全体の値は 0.037 に下がり、効果は 1 ファミリーに偏っている。コードや数学のような検証可能な領域は対象外である [verified]。引用: "We do not test closed-weight judges or verifiable domains such as code and mathematics"
- Chen ほか, "Do LLM Evaluators Prefer Themselves for a Reason?"（arXiv 2504.03846）: コード生成を含む検証可能な課題で調べると、強いモデルの自己選好の多くは実際に出力が良いことによる正当なものだった。ただし審査役自身が生成で間違えた問題では有害な自己選好が残り、強いモデルほど強い。長い思考を先に出させると減る [verified] (https://arxiv.org/abs/2504.03846)。
- Guey と Bougault, "Self-Preference Is Weak or Absent in Verifiable Instruction-Following Revision"（arXiv 2606.20093）: IFEval の修正課題で、実際の書き手が自分の下書きへの正しい修正を却下した率は 15.3%、別のモデルは 20.4% で、差は −5.1 ポイント（95% CI −12.9〜+2.7）だった。自己選好は検出されなかった [verified] (https://arxiv.org/html/2606.20093v1)。対象は中位の 4 モデル（gpt-4o-mini、claude-3.5-haiku、gemini-2.5-flash-lite、llama-3.3-70b-instruct）だけで、13 ポイント未満の効果は否定できない。比較役が別ファミリーなので、ファミリーごとの厳しさの違いが交絡している [verified]。引用: "Effects smaller than ∼13 pp cannot be excluded at this sample size."
- Tsui, "Self-Correction Bench"（arXiv 2507.02778, COLM 2026）: 同じ誤りを「ユーザーが書いたもの」として見せると直せるのに、「自分が書いたもの」として見せると直せない割合が、14 のオープンな非推論モデルで平均 64.5% あった。「Wait」を付け足すだけでこの盲点は 89.3% 減った [verified] (https://arxiv.org/abs/2507.02778)。これはモデルファミリーの違いではなく、誰の出力として見せるかという文脈の問題である。
- Xiang ほか, "Cross-Model LLM Code Review: Should you use Claude to review Codex or vice versa?"（arXiv 2607.21656, Agentic SE @ KDD'26）: LiveCodeBench の 116 問で、Claude Opus 4.7 と GPT-5.5（Codex CLI）を書き手とレビューアに組み合わせた。レビューアはテストを実行できない。合格率は Claude 単独 91.4%、Claude の自己レビュー 91.4%（変化なし）、Codex 単独 71.6%、Codex の自己レビュー 84.5%（p_BH = .022）、Claude が Codex をレビュー 89.7%（p_BH = .001）、Codex が Claude をレビュー 82.8%（p_BH = .046 で悪化）だった [verified] (https://arxiv.org/abs/2607.21656)。修正と破壊の件数は、Claude が Codex を見ると 26 件修正・5 件破壊、Codex の自己レビューは 21 件修正・6 件破壊、Codex が Claude を見ると 3 件修正・13 件破壊である。2 つの向きの直接比較は有意でない（p_BH = .1444）[unverified-summary] (https://arxiv.org/html/2607.21656v1)。
  - 読み方: 弱いほうの書き手には、自己レビューでも大きな改善があり、別モデルの上乗せはそれより小さい。強いほうの書き手には、自己レビューは効かず、弱い別モデルのレビューは害になった [speculation]。
- 別ファミリーで偏りが消えるか: コードレビューで、自分の PR を自分でレビューする条件と別ファミリーがレビューする条件を、正解つきで直接比べた研究は見つからなかった。家族単位の偏り（Play Favorites、Who Judges Matters）と類似したモデルへの偏り（Goel ほか）が報告されているので、別ファミリーに替えれば自己選好と同族選好は構造上なくなるが、能力が近いフロンティアモデル同士の類似性による偏りは残ると考えられる [speculation]。

### c) 効果はモデルの多様性から来るのか、依頼文・コンテキスト・道具の違いから来るのか

- Song 2610.01471: 上位の別ベンダー条件（GPT-5.4）は Codex CLI 経由で動き、作業ディレクトリのファイルを読めた。同じモデルの条件は Claude Code の Agent ツールで動いている。道具立ての違いが交絡しており、著者は「モデルの違いとレビューアの能力は分離できていない」と結論している [verified] (https://arxiv.org/html/2610.01471v2)。
- Song 2603.12123: モデルを変えずに、新しいセッションにすることと生成時の依頼文を伏せることだけで F1 が動いた（CCR 28.6% 対 SA 23.8%、p = 0.004）[verified] (https://arxiv.org/html/2603.12123v1)。コンテキストの設計だけで効果が出うることを示す。
- Stone v2: プロバイダごとに使った道具が違い、版の特定も日付からの推定である。著者は、別プロバイダが再実行や同じプロバイダの別モデルより役立つかは識別できないと書いている [verified] (https://zenodo.org/records/21328807)。
- CodeReviewBench（arXiv 2611.26942）: 道具立てを固定すると 3 つのモデル構成の再現率は同じだった。著者は「固定した検索の仕組みが見つけられる範囲を決め、モデルはその中で何を拾うかを決める」という仮説を出している。単一パスの別システムでは 4 ファミリー間で再現率が 15.4 ポイント、精度が 29.8 ポイント開き、Kodus のベンチマークでは 8 ファミリー間の差が約 3 ポイントだった。モデル選択の効き方は構成によって違う [verified] (https://arxiv.org/html/2611.26942)。この最小エージェントの F1 は約 0.22 で、市販ツールの中央値約 0.44 を大きく下回っており、作り込みの差がモデルの差より大きい可能性を示す [unverified-summary]。引用: "this experiment isolates model contribution, not harness quality."
- Kumar, "SWE-PRBench"（arXiv 2603.26130）: 8 モデルで、差分と要約だけの構成 A に、実行時の文脈（B）やテストのシグネチャ（C）を足すと、ほとんどのモデルで得点が下がった。とくに文脈が必要な指摘の検出が Sonnet 4.6 で 0.22 から 0.10 に落ちた [unverified-summary] (https://arxiv.org/html/2603.26130v1)。コンテキストを足せば良くなるとは限らない。
- Qiu と Gill, "Adversarial Review"（arXiv 2608.18167, ICML 2026 DL4C ワークショップ）: すべてのエージェントを Claude Sonnet 4.5 で動かし、レビュー役と批評役の構成だけを変えた。SWE-PRBench の F1 は単一レビューア 0.495、素朴な構成 0.457、意見の相違を明示させる構成 0.533 で、LiveCodeBench の合格率は 77% から 87% になった [verified] (https://arxiv.org/html/2608.18167v1)。有意性の検定はない [unverified-summary]。同じモデルのまま役割と依頼文の設計で数ポイント動くことを示す。引用: "We use Claude Sonnet 4.5 Medium Reasoning for all subsequent agent and subagent calls for all benchmarks."
- Yang ほか, "Understanding Agent Scaling in LLM-Based Multi-Agent Systems via Diversity"（arXiv 2602.03794）: 投票と討論で、多様な 2 エージェントが同質な 16 エージェントと同等以上になった [verified] (https://arxiv.org/abs/2602.03794v1)。ARC ではモデルの混合（+1.7〜+2.5 ポイント）のほうが人格づけの依頼文（−0.7〜+0.2 ポイント）より効き、両方の組み合わせが最大だった [unverified-summary] (https://arxiv.org/html/2602.03794v1)。ただし 7〜8B のオープンモデルだけで、コードの課題はない。
- Kim, "tap"（arXiv 2606.14445）: 実運用の記録で、異種モデルのペアのレビューは 262 件中 183 件（69.8%）、同種のペアは 113 件中 60 件（53.1%）で欠陥や修正要求を記録した [verified] (https://arxiv.org/abs/2606.14445)。観察研究で、著者自身もモデルと実行環境の組み合わせの効果としており、モデルの効果だけは取り出せない [unverified-summary]。
- 道具立ての効果の大きさ（レビューではなくコーディングエージェント）: 同じモデルで文脈の扱いだけを変えると、狭いコンテキスト窓の SWE-bench Verified 169 問で、テストを通す割合の平均が 28% から 49% に上がった（Lewis, arXiv 2608.26218）[verified] (https://arxiv.org/abs/2608.26218)。一方で、ベンダー純正の道具と中立の道具の差は平均で ±1 ポイント程度だった（Arjmandi, arXiv 2609.11987）[unverified-summary] (https://arxiv.org/abs/2609.11987)。
- まとめ: モデルの多様性と、依頼文・コンテキスト・道具の違いを要因として分けた実験（同じ道具で、同じモデルの再実行、同じベンダーの別モデル、別ベンダーのモデルを比べる設計）は、コードレビューについては見つからなかった。

### d) 多様性が効かない、または上位モデルでしか効かないという証拠

- Song 2610.01471: 軽量な別ベンダーモデル（Gemini 2.5 Flash）は F1 24.0% で、同じモデルの自己レビュー 27.1% を上回らなかった。コードのカテゴリでは、別モデルのどの条件も同じモデルの新セッション（40.7%）を上回らなかった。上位の別ベンダーモデルを 2 回使った場合と混合ペアの差は有意でなかった [verified] (https://arxiv.org/html/2610.01471v2)。3 つ目のモデルを足しても +1.3 ポイントだった [unverified-summary] (https://arxiv.org/html/2610.01471v2)。
- Li ほか, "Rethinking Mixture-of-Agents"（arXiv 2502.00674, TMLR 2026）: 最上位の 1 モデルの出力だけを集約する Self-MoA が、異なるモデルを混ぜる MoA を AlpacaEval 2.0 で 6.6%、MMLU、CRUX、MATH の平均で 3.8% 上回った。混ぜると平均品質が下がることが原因とされる [verified] (https://arxiv.org/abs/2502.00674)。
- Kim ほか 2506.07962: 正確なモデルほど誤りが相関し、複数のモデルを使うことは万能ではない [verified]。
- Hossain ほか 2609.22512: 別プロバイダのフロンティア審査役は、同じプロバイダの審査役とほぼ同じ程度に誤りが相関していた [verified]。
- Xiang ほか 2607.21656: 強い書き手（Claude Opus 4.7）の成果を弱いレビューア（GPT-5.5、この課題では単独 71.6%）が見ると、合格率は 91.4% から 82.8% に下がった [verified]。
- TeamBench 2605.07073: 単独で強いモデルでは、チームにすると伸びないか下がった [verified]。
- Stone v2: 新しく加えた 2 プロバイダ（grok-4.5、fugu-ultra、各 12 件）は独自の発見が 0 件で、既存のレビューアの確認にとどまった。小さい標本での観察である [verified] (https://zenodo.org/records/21328807)。
- Ganesh ほか, "Homogenization in Multi-Agent Systems"（arXiv 2610.09824）: コード生成などで、複数モデルを混ぜたマルチエージェントでも同質化のリスクは減らなかったと要約で述べている [verified] (https://arxiv.org/abs/2610.09824)。本文の数値は確認していない。
- 反対方向の証拠: Zhang ほか, "Stop Overvaluing Multi-Agent Debate"（arXiv 2502.08788）は、討論型の手法は CoT や Self-Consistency をしばしば上回らないとしたうえで、モデルの異質性は討論の手法を一貫して改善すると述べている [verified] (https://arxiv.org/abs/2502.08788)。効果量は本文を開いておらず確認していない。

## 判断に効く読み（解釈）

以下は上の証拠からの私の読みであり、すべて [speculation] である。

1. 「2 人目の独立したレビューアを足す」ことの効果は確かで、大きさも 14〜25 ポイントと意味がある。一方で「その 2 人目は別ベンダーでなければならない」ことは示されていない。上位の別ベンダーモデルを 2 回使った場合と混合ペアは区別できず（Song）、実務データの著者もプロバイダの効果を識別できないと認めている（Stone v2）。
2. 効くのは能力である。軽量モデルや弱いモデルは、別ベンダーであっても足しにならないか、むしろ害になる。上位モデル同士なら、別ベンダーを足すことで発見の重なりは下がり、網羅率は上がる傾向がある。
3. 新しいコンテキスト（成果物だけを渡す新セッション）は安価で、同じセッションの自己レビューより悪くない。ただし、自己レビューより明確に良いという結果は、同じ著者の続報で弱まった。生成時の依頼文を渡すと悪くなるという結果は 1 研究のみである。
4. コードに限ると、別ベンダーの上乗せは文書より小さいか、見えない（Song のカテゴリ別）。設計や文書の批評のほうが、別モデルの利得が出やすい可能性がある。
5. フロンティアモデルの誤りは、ベンダーをまたいで相関する。別ベンダーを足しても「全員が見落とす」部分は残り、人による確認やテストのような機械的な関門は代わりにならない。
6. 実務上は、上位の別ベンダーモデルを、互いの出力を見せずに独立に走らせ、その結果を元の成果物（ソース）に照らして確かめる、という形が、今ある証拠と矛盾しない。ただし、同じ費用で「同じ上位モデルの新セッションをもう 1 回」走らせる案との差は、コードレビューでは測られていない。

## 見つからなかったもの、開けなかったもの

- 見つからなかったもの
  - 実際のコードレビュー（実 PR）で、同じ道具立てのまま「同じモデルの新セッションの再実行」「同じベンダーの別モデル」「別ベンダーの同等能力モデル」を比べ、モデルと道具を要因として分けた実験。
  - 自分の書いた PR を自分でレビューさせる条件と、別ファミリーにレビューさせる条件を、正解つきで比べたコードレビューの自己選好の計測。
  - 別ベンダーのパネルにしたときの誤検出（偽陽性）の増え方を、再現率と同時に実 PR で測った研究（Bigger Isn't Always Better は和集合の数値に不整合があり、根拠として弱い）。
  - 事前登録された、複数組織にまたがる追試。Stone 自身が今後の実験として提案している段階である。
- 開けなかった、または全文を読んでいないもの
