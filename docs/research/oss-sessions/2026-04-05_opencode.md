## opencode 調査結果

### 基本情報

- **リポジトリ:** [anomalyco/opencode](https://github.com/anomalyco/opencode)
- **言語:** TypeScript（Bun ランタイム）
- **最終更新:** 2026-04-04（v1.3.14）
- **規模:** 137K stars / 15K forks / 536 watchers / open issues 6,179
- **ライセンス:** MIT
- **リリースケイデンス:** 非常に高頻度。v1.3.5〜v1.3.14 が 2026-03-28〜04-04 の約1週間で10リリース
- **作成日:** 2025-04-30
- **一言で:** プロバイダ非依存のオープンソースAIコーディングエージェント。TUI/デスクトップ/Web UIの3形態を持つ

### これは何か・何を解決するのか

OpenCodeは、Claude Codeに対するオープンソースの対抗馬として位置づけられるターミナルベースのAIコーディングエージェントである。SST（Serverless Stack）の開発チーム、現在はAnomaly社が開発している。

**解決する問題:**

1. **ベンダーロックイン**: Claude Code は Anthropic モデル専用。OpenCode は 75+ のモデルプロバイダ（Claude, OpenAI, Gemini, Grok, ローカルモデル等）を横断的に利用可能
2. **クローズドソースの制約**: Claude Code は非公開。OpenCode は MIT ライセンスで完全公開
3. **インターフェースの柔軟性**: TUI のみでなく、クライアント/サーバーアーキテクチャにより Web UI、デスクトップアプリ（Tauri）、モバイルクライアント、IDE 統合（Zed ACP）からの利用が可能

**ターゲットユーザー:**
- ターミナル中心のワークフローを好む開発者（neovim ユーザーを公言）
- 複数のLLMプロバイダを使い分けたい開発者
- セルフホストやエアギャップ環境でAIコーディングを行いたいチーム

### 設計思想・アーキテクチャ

#### コアアーキテクチャ: クライアント/サーバー分離

OpenCodeの最も特徴的な設計判断は、AIエージェントのコアロジックをサーバーとして分離し、複数のクライアント（TUI, Web, Desktop, Mobile）から接続可能にした点である。

```
opencode serve              # ヘッドレスAPIサーバー起動（デフォルト port 4096）
opencode web                # サーバー + Web UI
opencode attach <url>       # 既存サーバーに TUI を接続
opencode acp                # Agent Client Protocol (Zed統合用)
```

#### モノレポ構成（Bun workspaces）

```
packages/
├── opencode/        # コア: ビジネスロジック、サーバー、TUI（SolidJS + opentui）
├── app/             # 共有 Web UI コンポーネント（SolidJS）
├── desktop/         # Tauri デスクトップアプリ（packages/app をラップ）
├── plugin/          # @opencode-ai/plugin - プラグインSDK
├── sdk/js/          # @opencode-ai/sdk - JavaScript SDK
├── console/         # opencode.ai の Web コンソール（SaaS管理画面）
├── web/             # ランディングページ
├── slack/           # Slack 統合
└── storybook/       # UI コンポーネントカタログ
```

#### 技術スタック

- **ランタイム:** Bun 1.3+
- **フレームワーク:** Effect（関数型TypeScript）を全面採用。`Layer`, `Effect`, `ServiceMap` パターンでDI・エラーハンドリング
- **TUI:** SolidJS + [opentui](https://github.com/sst/opentui)（SST 自製のターミナルUI フレームワーク）
- **Web/Desktop UI:** SolidJS + Tailwind CSS
- **Desktop:** Tauri（Rust ベース）
- **DB:** Drizzle ORM（SQLite）
- **AI SDK:** Vercel AI SDK（`ai` パッケージ）を通じて 20+ プロバイダ SDK を統合
- **プロトコル:** MCP（Model Context Protocol）、ACP（Agent Client Protocol）

#### キーコンセプト

- **Session**: 会話セッション。メッセージ履歴、コンパクション（要約による圧縮）、リバート機能を持つ
- **Agent**: build（デフォルト、フルアクセス）、plan（リードオンリー）、general（サブエージェント）の3種。カスタムエージェント定義可能
- **Tool**: bash, read, edit, write, glob, grep, lsp, websearch, webfetch, task（サブエージェント起動）等
- **Plugin**: JS/TS モジュール。Hooks パターンでイベントをフック。npm / ローカルパスから読み込み
- **Command**: Markdown テンプレートベースのスラッシュコマンド（`.opencode/command/`）
- **Skill**: 追加スキルフォルダ
- **Permission**: ツール・ファイルパスごとの ask/allow/deny ルール

### 特徴的な点・注目ポイント

#### 1. LSP 統合によるリアルタイムフィードバックループ

OpenCode の最大の技術的差別化要素。ファイル編集後に LSP から型エラーや構文エラーを即座に取得し、LLM にフィードバックする。これにより「コード生成 → エラー放置」パターンを防止する。40+ の言語サーバーを組み込み、拡張子ベースの遅延起動を行う。

- `packages/opencode/src/lsp/index.ts` — オーケストレーション
- `packages/opencode/src/lsp/server.ts` — サーバー定義
- `packages/opencode/src/lsp/client.ts` — クライアント実装

#### 2. クライアント/サーバー分離とマルチクライアント

エージェントサーバーを独立プロセスとして起動し、HTTP APIで操作する。これにより:
- ローカルPCで起動したサーバーにモバイルからリモート接続
- Web UI と TUI を同時に接続して同じセッションを操作
- CI/CD パイプラインからヘッドレスで実行

mDNS によるローカルネットワーク内の自動発見機能も備える（`src/server/mdns.ts`）。

#### 3. Agent Client Protocol (ACP) 実装

Zed エディタ等の ACP 対応クライアントから JSON-RPC over stdio で接続可能。IDE ネイティブのエージェント統合を実現する新しいアプローチ。

- `packages/opencode/src/acp/` — 実装一式
- `packages/opencode/src/acp/README.md` — 詳細な設計文書

#### 4. Effect ベースの関数型アーキテクチャ

TypeScript の `effect` ライブラリを全面採用。`Layer`, `ServiceMap`, `Effect.gen` パターンで依存注入、エラーハンドリング、並行処理を統一的に扱う。大規模 TypeScript プロジェクトでの Effect 採用事例として注目に値する。

#### 5. モデル別プロンプトチューニング

`src/session/prompt/` に anthropic.txt, gemini.txt, gpt.txt, codex.txt, kimi.txt 等のモデルファミリー別システムプロンプトを用意。各モデルの特性に合わせたプロンプトエンジニアリングを行っている点は、マルチプロバイダ対応ツールならではのアプローチ。

### 使い方・典型的なワークフロー

#### インストール

```bash
# macOS (推奨)
brew install anomalyco/tap/opencode

# npm
npm i -g opencode-ai@latest

# ワンライナー
curl -fsSL https://opencode.ai/install | bash
```

#### 基本的な使い方

```bash
# カレントディレクトリで TUI を起動
opencode

# 特定ディレクトリで起動
opencode /path/to/project

# ヘッドレスサーバーとして起動
opencode serve --port 4096

# Web UI 付きで起動
opencode web

# 既存サーバーに TUI を接続
opencode attach http://localhost:4096
```

#### TUI 操作

- `Tab` — build / plan エージェント切り替え
- `Ctrl+P` — コマンドパレット
- `<leader>m` — モデル選択
- `<leader>a` — エージェント選択
- `<leader>t` — テーマ選択
- `@general` — サブエージェント呼び出し

#### 設定ファイル（`opencode.jsonc`）

プロジェクトルートの `.opencode/opencode.jsonc` または `opencode.json`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "opencode": { "options": {} }
  },
  "permission": {
    "edit": {
      "packages/opencode/migration/*": "deny"
    }
  },
  "mcp": {},
  "instructions": ["./AGENTS.md"],
  "agent": {
    "build": {
      "model": "anthropic/claude-sonnet-4-20250514"
    }
  }
}
```

#### コマンド定義（`.opencode/command/`）

Markdown テンプレートとして定義:

```markdown
---
description: "Generate a commit message"
agent: build
---
Review the staged changes and generate a commit message...
```

### 他ツールとの比較・ポジショニング

| 軸 | OpenCode | Claude Code | Aider | Cursor |
|----|----------|-------------|-------|--------|
| **OSS** | MIT | クローズド | Apache 2.0 | クローズド |
| **モデル** | 75+ プロバイダ | Claude のみ | 多数対応 | 多数対応 |
| **インターフェース** | TUI + Web + Desktop | TUI のみ | CLI のみ | IDE (VS Code fork) |
| **LSP 統合** | 40+ 組み込み | なし（公開情報なし） | なし | IDE 内蔵 |
| **Git 統合** | 基本的 | 基本的 | 自動コミット（強み） | IDE 内蔵 |
| **プラグイン** | JS/TS Hooks | スキル/フック | なし | 拡張機能 |
| **価格** | 無料 + API費用 / Zen | $20/月 Pro | 無料 + API費用 | $20/月 Pro |
| **クライアント/サーバー** | あり | なし | なし | なし |
| **メモリ使用** | 高（1GB+、リーク報告多数） | 低〜中 | 低 | 中 |

**ポジショニング:**
OpenCode は「Claude Code のオープンソース版」として最も直接的な競合。ただし、プロバイダ非依存・クライアント/サーバー分離・LSP統合・プラグインシステムなど、Claude Code にない独自機能を多く持つ。一方で、メモリ消費やバグの多さでは成熟度に差がある。

Aider とは CLI vs TUI/GUI の違いが大きく、Aider の git 自動コミット機能は OpenCode にはない。Cursor とはIDE vs ターミナルの根本的なアプローチの違い。

比較記事での一般的な推奨: 「IDE でのデイリーワークには Cursor、難しい問題にはターミナルエージェント（OpenCode/Claude Code）」

### 制約・注意点

1. **メモリリーク:** 長時間セッションで顕著。20+ の独立した報告があり、v1.3.x でも完全には解決していない。特に Windows と大きなコードベースで深刻
2. **Anthropic/Claude 統合の制限:** OAuth 統合は法的要請により削除済み。API キー経由での利用は可能だが、サブスクリプション認証は不可
3. **Bun 依存:** ランタイムが Bun 1.3+ 必須。Bun のエコシステム成熟度に依存
4. **TypeScript の大規模コードベース:** Go ベースのツール（初期の opencode、Aider 等）と比較してバイナリサイズ・起動時間・メモリ使用量で不利
5. **Open Issues の多さ:** 6,179 件。急速な成長に品質管理が追いついていない可能性
6. **Effect ライブラリへの全面依存:** Effect は TypeScript コミュニティではまだニッチ。コントリビュータの参入障壁になりうる
7. **商用サービス（Zen/Go/Black）との関係:** OSS プロジェクトだが、収益モデルは Zen（モデルプロキシ）等の SaaS。OSS とビジネスのバランスに注意

### 深掘り候補（コードリーディング対象）

| 対象 | パス | 理由 |
|------|------|------|
