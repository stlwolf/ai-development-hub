## rtk 調査結果

### 基本情報

- **リポジトリ:** [https://github.com/rtk-ai/rtk](https://github.com/rtk-ai/rtk)
- **言語:** Rust（公式メタデータおよび `Cargo.toml`）
- **最終更新（調査時点）:** GitHub の `pushed_at` は 2026-04-27 前後（[API: repository](https://api.github.com/repos/rtk-ai/rtk)）
- **規模（調査時点）:** Stars 約 36.6k、Forks 約 2.2k、Open issues 約 704、最新リリース **v0.37.2**（2026-04-20、[releases/latest](https://github.com/rtk-ai/rtk/releases/latest)）。`Cargo.toml` の package version は **0.37.2**（[Cargo.toml](https://raw.githubusercontent.com/rtk-ai/rtk/master/Cargo.toml)）。README の `rtk --version` 例は古いバージョン表記のままの可能性あり。
- **一言で:** 開発用 CLI の標準出力をエージェント向けに圧縮し、LLM コンテキストのトークン消費を抑える単一 Rust バイナリ型のプロキシ。

### これは何か・何を解決するのか

- **目的:** Claude Code / Cursor / Copilot / Gemini CLI などがシェル経由で得るコマンド出力に含まれる冗長な人間向け装飾・ボイラープレートを削り、推定 **60〜90%** のトークン削減を狙う（[README.md](https://raw.githubusercontent.com/rtk-ai/rtk/master/README.md)）。
- **解決する問題:** エージェントは「人間がターミナルで見るのに便利な」出力（進捗、ANSI、長い diff、成功テストの羅列など）をそのままコンテキストに取り込むとコストとウィンドウを浪費する、という問題。
- **利用者:** AI コーディングエージェント利用者（個人〜チーム）。フックで透明に挿入するか、明示的に `rtk <cmd>` を叩くか、の二層。

**注記（表現の正確性）:** GitHub の短い説明に「zero dependencies」とある一方、`Cargo.toml` には `clap`, `serde`, `rusqlite` など多数の **ビルド時依存** がある。ドキュメント上の意図は「配布物は単一バイナリで、実行時に別ランタイムを要しない」に近い（[docs/contributing/TECHNICAL.md](https://raw.githubusercontent.com/rtk-ai/rtk/master/docs/contributing/TECHNICAL.md) はオーバーヘッド `<10ms`・単一スレッドを強調）。

### 設計思想・アーキテクチャ

- **中核抽象:** 「フックがコマンド文字列だけを `rtk rewrite` に渡す → レジストリが `rtk …` へ書き換え → 実プロセス実行と出力フィルタは Rust 本体」という **透明プロキシ**。フィルタ失敗時は生出力へフォールバック、終了コードは飲み込まない方針（[TECHNICAL.md §2](https://raw.githubusercontent.com/rtk-ai/rtk/master/docs/contributing/TECHNICAL.md)）。
- **レイヤ分離:**
  - `src/core/`: 設定、トラッキング DB、TOML フィルタパイプライン、tee、テレメトリなど **コマンド非依存の基盤**（[src/core/README.md](https://raw.githubusercontent.com/rtk-ai/rtk/master/src/core/README.md)）。
  - `src/cmds/`, `src/filters/`: コマンド別 Rust 実装および大量の `.toml` フィルタ定義。
  - `src/discover/registry.rs`: 書き換えパターンの単一ソース（フック README および OpenClaw プラグインが言及）。
  - `hooks/`: エージェント別に配布される **薄いデリゲート**（シェル、Rust サブコマンド `rtk hook *`、TS プラグイン用スニペット）。
  - `src/hooks/`: `rtk init` によるインストール・整合性検証など（[hooks/README.md](https://raw.githubusercontent.com/rtk-ai/rtk/master/hooks/README.md) と TECHNICAL の対応関係）。
- **用語:** 「Rust Token Killer」の略として RTK、`rtk rewrite` の終了コード契約（0=書き換え、1=該当なし、2=deny、3=ask 等）が Claude 用フックに埋め込まれている（[hooks/claude/rtk-rewrite.sh](https://raw.githubusercontent.com/rtk-ai/rtk/master/hooks/claude/rtk-rewrite.sh)）。

### 機能一覧

**コア**

- **CLI プロキシ本体:** `main.rs` 経由のサブコマンドルーティング、Clap ベース（[src ツリー](https://api.github.com/repos/rtk-ai/rtk/contents/src?ref=master)）。
- **コマンド書き換え (`rtk rewrite`):** レジストリに基づき `git status` → `rtk git status` 等。複合コマンドは `&&`/`||`/`|` 等のルールあり（[hooks/README.md — Compound Command Handling](https://raw.githubusercontent.com/rtk-ai/rtk/master/hooks/README.md)）。
- **トークン節約フィルタ:** ファイル操作、git、テストランナー、リンター、AWS/docker/kubectl、パッケージマネージャ等、README に列挙（[README — Commands](https://raw.githubusercontent.com/rtk-ai/rtk/master/README.md)）。
- **トラッキング / `rtk gain`:** SQLite に推定トークン削減を記録（スキーマは [src/core/README.md](https://raw.githubusercontent.com/rtk-ai/rtk/master/src/core/README.md)）。
- **TOML フィルタ DSL:** 8 段階パイプライン（strip_ansi → replace → match_output → strip/keep_lines → truncate_lines_at → head/tail → max_lines → on_empty）。参照順はプロジェクト `.rtk/filters.toml`（`rtk trust` 必要）→ ユーザグローバル → ビルドイン結合（[src/core/README.md](https://raw.githubusercontent.com/rtk-ai/rtk/master/src/core/README.md)）。

**差別化**

- **マルチエージェントフック:** Claude `PreToolUse`、Cursor `preToolUse`、Copilot（透明 rewrite と deny-with-suggestion の併用）、Gemini、OpenCode プラグイン、プロンプトルール系（Cline/Windsurf/Codex）等の **機構別マッピング表**（[hooks/README.md — Supported Agents](https://raw.githubusercontent.com/rtk-ai/rtk/master/hooks/README.md)、[README — Supported AI Tools](https://raw.githubusercontent.com/rtk-ai/rtk/master/README.md)）。
- **tee recovery:** 圧縮・パース失敗時に生ログをディスクへ退避し、コンテキストには `[full output: ~/...]` のヒントのみ（`src/core/tee.rs`、README Configuration 節）。
- **OpenClaw プラグイン:** `before_tool_call` で `exec` を `rtk rewrite` に委譲（`openclaw/`）。

**ユーティリティ**

- **`rtk init` / `rtk init -g`:** グローバルフック導入、RTK.md、テレメトリ同意フロー等（README）。
- **テレメトリ:** デフォルト無効、オプトイン（[README — Privacy & Telemetry](https://raw.githubusercontent.com/rtk-ai/rtk/master/README.md)、`docs/TELEMETRY.md` へのリンク）。
- **Windows:** ネイティブ Windows はフック制限、WSL 推奨（README Windows 節）。

### 特徴的な点・注目ポイント

#### 1. トークン削減の 4 戦略と実装の当たり所

README が掲げる **Smart Filtering / Grouping / Truncation / Deduplication** はマーケティング上の分類だが、実装は次のように結びつく（一次情報ベース）。

| 戦略 | 実装の主な当たり所（例） |
|------|---------------------------|
| **Smart Filtering** | TOML DSL の `strip_ansi`, `replace`, `strip/keep_lines`, `match_output`；言語・ツール別 Rust フィルタ（`src/cmds/`, `src/filters/*.toml`）。 |
| **Grouping** | リンター・テスト出力をファイル単位・ルール単位にまとめる系のサブコマンド（README の `rtk lint`, `rtk tsc`, テスト系「failures only」）。 |
| **Truncation** | `truncate_lines_at`, `head/tail_lines`, `max_lines`；`[limits]` の `grep_max_results` 等（[src/core/README.md](https://raw.githubusercontent.com/rtk-ai/rtk/master/src/core/README.md)）。 |
| **Deduplication** | ログ系（`docker logs`, `kubectl logs`, `rtk log`）の説明で明示（README）。 |

**コマンド別:** 100+ サブコマンド・フィルタ TOML が `src/filters/` に大量配置（[API ディレクトリ一覧](https://api.github.com/repos/rtk-ai/rtk/contents/src/filters?ref=master)）。個々の「どの行を落とすか」は各 `.toml` / `cmds` 実装に分散。

#### 2. フック統合設計（10+ ツール文脈）

- **アーキテクチャ:** 全エージェントで **フィルタロジックは Rust 一元**、配布物は **JSON をパースして `rtk rewrite` を叩くだけ**（[hooks/README.md — How It Works](https://raw.githubusercontent.com/rtk-ai/rtk/master/hooks/README.md)）。
- **透過的書き換え:** Claude は `hookSpecificOutput.updatedInput`、Cursor は `updated_input`、Gemini は `hookSpecificOutput.tool_input` 等、**エージェントごとに異なる JSON 形**へマッピング（同 README の「JSON Formats by Agent」）。
- **非ブロッキング契約:** jq / rtk 欠如 / 解析失敗でも **フックは exit 0** で素のコマンドを通す（同 README「Exit Code Contract」）。**既知ギャップ:** `hook_cmd.rs::run_gemini()` が不正 JSON で exit 1 になり得ると README 自身が記載。
- **競合・上書き:** `rtk init` が各ツールの settings をパッチ。個人環境では **既存フックチェーンと順序・合成** がツール側アップデートで壊れうる（推測ではなく一般的リスク。rtk は整合性 SHA を持つ旨が TECHNICAL に触れる）。

#### 3. tee recovery パターン（圧縮時の情報保全）

- **通常:** `tee_raw` / `tee_and_hint` が **失敗時（exit code ≠ 0）** かつ生出力が **500 バイト以上** のとき `~/.local/share/rtk/tee/`（または設定・`RTK_TEE_DIR`）へ保存。デフォルト **mode = failures**，**max_files=20**, **max_file_size=1MB**（[src/core/tee.rs](https://raw.githubusercontent.com/rtk-ai/rtk/master/src/core/tee.rs)、README）。
- **成功だが要約しすぎ:** `force_tee_hint` が **exit code を無視**して書き込み、AWS 等で `FilterResult.truncated` のときにフル出力へのパスを残す（`tee.rs` コメント、[src/core/README.md — Tee](https://raw.githubusercontent.com/rtk-ai/rtk/master/src/core/README.md)）。
- **無効化:** `RTK_TEE=0`、または `config.toml` の `[tee] enabled = false`。

#### 4. `openclaw/` ディレクトリと OpenClaw の関係

- **役割:** OpenClaw の **`before_tool_call`** に登録し、ツール名 `exec` の `command` を **`rtk rewrite` のサブプロセス**に渡して置換（[openclaw/index.ts](https://raw.githubusercontent.com/rtk-ai/rtk/master/openclaw/index.ts)）。
- **薄さ:** コメント通り、ルール追加は **Rust レジストリ側**で完結しプラグインは `which rtk` と `execSync` のラッパー。
- **導入:** `openclaw plugins install ./openclaw` または手動コピー（[openclaw/README.md](https://raw.githubusercontent.com/rtk-ai/rtk/master/openclaw/README.md)）。

#### 5. `hooks/` ディレクトリの詳細

- **所有範囲:** 「ユーザマシンにインストールされる成果物」— シェル、`rtk hook copilot` 等のバイナリ連携、ルールファイル、OpenCode TS プラグイン断片。インストール本体は `src/hooks/init.rs` 側（[hooks/README.md — Scope](https://raw.githubusercontent.com/rtk-ai/rtk/master/hooks/README.md)）。
- **サブディレクトリ:** `claude/`, `cursor/`, `copilot/`, `codex/`, `cline/`, `windsurf/`, `opencode/`, `kilocode/`, `antigravity/` 等（[API: hooks](https://api.github.com/repos/rtk-ai/rtk/contents/hooks?ref=master)）。
- **Claude フック実例:** `jq` で `.tool_input.command` を抽出 → `rtk rewrite` → 終了コードに応じて `permissionDecision` 付与 or 省略（[hooks/claude/rtk-rewrite.sh](https://raw.githubusercontent.com/rtk-ai/rtk/master/hooks/claude/rtk-rewrite.sh)）。

#### 6. Justin Poehnelt 系「Agent-First CLI」との対応

一次ソースとして、Poehnelt 原作へのリンクは [understandingdata.com のまとめ](https://understandingdata.com/posts/rewrite-cli-for-agents/) 経由で [justin.poehnelt.com の記事](https://justin.poehnelt.com/posts/rewrite-your-cli-for-ai-agents/) が引用されている。

| Poehnelt 側の柱（要約） | rtk との対応 |
|---------------------------|--------------|
| **Context Window Discipline**（field mask, ページング等） | 既存 CLI の **stdout を後段で削る**プロキシ。ネイティブ `--fields` ではなく **結果の圧縮**で同じ経済性を狙う。 |
| **Machine-readable / predictable output** | テスト・リンターで JSON/NDJSON 利用を前提としたフィルタが多い（README の `go test`, `ruff` 等）。ただし万能 JSON 化ではない。 |
| **Schema Introspection** | **非対応**。`gws schema ...` 型の **実行時スキーマ**は持たず、レジストリは **コマンド文字列パターン**（`src/discover/registry.rs`）が中心。 |
| **Input Hardening** | **非主眼**。エージェント入力検証より **出力ノイズ除去**が主目的。 |
| **Skills / CONTEXT 注入** | `RTK.md`・各種 rules で「rtk を使え」という **プロンプト層**はあるが、Poehnelt が想定するスキルパッケージ設計そのものではない。 |

**総評:** rtk は Poehnelt が示す「エージェント第一の CLI を **最初から**設計する」アプローチの **代替ではなく、レガシー CLI 群への後付けアダプタ**として位置づくのが正確。文脈規律・コスト削減という **目的**は強く一致する。

#### 7. 個人開発環境での採用判断（コスト vs 学び）

**コスト側**

- **設定・運用:** `~/.config/rtk/config.toml`（macOS は `~/Library/Application Support/rtk/config.toml`）、`[hooks] exclude_commands`、`[tee]`、`rtk trust` 済みプロジェクトの `.rtk/filters.toml` など、**状態がホームディレクトリとリポジトリに分散**（README / core README）。
- **フック競合:** Cursor / Claude 等の **ネイティブフック**や他ツールと **同一イベントに複数登録**した場合の優先度・合成はエージェント依存。rtk は「壊さない」ために exit 0 を徹底する一方、**期待どおり書き換えが効かない**ケースのデバッグコストは残る。
- **バージョン追従:** フックに **rtk >= 0.23.0** 等のガードあり。エージェントの JSON 仕様変更時は `hooks/` のメンテが必要（README の Integration Tiers）。
- **観測・プライバシー:** テレメトリはオプトインだが、組織ポリシーでは「集計でも送らない」要件と衝突しうる（README のフィールド一覧は透明）。

**参考価値側**

- **パターン知識:** 「フックは薄く、ルールは単一バイナリ」「失敗時 tee」「エージェント別 JSON のみ分岐」は **自前ツール設計の教科書**になりうる（[hooks/README.md](https://raw.githubusercontent.com/rtk-ai/rtk/master/hooks/README.md)、[TECHNICAL.md](https://raw.githubusercontent.com/rtk-ai/rtk/master/docs/contributing/TECHNICAL.md)）。
- **採用の分岐基準（調査者所見）:** エージェントが **Bash 経由で同じコマンドを繰り返し実行**するワークロードほど ROI が高い。Built-in `Read`/`Grep` 中心の運用では README が指摘する通り **自動書き換えの外**が残るため、効果は限定される。

### 使い方・典型的なワークフロー

1. インストール: Homebrew / `install.sh` / `cargo install --git`（[README — Installation](https://raw.githubusercontent.com/rtk-ai/rtk/master/README.md)）。
2. `rtk init -g`（エージェント別フラグ）でフックとドキュメント注入。
3. エージェント再起動後、通常どおり `git status` 等を実行 → フックが `rtk git status` に差し替え。
4. 設定例:

```toml
[hooks]
exclude_commands = ["curl", "playwright"]

[tee]
enabled = true
mode = "failures"
```

（[README — Configuration](https://raw.githubusercontent.com/rtk-ai/rtk/master/README.md)）

### エコシステム・実利用状況

- **採用事例:** 公開リポジトリからは **企業名・本番規模の一次データは未確認**。コミュニティ規模は GitHub stars / forks が大きい（調査時点の [API](https://api.github.com/repos/rtk-ai/rtk)）。
- **盛り上がりの文脈:** 2026 年初頭創設の組織リポジトリで成長が急激。Show HN および続く HN スレが存在（例: [item?id=46974740](https://news.ycombinator.com/item?id=46974740), [item?id=47081527](https://news.ycombinator.com/item?id=47081527)）。トークン課金・コンテキスト上限への関心と合流。
- **コミュニティ:** Discussions / Issues 数は多く、機能要望・エージェント対応・フィルタの隙間が主題になりやすい構造（open issues 数は API 参照）。
- **周辺ツール:** 会話全体圧縮系（例: HN 上で言及される Squeezr 等）との比較が散見されるが、**同一カテゴリの公式ポジショニング文書は未読のため割愛**。rtk 自身は **シェル出力プロキシ**にフォーカス。
- **評判（バランス）:**
  - **肯定的:** 単一バイナリ、低オーバーヘッド、削減率の明示、フックの非ブロッキング設計（README / TECHNICAL）。
  - **否定的・注意:** 積極的フィルタがデバッグ情報を落とすリスク（tee で緩和）、Windows ネイティブの制限、Built-in ツール経路は対象外（README）、別名 `rtk` の crates.io 衝突注意（README）。

### 他ツールとの比較・ポジショニング

- **対 エージェントネイティブツール:** Claude `Read`/`Grep` はフック対象外 → **「シェル中心のエージェント」ほど rtk と相性が良い**（[README — Important](https://raw.githubusercontent.com/rtk-ai/rtk/master/README.md)）。
- **対 Poehnelt 型の agent-native CLI:** スキーマ駆動・入力検証・MCP 面は **rtk のスコープ外**。**既存エコシステムの帳尻合わせ**が rtk、**新規 CLI の設計規範**が Poehnelt 側、という補完関係。

### 制約・注意点

- **成熟度:** リポジトリ作成から日が浅く（2026-01-22 作成 API）、API・フック仕様は **破壊的変更リスク**が相对的高い。
- **LICENSE 表記:** `Cargo.toml` と README 末尾は **MIT**。[GitHub API の license フィールド](https://api.github.com/repos/rtk-ai/rtk) は調査時点で Apache-2.0 と表示され **食い違いの可能性**あり。法務用途はリポジトリ内 `LICENSE` ファイルを直接確認すること。
- **README と実装の版数:** README の verify 例と `Cargo.toml` / latest release の版が一致しない可能性。
- **スケール:** SQLite トラッキング、tee ローテーションは **個人〜小チーム向け**想定。中央集約ダッシュボードは `rtk gain --format json` 等で自前（README）。

### 深掘り候補（コードリーディング対象）

- `src/discover/registry.rs` — 書き換えパターンの全体像。
- `src/hooks/rewrite_cmd.rs`, `src/hooks/init.rs` — 複合コマンド・インストール・ deny/ask。
- `src/core/filter.rs`, `src/core/toml_filter.rs` — TOML DSL 評価と Rust フィルタ境界。
- `src/core/stream.rs`, `src/core/runner.rs` — 実行・ストリーミング・フォールバック。
- 代表フィルタ: `src/filters/cargo-test.toml`, `src/filters/git-status.toml` 等（実在ファイル名はリポジトリの `src/filters/` 一覧を参照）。
- `hooks/copilot/` — deny-with-suggestion と VS Code Chat 両対応の実装差分。
