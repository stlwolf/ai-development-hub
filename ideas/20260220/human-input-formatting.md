# 人間側のプロンプト・ドメイン入力のフォーマット化

SO やエージェント間のプロンプトだけでなく、人間がエージェントに渡す情報にもフォーマット化の余地がある。

## 背景

FWアップグレードはドメイン判断が少なかったため問題にならなかったが、新機能実装やビジネス要件を含むタスクでは、人間からの入力品質が出力品質を直接支配する。

## 過去の実験

インフラ構築タスクで、AI に「自分（人間）がドメイン判断するために必要な質問リスト」を先に生成させ、人間がそれに回答、回答をドキュメント化してエージェントに再投入する手法を試みた。

効果:
- 人間が「何を伝えるべきか」を漏れなく把握
- AI が必要な情報を構造化された形で受け取れた
- ドキュメントが残り、別スレッド/別エージェントへの引き継ぎが容易

## Cursor プランモード質問機能との関係

Cursor のプランモードでは、複数選択肢 + 自由記述欄の形式で人間に質問できる（AskQuestion ツール）。プロトコル化の可能性:

1. AI が判断に必要な情報を構造化された質問として提示
2. 人間が回答（選択 + 自由記述）
3. 回答がログとして残る
4. 別エージェントが同じ回答を参照して作業継続可能

## 核心

「人間がプロンプトを上手に書く」個人スキルの問題ではなく、**サービス開発のプロセスとして入力品質を標準化する**話。AI 側が質問フォーマットを提示し、人間がそれに沿って回答する形が最も持続可能。

## 検討事項

- タスクタイプ別の質問テンプレート（新機能/バグ修正/リファクタ/インフラ等）
- 質問の深さ（初回は概要、詳細設計フェーズで深い質問）
- 回答のドキュメント化先（Issue? ナレッジベース? リポジトリ内?）
- AI が質問を自動生成する場合のガードレール
