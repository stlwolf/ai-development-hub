# SO 向けプロンプトのフォーマット化

FWアップグレード実践で、SO に渡すプロンプトの構造化度合いが収束速度に影響する可能性を観察。

## 観察

- 初回: 5つの質問を一括、自由形式 → 回答の焦点が散った
- 中盤: 「このプランを反証して」+ 検証観点リスト → 構造的な問題を発見
- 後半: 先行タスクの FB を前提情報として添付 → 1ラウンドで合意

プロンプトの品質向上は「何を聞くべきか」の明確化によるもの。

## 提案: タスクタイプ別プロンプトテンプレート

### プランレビュー型

```
- 前提条件（リポジトリの状態、技術スタック）
- プラン本文（Phase / Step 構造）
- 検証してほしい観点（明示的にリスト）
- 既知の懸念点（自分の分析で不確実な箇所）
- 先行タスクの FB（あれば）
```

### 事実確認型

```
- 確認対象のパッケージ/API/バージョン
- 現在の認識（自分が調べた結果）
- 一次ソースの指定（レジストリ URL 等）
```

## 未解決: コンテキスト添付基準

`-c` で添付するファイルの選定が感覚的。何を添付すべきかの基準がないとプロンプト品質がブレる。

## 実装先の候補

- `so-compare.sh` にテンプレート選択機能
- `peer-ai-review` コマンドに埋め込み
- 別途プロンプトテンプレート集として管理
