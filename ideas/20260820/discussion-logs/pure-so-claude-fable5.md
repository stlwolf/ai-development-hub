もう1点、「トークン節約=書き手だけの利得」も誤りを含みます。共有コンテキストの環境(長いセッション、複数文書のロード)では、トークン量は**読み手のコンテキスト予算**を直接消費します。圧縮の利得は書き手側に偏ってはいても「だけ」ではない。なお段階1のプレーン化は 9.7k→17k と75%増でした。

さらに指摘したいのは、research ノートでは [speculation] と正しくタグ付けされたこの命題が、discussion の「確定したこと」4に**タグなしで昇格している**ことです。自前の evidence-verification 規約に照らして、これは status inflation です。

### 2. 欠落

- **人間の読解科学がほぼ皆無。** 「人間可読性」と題した証拠束の測定値がほぼ全て AI 読者(names-disappear、format tax、latent 通信)についてのもので、人間側は BLUF/Minto [unverified-summary] と owner 体感だけです。Nielsen Norman Group のスクリーン読解研究(F字パターン・走査行動。AI チャット出力の読まれ方の実測もある)、plain language の標準化(ISO 24495-1、米 Plain Writing Act)、headlinese/telegraphese の心理言語学(電報体の人間コストを直接測った先行分野)、可読性指標の系譜。中心の問いが人間側なのに、証拠の重心が機械側にあります。
- **RLHF の verbosity/length bias 文献。** over-answering と rule-of-three 的な癖には「reward model の長さバイアス」という確立した因果説明があります。これは所見2の現象への**原因**の候補であり、原因が preference-tuning 由来なら、対策の第一候補は editor パスではなくシステムプロンプトでの counter-steering(安価)になる — 対策の優先順位を変える欠落です。
- **Lost in the Middle(Liu et al.)。** 情報の位置がモデルの読解精度を動かすという実測。「順序」軸を人間専用の問題として扱っていますが、AI 読者にとっても順序は効きます。収束仮説(1つの形が両方に効く)を支持しうる材料が、順序の側に落ちています。
- **Diátaxis と逆ピラミッド。** 文書種別ごとに読者アクセスパターンを分ける実務標準(後述の別の結論に接続)。逆ピラミッドが**電信**の産物である(電報が telegraphese と結論先出しの両方を生んだ)という史実は、所見3の BLUF より古い先行技術です。
- **スタイル転送研究(formality transfer、GYAFC 等)。** editor 型の後編集には学術的な蓄積があり、「市場スキル」より強い根拠で試作を設計できます。

### 3. 別の結論

同じ証拠から、私は**読者種(人間用/AI用)ではなくアクセスパターン(精読/参照走査)で分解する**方が良いと考えます。

- 精読される文書(discussion、episode の叙述、チャット応答)は、人間・AI どちらが読むかに関係なく平易な散文が有利。
- 走査・参照される文書(board、status、カタログ)は、**人間にとっても**密度と視覚的並列性が利得になる。board を目視で走査する人間は密度から利益を得ており、「電報体の利得は書き手だけ」はここで反例を持ちます。

このフレームだと、電報体の問題は「書き手最適化」ではなく**「走査最適レジスタの、精読文脈への誤適用」**になります。段階1との張力も、「測っている層が違う」より綺麗に解消します: 明示事実プローブは走査タスクであり、走査最適レジスタは走査プローブに通った。names-disappear で落ちたのは要約=精読タスクだった。そして設計則が1つ出ます — **レジスタは読者種でなくアクセスパターンで選ぶ**。これは discussion 確定6の「読者軸は偽の二択」と同じ方向を向いていますが、二択を捨てた後に何で分けるかの答え(ライフサイクルではなく、アクセスパターン)が異なります。会話面が平易散文であるべき結論は変わりません(会話面は常に精読される)が、根拠が「人間専用だから」から「精読面だから」に変わり、episode/board の for-AI 方針(開いている争点4)まで同じ軸で決められます。

副次的な別結論として: 読みづらさの主因を「自己回帰の構造要因」ではなく「preference-tuning の副作用」と置くと、対策階層が変わります(第一手=output style での counter-steering、editor パスは残差処理)。closed-weight の format tax がほぼゼロという測定は、この安価な第一手が無税で通る可能性を既に示しており、起票済みの output styles 検証はこの因果仮説の判別実験を兼ねられます。
