## 事実として立っていること（3レーンも争わなかった測定値）

証拠は research ノート v2 参照。識別子除去による理解低下（要約 -28.6pt）、over-answering（重複 65.7% / padding 69.1%）、format tax（プロンプト指示側が主・closed-weight ではほぼゼロ・thinking-first で +9.2pp 回復）、latent 通信の同一系列限定、段階1実測（電報体でも明示事実プローブは全○・コストは記号 decode と参照解決の狭い層）。

## 現在の見立て（推論。SO 反証で v1 から更新済み）

1. **読みづらさは3軸**: 内容選択（量・重複）/ 順序（導出順 vs 読者順）/ 表面の癖。v1 の2軸は、一番よく測れている内容選択の軸を落としていた。
2. **editor 型偏在の説明は配布制約**: 市場の対策が後編集型なのは第三者が重みやシステムプロンプトに触れないため。「自己回帰で生成時点に結論が無い」という v1 の構造要因説は取り下げ（反例: ハーネスの sysprompt 自体が生成時レジスタ指示・reasoning モデル・thinking-first の回復）。
3. **会話面は生成時契約を先に試す**: closed-weight では format tax がほぼゼロなので「生成を縛るより後段」は会話面には当てはまらない。文書生成は後段整形が安いまま。二分して扱う。
4. **電報体の害の正体は誤適用**: 「識別子除去と同型 → 書き手最適化」は3レーン一致で崩れたため取り下げ。現仮説は「走査最適レジスタの精読文脈への誤適用」。名前を削る操作（記号圧縮）と接着を削る操作（体言止め）は別物として扱う。反証条件つきの実験（名前保存 + 体言止めのみ → 要約課題）は段階1の再測定改善(5)と同一。
5. **3層分割は保持、表現を弱める**: transport/envelope は schema（既に for AI）。意味の層は自然言語が「有力な既定」（最適の証明ではない・CNL の第三項が3系統から独立に出現）。モデル内部は latent が強いが同一系列限定。会話面が平易散文であるべき根拠は「人間専用だから」ではなく「常に精読される面だから」。
6. **置き場が分けていたのは読者ではなくライフサイクル**: research = 安定（動かない証拠）、ideas = 揮発（次ラウンドで動く議論の状態）。ただし claude レーンは「二択を捨てた後に何で分けるか」への別解としてアクセスパターン（精読/走査）を出しており、ライフサイクル軸と競合ではなく別レイヤ（保存場所 vs レジスタ選択）の可能性がある。整理は次ラウンド。

## 開いている争点

- **レジスタ選択の軸はどれか**: 3レーンの「別の結論」が三つ巴 — codex: 意味表現の正本 + 用途別レンダラー / cursor: 構造共有 + 消費者別レジスタ（二層併産の一般化）/ claude: アクセスパターン（精読/走査）。収束仮説（1つの平易散文 + 機械構造が両読者に効く）は精読面限定に縮んだ。どれを #263 段階2 と #329 の設計に採るかが次の主戦場。
- **読みづらさの主因**: 導出順説（v1）に対し、RLHF 長さバイアス説（claude + cursor が独立提出）。#348 の output styles 検証が判別実験を兼ねる（style の counter-steering で大きく改善するなら preference-tuning 由来が濃い）。
- **接着削り（体言止め・高密度）の実害**: 未測定のまま。段階1改善(5) と同じ実験（名前保存の変異テスト）が反証条件。
- **for AI 文書の最適形**: 「機械語寄り」は読解側の証拠で棄却方向のまま。ただし CNL という中間層と、走査面では密度が人間にも利得というアクセスパターン仮説により、「for AI = 平易散文」でもない。
