# #284 の設計判断を decision へ後追い昇格

## Context / なぜこの作業が始まったか

#284 の closure は「Decision / ADR 昇格は なし」と1行で判定した。owner との振り返りでこの判定は不十分だったと結論したため、確定済みの設計判断を後追いで decision doc に書き起こす。判断そのものは #284 と PR #285 で既に確定しているので、本ユニットが作るのは正本の doc だけである。

本ユニットにはもう一つ目的がある。**episode と issue コメントだけで decision を書けるかどうかを試すこと**である。書けない箇所は埋めずに欠落として報告する、という条件で始まった。これは #284 で入れた read/write 契約が「設計根拠を運べているか」の試験に当たる。

なお本ユニットは 2026-07-28 に plan-first の計画を書き、owner の gate 3 承認を得て 2026-07-29 に執筆した。frontmatter の日付は着手日に合わせている。

### 2026-07-29 案J は棄却されていない — ただし「記載漏れ」も当時の記録ではない

addendum は「案J は棄却ではなく案N′ に吸収されており、closure の一覧が J を欠番にしているのは記載漏れである」と指示した。これを raw log で確かめたところ、**「記載漏れ」という判断自体は #284 当時の記録には無い**（0 ヒット）。統括の現行セッションでの再構成である。

ただし**吸収されたという実体は成果物から検算できる**。案J の定義は「Step 3 の型名は残すが『書く内容』を『本文で確認する証拠 / closure で行う disposition』へ変更し、closure で事実を再執筆しない契約にする。本文中の durable anchor を closure がリンク・要約し、欠落時だけ `reconstructed` として補完する」である。着地した案N′ と突き合わせると次になる。

- **採られた**: closure で事実を再執筆しない契約・本文の durable anchor を closure が指す形。これは案N′ の中核そのものである。
- **採られなかった**: Step 3 の「書く内容」列を書き換える案（N′ は Step 3 の表を動かしていない）。欠落補完に `reconstructed` を流用する案（N′ は別マーカー `本文なし: <理由>` を立て、`reconstructed` 流用は「語の意味の乗っ取り」として明示的に退けた）。

つまり **案J は中核が採用され、具体形2点が退けられた**。「棄却」でも「そのまま吸収」でもない。この読みは成果物だけで検算できるので、decision には自分の導出として書く。

### 2026-07-29 SO 指摘の内訳（両レーンが一致した5件と、片方だけの4件）

7. **（cursor）決定3項で「座礁点」の外延が揺れている。** #284 は「座礁点（事実・失敗セクション）は据え置く」と「Step 4 の確認対象は移さない」を別の文で書いている。自分の doc は座礁点と Step 4 の確認対象（closure 節）を畳んでおり、決定4項では突合対象を事実・失敗節と正しく書いているので、同一 doc 内で語の外延がずれた。
8. **（cursor）決定4項は N′ 確定時点の判断ではなく、実装中の gate 4 round 2 の是正である。** 最終成果物としては正しいが、「最初からそう決めた」と読める。時期を開示していない。
9. **（cursor）転用形 (4) の帰属が誤り。** 宛先明示は gate 1 の診断訂正・設計原則 §4 / §5・#113 の決定記録から出たもので、実測3軸（二重執筆 / why / 肥大）から出たものではない。**誤帰属が抽象を一段格上げする支点になっていた**という指摘で、これが最も痛い。

**両レーンが「material なし」で一致した箇所**も記録する。座礁点の範囲を動かしていないこと・述語が4本であること・バリデータを実装しないこと・測定値の訂正後表記の選択は、いずれも一次資料と一致していた。

### 2026-07-29 SO 指摘への対応 — 9件すべて反映・round 2 は回さない

宣言どおり round 1 の material をすべて直し、round 2 は回していない。**#284 の判断に触る修正は1件も無かった**（すべて自分の doc の忠実度と主張の強さの問題だった）ので、親へ上げる必要も生じなかった。

対応の要点は次のとおりである。

- 決定2項の見出しを「2度書かない」から「**再掲しなくてよい（再掲の禁止ではなく、要求しない）**」へ改めた。実装した契約の強さに合わせた。
- 決定1項の「生産者側の欠陥はゼロ」を「**観測範囲では根拠が得られなかった**」へ弱めた。測定は欠陥の不存在を証明していない。将来の変更トリガーにも「生産者側の欠陥が実際に観測された場合」を追加した。
- 決定3項で**座礁点（事実・失敗セクション）と Step 4 の確認対象の範囲（closure 節）を別の文に分けた**。#284 の着地コメント自身がこの2つを畳んで書いており、その表現を引き継いだのが原因だった。N′ 確定コメントの方が精密だったので、そちらに合わせた。
- 決定4項に**時期の開示**を足した。全出力型への拡大は N′ 確定時点の判断ではなく実装中 gate 4 round 2 の是正である。「復元できなかったこと」にも独立した節を立てた。
- 決定5項で **P1 / P2（pointer 契約）と P3 / P4（追記判定）が別軸である**ことを明示し、同じ節に置いたのは実装上の都合で契約から導かれたものではないと書いた。P3 の閾値が未決である点も同項の中に書いた。述語が4本である選定理由は記録に無いので「復元できなかったこと」へ回した。
- 決定6項の根拠（意味の単位が違う・全項目に付けると抜け道になる）を「根拠」節に独立した小節として足した。結論だけが浮いていた状態を解消した。
- 「根拠」節の実測に**重複の分布**（#263 は決定と根拠 4/4・#262 も決定と根拠）を足した。全出力型への拡大を支えるのは総数 6/6 ではなくこの分布である。
- 選択肢表の案K / 案M の理由セルに「**（後からの再構成）**」を前置し、当時は未探索カテゴリの列挙で止まっている旨を書いた。案J は「棄却されていない」から「**採否は不明・構成要素の一部が N′ にも現れる**」へ弱めた。案D / 案H も理由が不完全である旨を表と限界節の両方に書いた。
- 転用形の節を「型に依らない抽象」から「**検証されていない仮説**」へ書き換え、項ごとの証拠強度を表にした。**(4) の帰属を訂正した**（実測ではなく gate 1 の診断訂正と設計原則と #113 の決定記録から出ている）。「宛先の不在は越境と区別できない」という一般命題は取り下げ、1事例の観測に留めた。decision 側の先例が**別の文書型のあいだの pointer であって同型ではない**ことも明記した。

**この round で最も価値があった指摘は、自分では気づけない種類だった。** 転用形 (4) を「実測から出た」と誤って帰属していた点である。誤帰属それ自体は小さいが、**実測に紐づけることで1事例の観察を格上げする支点になっていた**。抽象の格を上げたい動機と、根拠を強く見せる書き方が結びつくと、こういう誤りが自然に出る。2レーンのうち1レーンだけがここを捕まえた。
