# #550 判断ボードを作り直すきっかけにアカウントの切り替えを足し、子のカードの別リポジトリの番号の直しを読み違えない書き方にする

### I1-2: SKILL.md の直し（2026-10-29）

- 4節の1: 「送り元と違うリポジトリの番号を、すべて `owner/repo#N` に直す」を主文にし、`source` が違うときの扱いをその中の場合分けに下げた。「送り元が同じでも省かない」を太字の独立した文にし、knowledge item `01M5T897ZT6RD65E4PSGZFGKTP` に沿って、読み手の思い込みの側（「直すものが無いように見えても」）から書いた。
- 10節: きっかけを3つにし、3つ目（アカウントや組織の切り替えで読めない・出し直せない）の手順の項と、アカウントを戻したときの項を足した。あわせて「最新の URL の正本は台帳の最後の `published`」と「作り直すときの公開のファイル名」の項を、3つのきっかけ共通の決まりとして置いた。
- **判断: 閉じたページを出したことを `published` に書かない**。前の10節は「`published` に新しい URL を書く。古い URL には閉じたページを出す」の順で、閉じたページを出したことも `published` に書くと、最後の `published` が古い URL になり、「最新の URL の正本は最後の `published`」と食い違う。`ledger.py` の形は変えない（scope）ので、書かないことを文で決めた。
- **判断: ファイル名に、組織の印に加えて回の番号も足す**。確定版は「組織を見分ける印」だけだが、個人→チーム→個人と戻して作り直すと、同じセッションでは個人の印の名前が前の個人のページの URL へ出しに行き、閉じるべき前のページに上書きする。決まりの芯を「前に公開したどのファイル名とも違う名前」に置き、組織の印はその一部にした。印の出どころの #539 のコメントは「組織や版を区別する印」と書いていた。これは確定版の範囲の中の補正と見ている（新しい作業義務は足していない）。
- **判断: アカウントを戻しても、前のページへは戻らない**。確定版の「最新の `published` の URL を使い続ける」に1文ずつ当て直すと（knowledge item `01M5PKRS6WECYZTYFC4WXANW50`）、戻したアカウントで最新の URL を読めないときの扱いが書かれていない。前のページへ戻すと「前のページは閉じた」と食い違うので、その場合も3つ目のきっかけとして作り直す、と書いた。統括が作り直さずに待つ（hub の統括が 2026-10-28 にしたこと）場合は、最後の `published` が前のページのままなので、そのまま使い続けることになり、この文と食い違わない。
- 棄却: アカウントを戻したとき、前のページを閉じる前にその保存先を読んで答えを拾う案。確定版は「会話で一言」を頼む形で決めていて、読むと「表へ移した問いの保存先を読み直さない」（13節）と、どちらの答えを採るかの順（7節の段3）に新しい場合分けが要る。scope の外なので足さなかった。
- 12節に「読んでいないことを理由に拒まれたとき」と「ページそのものを読めないとき」の区別を書いた。前者は Artifact の道具の説明（「この会話で読んでも出してもいないページへの公開は拒まれ、今のページが渡される」）によるもので、アカウントの切り替えではない。
