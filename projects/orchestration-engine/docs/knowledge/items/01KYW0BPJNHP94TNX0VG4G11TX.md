自分が名指しした失敗の型を、書き手に回ったときに免れると仮定してはいけない。**書き手側に回ったら、自分の検出実績を理由に外部の反証を軽くせず、必ず外部の目を入れる。**

#290 の arc で、「成立条件を落として効果を言い切る」型の過大主張が6回再生産された。1〜5回目は plan 執筆の子（opus）が犯し、毎回 SO の他族レーンが捕まえた。**6回目は、独立監査でこの型を名指しし、5回の再生産を監査文書に書いた当人（Fable 5・別セッション）が、書き手に回った直後に4件犯した**（「解消」「起きない」「規律にも依存しない」「現れることはない」）。書き手の個体・モデル系統・型の知識の3つすべてが入れ替わっても再生産され、自己検出は6回ともゼロだった。うち1件は、**同じ節の中で「言い切るな」という規律を自分で宣言した直後の行**で起きている — 規律の宣言は違反を防がなかった。

なぜ非自明か。検出の実績は「自分はこの型に強い」という証拠に見える。しかし #290 の観測では、検出能力は**読み手という位置**（他人の主張を疑う側・成立条件を照合する側）で働いたのであって、書き手の位置（自分の設計の効果を記述する側）には持ち越されなかった。同一個体が、読み手の位置では他者の過大主張と上流の誤り2件を検出し、書き手の位置では自分の過大主張4件を1件も検出できていない。

行動変更:

1. **書き手に回ったら、外部の反証（SO・レビュー）を必ず入れる。**「この型は自分が一番よく知っている」は反証を省く理由にならない — それが成立しない実測がこの item の根拠である。
2. **効果を言い切る文を書いたら、成立条件を同じ文か直後に併記する。** ただしこの規律の宣言自体は違反を防がなかった（上記）ので、**併記の有無を外部の目に明示的に照合してもらう**（反証プロンプトに「成立条件を落として効果を言い切る型を探せ」を入れる。#290 では外部 SO が同型を繰り返し捕捉しており、この観点を明示指定したラウンドでも実際に捕まった）。
3. 検証が構造的に届かない層（PR ゲートの外・gitignored の正本層）で書くときほど 1 と 2 を強く適用する。届く層では既存ゲートが代替する（exclusions）。
