並列のジョブを走らせている最中に、そのジョブのハーネスを書き換えない。直すのは全部終わってからにする。

shell はスクリプトを一度に読み込まず、実行しながらファイルを読み進める。走っている最中に書き換えると、既に起動した子は新しい内容の途中から読むことになり、**構文としては壊れていないのに「予期しないファイル終了」で落ちる**。エラーの文面は書き換えとは何の関係も無いように見えるので、原因を投入内容やモデル側に探すことになる。

実際に4本の run をこれで失った。直したかった欠陥はスクリプトの別の場所にあり、直し自体は正しかった。

守り方は2つある。**走っているスクリプトは書き換えない**こと。そして**投入の前に1ジョブだけ通して足回りを確かめる**ことである。後者があれば、直したくなる欠陥の大半は投入前に出る。
