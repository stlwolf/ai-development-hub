bash 3.2.57 で、`set -euo pipefail` と EXIT の trap を持つスクリプトが unbound variable で止まると、終了コードは trap の最後のコマンドの値になる。`/bin/bash -c 'set -euo pipefail; trap true EXIT; echo "$undefined"'` は 0 で終わる。trap が無いときと、`false` で止まったときは 1 である。bash 5.2.37 では、同じ形が 1 で終わる。

非自明なのは2点ある。1つ目は、**途中で止まったことが終了コードに出ない**ことである。2つ目は、**trap の中で `$?` を保存して返す素直な直し方も効かない**ことである。`trap 'rc=$?; ...; exit "$rc"' EXIT` でも 0 になった。unbound variable で止まった場合、trap に入った時点の `$?` が 0 だからである。#442 でテストのラベルの変数の直後に全角の括弧を書き、括弧の先頭バイトが変数名に食われてテストが途中で止まった。bash 3.2 の終了コードは 0 で、`=== Results:` の行が無いことで気づいた。engine のテストには、`set -euo pipefail` と `trap 'rm -rf "$_TMP_DIR"' EXIT` の組を持つものが多い。

次にどう行動を変えるか:

- bash 3.2 でテストを回したら、終了コードに加えて、最後のまとめの行（`=== Results:` など）が出ていることを確かめる。まとめの行が無ければ、終了コードが 0 でも通ったと読まない。
- 終了コードで合否を返させたいなら、最後まで進んだかを印の変数で見る。最後の行で `_done=1` とし、trap で「印が無く `$?` が 0 なら 1」にする。この形なら bash 3.2 と 5 のどちらも 1 で終わることを確かめた。途中で意図して exit 0 する経路（SKIP など）があるなら、その前に印を立てる。
