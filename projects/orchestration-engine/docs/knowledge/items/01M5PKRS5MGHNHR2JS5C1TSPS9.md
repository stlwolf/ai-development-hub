**「いつ〜する」の規則は、「〜する」と決める前に読まれる場所に置く。行為の手順を持つスキルに置くと、行為をすると決めたあとにしか読まれず、規則が発火しない。**

#466 で、owner への問いを載せるページを「いつ作るか」を決めたとき、最初に思いついた置き場は、ページを作るスキル（html-one-pager）だった。ページの扱いの決まりはそこに集まっているからである。しかし html-one-pager の description は「ページを作る依頼を受けたら読み込む」で、統括がページを作ると決めたあとにしか読み込まれない。「問いが2件たまったらページを作れ」をそこに書いても、ページを作ると決める前の統括には届かない。統括が問いを会話に書いて済ませれば、スキルは一度も読み込まれない。

規則は、出来事の名前（子から問いが届いた・SO が終わった・owner に判断を求める）で発火する別のスキルに置き、ページの扱いの一般の決まりだけを html-one-pager に残す形にした。owner はこれを承認した（#466 の decision の決定24）。

## なぜ非自明か

置き場の候補を「その規則が何について書いているか」で選ぶと、行為の手順を持つスキルが最も自然に見える。規則の中身は正しく、置き場を読み直しても欠陥は見えない。欠けているのは「いつ読まれるか」で、これは置き場の文面ではなく、置き場の入口の条件（description・ルールの読み込み・hook の発火点）の側にある。

## 次にどうするか

- 規則の置き場を決めたら、その置き場が**いつ読み込まれるか**を入口の条件で確かめ、規則が発火すべき時点より前に読まれるかを見る。
- 後なら、出来事の名前で発火する入口（その出来事のスキル・hook・常に読まれるルール）に置き、行為の手順のスキルからは指すだけにする。
- 発火を description の一致に頼る置き場では、実物の場面で読み込まれたかを記録して確かめる。
