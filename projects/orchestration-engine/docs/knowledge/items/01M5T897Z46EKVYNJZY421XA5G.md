**承認された判断の間を揃えるだけに見える直しでも、片方が人間の承認者の答えの文面で、揃えると効き目がほかの使い方に広がるなら、補正でなく変更として、実行する前に照会する。級の判定が分かれうる直しは、承認済みの直しと別の commit にする。**

#538 の実装で、承認された「答えを待つページは答えを集める側ごとに1枚まで」を html-one-pager に足したとき、同じ項目に残っていた「分けるのは、作業のまとまりが違うときか、量が多いとき」と食い違った。子は、承認済みの plan の別の設計判断（作業のまとまりは同じページの節で受ける）の読みに揃えて直し、補正と申告した。統括は変更と判定し、owner の再承認に回した。食い違っていたのは owner が #466 で答えた2つの文面で、揃えるとその片方の意味が変わり、html-one-pager を使うほかのリポジトリの統括の使い方も変わるからである。

子はその直しを、承認済みの直しと同じ commit に入れていた。owner が揃えないと答えたら commit ごとは戻せず、該当の文だけを新しい commit で戻す手順を別に書くことになった。

## なぜ非自明か

級の決まりは「新しい判断・対応範囲・作業義務を足すか」で見る。揃える直しは、どちらの文も承認済みなので、何も足していないように見える。しかし揃えるときにどちらの文を採るかは、それ自体が選択で、採らなかった側が人間の承認者の答えの文面なら、その答えの意味を変える選択になる。依頼側と実行側で、「承認されたのは文面か、読みか」の見方が分かれる。

## 次にどうするか

- 揃える直しでは、揃える両方の文の出どころを見る。片方でも人間の承認者の答えの文面なら、変更として実行の前に照会する。
- 揃えた結果の効き目が、その委譲の成果物の外（配布物を使うほかのリポジトリ・ほかのセッション）に広がるかを見る。広がるなら重い側に置く。
- 級の判定が分かれうる直しは、承認済みの直しと別の commit にし、戻すときに1つの commit を戻せば済むようにする。
