# #270 registry GC の全消しを止める — 実装プラン

## この単位が引き受けるもの

`oe_reg_gc`（`lib/delegate-registry.sh:167-186`）が、壊れた server pid で登記系コマンドが1回走ったのをきっかけに**生きている全 entry を消す**問題を止める。運用中に3回発生している。

**採る形は「GC の入口で身元の整合を検査し、確立できなければ何もしない」である。削除条件（`:182`）そのものは変えない。**

## この plan は gate 2 で設計を差し替えている（読む前に）

**gate 1 の結論（案C = 別 server pid の entry を削除せず無視する）を、gate 2 の反証を受けて案K（provenance の整合検査）へ差し替えた。** 経緯は episode の gate 2 節が正本で、ここには結論だけ置く。

差し替えた理由は2つある。どちらも**自分で一次確認した**。

1. **案C の決め手が崩れた。** 「読み取り側（`oe-tree`）は別 pid を残すのに GC だけが消す＝GC の意味論が浮いている」という論拠で案C を採ったが、**別 pid の削除は元設計の意図的な安全策だった**（F17）。読み取り側と GC は意味論が食い違っていたのではなく、**責務が違った**（read-only の表示 vs 世代跨ぎの identity 安全）。
2. **案C は correctness の負債を作る。** 別 pid の entry が永久に残るため、OS が tmux server の pid を再利用した時点で旧世代の entry が「自分のもの」として復活する。**新しい tmux server はペイン ID を `%0` から振り直すので、ペイン ID の衝突はほぼ確実に起きる**（F18）。つまり窓の確率は「pid 再利用 ∧ ペイン衝突」の積ではなく **pid 再利用のみ**で決まり、しかも滞留が無期限なので時間とともに広がる。

**案K はこの両方を持たない。** 削除契約を変えないので滞留も生まれず、`oe-tree` の表示も既存テストの期待値も動かない。

## 設計判断

### DJ-1 案K を採る — GC の入口で身元の整合を検査し、削除契約は動かさない

**採用: 案K（provenance の整合検査）＋ pid の形式検査。**

`oe_reg_gc` が正しく動くための不変条件は「**prefix に使う `pid` が、`live_keys` を作ったサーバと同一である**」ことである。型A も型B も、この不変条件が壊れた状態で GC が走ったために起きた。案K はその不変条件を直接検査し、成立しなければ何もしない。

**物差しは既存の `list-panes` 呼び出しの書式を伸ばすだけで取れる。** 同じ1回の呼び出しから「生存ペイン一覧」と「応答したサーバ自身が名乗る pid」の両方が返るので、**物差しと母集団の provenance が構造的に一致する**（2回呼ぶ間にずれる隙が無い）。

```text
$ tmux list-panes -a -F '#{pane_id} #{pid}'
%331 25967
```

採る理由。

- **型A・型B の両方を、型ごとのガードを足さずに1つの検査で覆う。** しかも**誤認先の名前空間も守る**（不整合を検出した時点で GC 全体をスキップするので、どの名前空間にも触らない）。案C はここで誤認先を巻き添えにする。
- **削除契約を変えない。** 別 server pid の entry は健全な文脈では従来どおり掃除される。したがって F17 の安全策（リーク防止・世代跨ぎの identity 安全）が維持され、**滞留も、そこから生じる correctness の follow-up 債務も発生しない。**
- **壊れた文脈で書かれた stray（`__330.json`）は、次の健全な GC が掃除する**（自己修復）。案C ではこれが永久に残る。
- **既存テストの期待値を1件も反転させない**（実測で 20/0。下記「事前検証」）。`oe-tree` の表示も `episode-221` の論拠も動かさない。
- 変更は `oe_reg_gc` の入口に閉じ、キー契約（F9）にも書き込み経路にも触れない。

**pid の形式検査を `-n` ではなく数値で行う。**

```sh
[[ "$pid" =~ ^[0-9]+$ ]] || return 0
```

- 空・glob メタ文字・非英数を一括で弾く。
- **書き込み側は pid を sanitize してキーにする（`:30`）のに、prefix 比較は raw pid をパターンとして使う（`:182`）という非対称がある。** 数値なら sanitize しても不変なので、この非対称そのものが消える。F19 のとおり現状でも実害は出ないが、不変条件を明示するほうが安い。
- `=~` は bash 3.0 以降で使えるため ADR-005 の 3.2 互換に収まる（実測済み）。

### DJ-2 案C を採らない（gate 1 からの差し替え）

案C（別 pid は削除せず無視）は gate 1 で3レーン全会一致の第一候補だった。**採らない理由は上記「差し替えている」節の2点**である。要点だけ再掲する。

- 決め手（読み取り側との整合）が **F17 で崩れた。** 別 pid の削除は意図的な安全策であり、GC の意味論は浮いていなかった。
- **型A を塞ぎ切らない。** `$TMUX` が名乗る pid と `list-panes` の接続先が食い違う場合、案C は誤認先の名前空間の entry を削除する。gate 2 の2レーンが独立に同じ穴を指摘した。
- **無期限の滞留が identity 復活の窓を開ける**（F18 により、窓は pid 再利用のみで決まる）。塞ぐには年齢ベース掃除などの follow-up が**必須**になり、「案C 単独で完成」とは言えない。

**案C が優れていた点も記録する**（将来 K が行き詰まったときの出発点として）。`continue` 1語で済み、tmux への新しい問い合わせを増やさない。K は `list-panes` の書式に依存を1つ足す。

### DJ-3 案A のしきい値は持たない

**決定的な理由は「効かない」ことである。** record 経由の実運用では事故は N−1 件削除になる（F3c）。誤 pid の新規 entry が先に書かれ、それは生き残るからである。**自分の再現実測がその形だった**（3件中2件が消えた）。「全件消すならスキップ」は3回の事故のどれにも発火しない。

逆向きの害もある。entry が1件だけでそれが正当に死んでいるとき、**正当な GC を永久に止める。**

これは `01KZ21M0N0FZ4YMR2R6DPHTWQ4`（合格条件を累計で書くな・直近の窓で見よ）の鏡像である。あの item は「壊れても緑を出し続ける検査」を戒めるが、ここで踏みそうなのは**「正しい仕事を止め続けるガード」**である。

**さらに深い形**: 「たった今書いた entry は生き残るはずだ」という自己参照のアンカーは、しきい値を持たない完璧な検査に見えて、**型B では事故時にも成立する**（キーも live_keys も同じ壊れた pid から作られる・F3d）。**アンカーは検査対象と同じ壊れた入力から導かれていてはならない。**

**この基準を案K 自身に当てると、案K の物差しも完全に独立ではない**（F22）。`tmux` は `-L` / `-S` が無いとき **`$TMUX` の第1フィールドをソケットとして接続先を決める**ので、案K が突き合わせているのは「`$TMUX` の第2フィールド」と「`$TMUX` の第1フィールドが指すサーバが名乗る pid」である。すなわち**検査しているのは `$TMUX` の内部整合性**であって、`$TMUX` が現在のプロセスの実サーバを指しているかではない。

- 独立しているのは**第2フィールドから**であり、`$TMUX` 全体からではない。
- したがって案K は「`$TMUX` が部分的に壊れた」形（型A / 型B）を覆い、「**`$TMUX` がまるごと別の生きたサーバのものである**」形（型C・下記 DJ-6）は覆わない。

**当初この節に「`$TMUX` から独立している」と書いていたのは誤りである。** gate 2 の claude レーンが tmux のソースを引いて指摘し、自分で実測して確定させた（F22）。案A を棄却した論拠を自分の案に当て直したら、限定が必要だったという形である。

罠そのものへの回帰テストは、案A を採らない場合でも置く（テスト [13]）。

### DJ-4 案K が新たに持ち込む失敗モードを、テストで塞ぐ

**案K は「測れなかったら何もしない」を導入する。** これは `01KZ21M0N0FZ4YMR2R6DPHTWQ4` の罠を自分で作る余地でもある — もし `#{pid}` が取れない環境があれば、**GC は黙って永久に no-op になる。**

- 環境の失敗（物差しが取れない）とデータの不備（entry が古い）を別の帯として扱う（`01KYA7C9NN4VDM7H2NYXZB2PSX`）。どちらも動作は「触らない」だが、**別の分岐として書き、別のテストで押さえる**（テスト [15]）。
- この環境の tmux は 3.5a で `#{pid}` を返すことを実測済み。`#{pid}` は書式が無効なら空になるため、**空を「測れなかった」として扱えば安全側に倒れる。**
- **「GC が走らなくなったこと」を運用中に検知する仕組みは無い**（F11 のとおり stderr は捨てられる）。ここは正直に限界として残す。テストが唯一の検知手段である。

### DJ-6 型C（複数 server の並行運用）は塞がない — 明示的に受容する

**失敗モードは2つではなく3つある。** gate 2 で3つ目が出た。

| 型 | 内容 | 現状 | 案C | **案K（採用）** |
|---|---|---|---|---|
| 型A | `$TMUX` の pid が別値（内部不整合） | 全消し | 塞ぐ | **塞ぐ** |
| 型B | `$TMUX` が空 | 全消し | 塞ぐ | **塞ぐ** |
| **型C** | **`$TMUX` は自分のサーバに対して完全に正しいが、registry を共有する別 server が同時に生きている** | 全消し | **塞ぐ** | **塞がない** |

**型C は「壊れ方」ではない。** tmux server を2つ動かしていれば正常な状態で成立する。`$TMUX` の第1フィールドと第2フィールドは整合しているので案K の検査は通り、変更していない削除条件が別 server の entry を prefix 不一致として消す。

**実測で確認した**（F22 / F23）。`TMUX="<probe のソケット>,<probe の pid>,0"` にすると `list-panes` は probe サーバへ繋がり（`pane=%0 serverpid=24060`、既定サーバは 25967）、案K 適用版でも別 server の正規 entry 2件が **0/2 になった。**

**しかも到達経路は仮定ではない。** F18 を測るために `tmux -L probe270` でサーバを立てた数十秒のあいだに、その中で `oe_reg_record` が1回走っていれば、本番の registry は消えていた。

**それでも本単位では受容する。理由を書く。**

- **型C は現状（master）でも全消しである。** 案K は型C を**悪化させない**。観測済みの3件（すべて型A / 型B・単一サーバ）を副作用なしで塞ぐ、という交換になる。
- **型C は一度も観測されていない。** 3回の事故はすべて単一の既定サーバ上で、prefix 不一致によるものだった。issue が報告した「別ツリーの cockpit を巻き添えにした」も、確認した限り**同一サーバ上の別セッション**であって別 server ではない。
- **塞ぐには新しい原始関数が要る**（下記）。`behavioral-rule` §4 の最小スコープに照らして、観測されていないモードのために設計を1段重くしない。

**補足（2026-08-15・owner 裁定時に親から）— 型C の露出窓は「日常運用」ではなく「engine のテスト」である。**

上の受容の理由づけは「型C は一度も観測されていない」と書いたが、**これは日常運用については正しく、テストについては当たらない。** ソケットを数えると `/private/tmp/tmux-501/` に**16件あり、生きているのは `default` だけで残る15本は死んだ probe ソケットである**（`oe202probe` / `oe227test` / `oejumptest` など、engine の検証で立てられたもの）。**うち `probe270` と `probeC` は、この plan の F18 / F22 を測るために自分が前日立てたものである。**

**自分で plan に書いた「`tmux -L probe270` でサーバを立てた数十秒のあいだに、その中で `oe_reg_record` が1回でも走っていれば本番の registry は消えていた」が、まさにその窓である。** つまり型C を踏む現実的な経路は、owner の日常操作ではなく**engine を検証する我々自身の手つき**である。probe サーバの中で `oe-delegate` / `oe-register` / それらを呼ぶテストを走らせれば成立する。

**受容の結論は変えない**（型C は現状でも全消しで、案K は悪化させない）。変えるのは**理由づけの射程**である。「観測されていないから受容する」ではなく、「**日常運用では観測されておらず、テストで踏む窓は #337 で塞ぐ**」が正確な言い方になる。テストで踏んだ場合の被害は本番 registry の全消しなので、**#337 の優先度はこの補足のぶんだけ上がる。**

**塞ぐ形は分かっているので、follow-up として名前をつけて残す。** 削除条件を2つの帯に分け、**他名前空間の entry は「持ち主のサーバプロセスが生きていないときだけ」消す**形である（`kill -0` + `ps -p <pid> -o comm=` が tmux か）。これは案C の「他人に触らない」と案K の「リーク防止を保つ」を同時に満たし、**3つの型すべてを塞ぐ。** gate 2 の2レーンが独立にこの形へ収束した。

- 本単位に入れない理由: repo に pid 生存判定の先例が無く（`kill -0` / `ps -p` は bin / lib に0件）、`ps` の可搬性も別途確かめる必要がある。**設計SO を1周も通していない形なので、ここで採ると測り直しと反証がまるごと B-2 に乗る。**
- **owner が複数の tmux server を日常的に使うなら、この follow-up は「あると良い」ではなく必須である。** gate 3 で確認してほしい点として報告に載せる。

**意図であることをテストで固定する**（テスト [16]）。将来この振る舞いを見つけた人が、事故なのか設計判断なのかを判別できるようにする。

### DJ-7 案C の美点も記録する（案K は上位互換ではない）

比較表は6軸で案K が勝つ形になっているが、**交換であって上位互換ではない。**

**案C は「他人の名前空間には触らない」を構造として持つので、何が壊れても削除が1名前空間に閉じる。** 案K は無制限の削除を残したまま前提条件を1つ足しただけなので、**前提条件をすり抜ける形（型C がまさにそれ）では爆風が全体に及ぶ。** 未知の失敗モードに対する頑健さは案C のほうが高い。

案K を選ぶのは「観測された3件を、契約を壊さず滞留も作らずに塞げる」からであって、「あらゆる面で優れている」からではない。**将来 K が行き詰まったときは、この軸が案C（または上記の帯分け）へ戻る根拠になる。**

### DJ-5 出力は足さない

呼び出し元が `oe_reg_gc 2>/dev/null || true`（F11）なので、GC が何を飛ばしたかを stderr に書いても誰にも届かない。「警告を出しているから気づける」という設計はこの呼び出し方の下では成り立たない。

先例は一枚岩ではない（F21）。`event-bus.sh:75` / `oe-ident:67` は黙って飛ばし、`oe-tree:136-139` は exit 2 で落ちる。**best-effort な GC が黙って `return 0` するのは前者に揃う**が、「作法を揃える」という言い方で後者の存在を丸めない。

`return 0` は「掃除できた」ではなく「本体を失敗させない」を意味する。既存の早期 return（dir 無し / tmux 無し / list-panes 失敗 / 一覧空）とすべて同型である。**コメントで「掃除せず正常終了（best-effort）」と明記する**（将来 `:64` の握り潰しを開けたときに意図が残るように）。

## 手順

### Step 1 — `oe_reg_gc` の入口に整合検査を入れる

`lib/delegate-registry.sh`。**削除条件（`:182`）は変更しない。**

```sh
  local pid panes live_keys p f base rc server_pid
  pid="$(_oe_reg_server_pid)"
  # 身元が数値でなければ何も掃除しない（#270）。空・glob 文字・非英数を一括で弾く。
  # 数値は sanitize で不変なので、下の prefix 比較（raw pid）とディスク上のキー
  # （_oe_reg_key の sanitize 済み）の非対称もここで消える。
  [[ "$pid" =~ ^[0-9]+$ ]] || return 0
  # 生存ペインと「応答したサーバ自身が名乗る pid」を同じ 1 回の呼び出しで取る。
  # 2 回に分けると、物差しと母集団が別のサーバから来る隙ができる。
  panes="$(tmux list-panes -a -F '#{pane_id} #{pid}' 2>/dev/null)"; rc=$?
  # list-panes 失敗 or 空（サーバ未起動/接続不可）時は GC をスキップ（全 entry 誤削除を防ぐ）
  [[ "$rc" -eq 0 && -n "$panes" ]] || return 0
  # 物差しが取れない = 測れなかった（環境の失敗）。データの不備と混ぜず、触らない。
  server_pid="$(printf '%s\n' "$panes" | awk 'NR==1{print $2}')"
  [[ -n "$server_pid" ]] || return 0
  # $TMUX 由来の pid と、live 一覧を作ったサーバの pid が食い違うなら身元が壊れている
  # （$TMUX 消失・別 server pid の混入）。掃除せず正常終了する（best-effort）。
  [[ "$pid" == "$server_pid" ]] || return 0
  live_keys="$(printf '%s\n' "$panes" | while IFS= read -r p; do
    p="${p%% *}"
    [[ -n "$p" ]] && printf '%s\n' "$(_oe_reg_key "$p")"
  done)"
```

**`#{pid}` の前提を1行書く。** `#{pid}` は tmux の FORMATS で Server PID を指し（`pane_pid` はペイン先頭プロセスなので別物）、**tmux 2.1 以降で使える**。未知の書式は空文字になるため、`[[ -n "$server_pid" ]]` が安全側に倒れる。この前提をコメントに残す（実環境は 3.5a）。

**関数ヘッダ（`:167`）も更新する。** 現在は「生存ペインに無い **or 別サーバ pid** の entry を掃除」で、案K では削除契約が変わらないため後半は正しいままだが、**「身元が確認できたときだけ走る」ことを1行足す**。正しい実装の真上に不完全な要約を残さない。

### Step 2 — テストの tmux モックを書式対応にする

`tests/test_delegate_registry.sh` のモックは `list-panes` に対し常に pane ID だけを返す。案K は同じコマンドを別書式で呼ぶので、**実 tmux と同じく要求された `-F` に応じて返す**形にする。

```bash
    "list-panes -a"|"list-panes"*)
      if [[ -n "${MOCK_TMUX_FAIL:-}" ]]; then echo "no server running on socket" >&2; return 1; fi
      # 実 tmux と同じく、要求された -F 書式に応じて返す（#{pid} を含むかで分岐）
      # shellcheck disable=SC2086
      if [[ "$*" == *'#{pid}'* ]]; then
        for _mp in $MOCK_LIVE_PANES; do printf '%s %s\n' "$_mp" "${MOCK_SERVER_PID:-99999}"; done
      else
        printf '%s\n' $MOCK_LIVE_PANES
      fi ;;
```

**この分岐を入れないと、`oe_reg_resolve` / `oe_reg_list` が pane ID として `"%5 99999"` を受け取って壊れる**（実測で6件落ちた）。`MOCK_SERVER_PID` の既定は既存の `TMUX` モック（`99999`）に合わせる。

### Step 3 — 隔離を fail-fast にする（既存の穴を塞ぐ）

**F20 の穴を先に塞ぐ。** `mktemp -d` が失敗すると空文字が exported され、lib の `:-` fallback が**実環境の registry** へ解決する。身元をわざと壊す GC を足す以上、ここは塞いでから追加する。

```bash
# --- 隔離した state dir（失敗したら即停止。実 registry を掴んだまま GC を走らせない）---
_tmp_root="$(mktemp -d)" || { echo "FATAL: mktemp -d failed" >&2; exit 1; }
[[ -n "$_tmp_root" && -d "$_tmp_root" ]] || { echo "FATAL: temp root is not a directory" >&2; exit 1; }
export OE_DELEGATE_STATE_DIR="${_tmp_root}/oe-delegate"
export OE_PANE_ISSUE_DIR="${_tmp_root}/pane-issue"
mkdir -p "$OE_DELEGATE_STATE_DIR" "$OE_PANE_ISSUE_DIR" || exit 1
trap 'rm -rf "$_tmp_root"' EXIT
# lib を source した後の最終確認（fallback で実環境へ落ちていないこと）
case "$OE_DELEGATE_STATE_DIR" in
  "$HOME"/.claude/*) echo "FATAL: 隔離が外れて実環境を指している" >&2; exit 1 ;;
esac
```

**当初プランが書いた「実パスとの `!=` 比較をファイル冒頭に置く」形は効かない。** `:12` の無条件代入が直後に上書きするうえ、空値は実パスと等しくないので通過する（F20 で実測）。**検査は代入の後に置き、非空・実在・`$HOME/.claude` 配下でないことを見る。**

**型B の再現は `TMUX` だけを unset し、`TMUX_PANE` は正常なまま**にする（F3b。両方消す再現は実際には起こり得ない状況の検証になる）。
