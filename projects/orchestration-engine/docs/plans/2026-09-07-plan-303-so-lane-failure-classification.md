# #303 / #344 — SO レーンの空返しを分類し、渡す前に入力を拒否する契約（実行プラン v2）

> **v2（2026-09-07・owner の gate 3 裁定を受けて）**: 初版は段階1（設計だけ・実装しない）だった。gate 2 が3レーンとも反証したため「確定の前に測ること」を特定する形へ書き直し、それを owner に返した。**裁定は「測定と実装を同時に進める」で、分類の目的を診断記録に限定しない。** 本 v2 はその裁定に沿って、測定の列（M）と実装の列（I）の2列に組み直したものである。裁定の正本は統括の発行した `.oe/ruling-303-hg.md`（作業層）で、要旨は §5 に転記してある。
>
> **§1〜§4 は初版のまま残す**（実測と gate 2 の記録であり、裁定で変わらない）。§5 以降が v2 である。

## 1. 何を解こうとしているか

SO のレーンが返らないとき、`so-compare` は原因の違う複数の故障を同じ値に畳んでいる。畳まれている限り、待っても直らないものを待ち、恒久的な故障を「そのうち直る」と読む。実害はすでに出ている（#299 の実装SO が2レーンで締められ、あとから返った3レーン目が重い欠陥3件を出した）。

**本プランが増やすのは「なぜ返らなかったか」を機械が言える範囲であって、返らないこと自体は減らない。**

- **「claude は stdout を見る」という設計は、いまの既定経路では B-2 の型を拾えない。** 上限文言が平文で出るなら、それは `claude-raw.json` に入り `claude-stdout.txt` は空になる。
- 本プランの初版は「B-2 と B-3 のどちらも `raw.json` が空だった」と書いていたが、**B-2 にはそのファイル自体が無い。** 記述が誤っていたので取り消す。
- **claude が上限に当たったとき、いまの JSON 経路で何がどのファイルに落ちるかは未測定である。** `.result` に入るなら `claude-stdout.txt` に載るが、確かめていない。

### 分けられないものは「分けられない」と書く

**B-3 を `usage_limit` と断定してはいけない。** #303 のときに原因が分かったのは「6時間後に同じプロンプトが返った」「owner が上限のリセット待ちを踏んだ時間帯と重なる」という**プロセスの外の情報**によってである。meta にあるどのキーからも導けない。

したがって本プランの分類は、**確定できるところまでしか言わない**設計にする。B-3 に付く値は `unknown`（原因不明の空返し）であって `usage_limit` ではない。

## 4. 撤回する判断と、残す判断

**撤回する。**

- **「claude は stdout を見る」**（指摘4）。いまの既定経路と噛み合わない。claude の観測点は、上限時に JSON の何がどこへ落ちるかを測ってから決める。
- **「入力の検査はプロンプト組み立て完了時点の1箇所に置く」**（指摘7・8）。取り逃す経路が具体的に列挙された。**境界ごとに置き、最後に共通の検査を足す**形へ変える。
- **「拒否したときは exit 3 を返す」**（指摘6）。`oe-refute` の `refuted` と同じ値になる。**別の値にするか、上位ツールに明示の分岐を先に入れる**。どちらにするかは実機で確かめてから決める。
- **「PR-1 → PR-2 の順で分類を先に入れる」**。消費者に届かない分類を先に入れても、判断は何も変わらない（指摘1・2・3）。順序を変える。

**残す。**

- **`timeout_status` を壊さず、原因を別のキーで持つ方向**。3レーンとも方向自体は妥当としている。
- **分からないものを断定しない原則**。B-3 を `usage_limit` と書かない。
- **経路によって拒否と修復を使い分ける方針**。ただし基準の言い方は直す（下記）。

## 5. gate 3 の裁定（owner・2026-09-07）

| # | 論点 | 裁定 |
|---|---|---|
| HG-A / HG-B | 段階2 の入り方 | **測定と実装を同時に進める。** 測定だけで止めない。分類の目的を「診断記録」に限定せず、**消費者に届く形まで含める** |
| HG-C | 追い打ちの極小プロンプト（canary） | **試す。** 測定の中で、数秒の上限・空返しの直後に1往復 |
| HG-D | claude の上限を statusLine の `rate_limits` から先行検知する案 | **起票しない。** board にメモだけ残す |
| HG-E | gate 2 の再走 | **いまは再走しない**（統括判断）。弱 SO は1周で足りる規約に従う。**分類の契約は測定の結果で確定させ、そのとき設計SO を1周回す**。実装 PR はそれぞれ gate 4 を通す |

**この裁定は §4 の「撤回した判断」を復活させない。** 撤回した4件（claude の観測点・1箇所検査・exit 3・実装を先に入れる順序）は撤回のままである。裁定が変えたのは**測定と実装を同時に走らせるかどうか**であって、崩れた設計の中身ではない。

## 6. 2つの列

**衝突しない範囲で分ける。** 測定の列（M）は判定材料を作り、実装の列（I）は道具と経路を作る。**I-1 は両方に属する**（測定の道具そのものである）。

### 順序

```text
I-1 ──→ M-1 ──────────────→ M-2 ──→ M-3（設計SO 1周・終端）
   └──→ I-3（並行可）
                     I-2 ──┘（暫定 enum で出し、M-3 の確定後に更新）
```

- **PR は積み上げない。** 列が独立なので、各 PR は master から切る。
- **SO は1本ずつ。** canary の実験も並行させない。
- 各 PR は 1 論理変更・gate 4（弱2レーン）・Copilot・`shellcheck`・陽性対照。**マージは owner。**

## 7. 測定の列（M）

### M-1: いまの版で空返しを集め直す

**初版の母集団は使えない。** 収集期間中に `so-compare` 自身が4回変わっており（§2）、すでに直った故障の残骸が混じっている。

- やること: PR #376 反映後の版（cursor は `composer-2.5`）で回した SO の出力から空返しを集め、I-1 のコマンドで分類する。
- **so-compare の版を meta に必ず残す。** これが無いと同じ汚染を繰り返す。いまの meta には CLI の版（`cli_version`）はあるが、**`so-compare` 自身の版が無い。**
- 出すもの: 版で層別した `unknown` 率。**`unknown` でない側がどれだけ残るか**が、分類の粒度を決める材料になる。
- **期待値を先に宣言する**（測ってから決めない）。初版の母集団では 45 件中 41 件（91%）が `unknown` だった。**いまの版では D（不正な UTF-8・#345 で発生源が塞がれた）と E の一部が消えるので、`unknown` 率は上がると予測する。**

### M-2: canary（空返しの直後に極小の1往復）

- やること: レーンが空で返った直後に、**そのレーンへ数秒の上限で極小のプロンプトを1往復**投げ、結果を記録する。
- **まず実験フラグの下に置く**（既定は無効）。本番の経路には入れない。
- **期待値を先に宣言する。**

| 本走行の型 | canary の期待 |
|---|---|
| 時間切れ（A-1 / A-2 / A-3） | **成功する**（数秒で返る） |
| 使用量上限（B-1 / B-2 / B-3） | **上限の文言つきで非ゼロ**（数秒） |
| 認証切れ（C） | **認証の文言つきで非ゼロ**（ほぼ0秒） |
| 環境エラー（E） | 環境の文言つきで非ゼロ（ほぼ0秒） |

- **陽性対照**: `SO_TIMEOUT=5` で人為的な時間切れを作り、同じ canary が成功することを確かめる。P-1 の表の各型に対して1例ずつ取る。
- **取れない型は取れないと書く。** cursor の上限は実例が無く、claude の上限は起きるまで待つしかない。**待てない型は「未取得」と明記し、canary の判定範囲から外す。**

### M-3: 分類の契約を確定する（終端）

- やること: M-1 と M-2 の結果から、**meta だけでは分けられない形を canary が分けられるか**を判定する。
- 判定を受けて、分類の契約（`failure_reason` の enum・meta のキー・exit code）を確定する。
- **ここで設計SO を1周回す**（gate 2 の2周目・弱3レーン・1本ずつ）。
- **この報告で STOP する。** I-2 の確定版はその後の裁定で決める。

## 8. 実装の列（I）

### I-1: 読み取り専用の外部分類コマンド

**3レーン中2レーンが独立に出した案である。** 配布物（`~/bin` の symlink で全セッションに即反映される `so-compare`）を触らずに、過去の出力へ遡って分類を当てられる。**M-1 の道具でもある。**

- 置き場: engine の `bin/`。名前は `oe-lane-explain`（仮）。
- 入力: SO の出力ディレクトリ（`tmp/oe-refute-*` / `tmp/oe-review-*` / `tmp/so-*`）。単体でも一括でも当てられる。
- 出力: レーンごとに `{tool, timeout_status, failure_reason, failure_evidence, elapsed, limit, so_compare_version}` の JSON。集計モードでは版で層別した件数。
- **`so-compare` に1行も触れない**（diff で確認する）。

**設計要件（P-1 の失敗から）**

- **「ファイルが不在」と「ファイルが空」を畳まない。** 別のカテゴリとして数える。不在は「そのファイルを作らない版が生成した記録だ」という証拠である（`knowledge/items/01M1VX9MH72K7G940R6WC7M218.md`）。
- **stdout の文言でシグネチャに当てるとき、`exit_code=0` のレーンは対象外にする。** モデルの回答がプロンプト中の文言を引用しただけのケースを誤検出しないため（gate 2 の codex の指摘）。
- **当たらなければ `unknown` に倒し、`failure_evidence=none` を書く。** 断定しない。

**受け入れ基準**

- [ ] 過去の全出力ディレクトリに一括で当たり、版で層別した `unknown` 率を出す
- [ ] P-1 の7種の fixture で期待した値が付く
- [ ] **B-3 の fixture で `unknown` が付く**（`usage_limit` と書かないことを固定する）
- [ ] **成功したレーンで値が付かない**（陽性対照）
- [ ] **`exit_code=0` かつ stdout に上限の文言を含む fixture で誤検出しない**（陰性対照）

### I-2: 分類を消費者へ届ける

### I-3: 入力を型付きの理由で拒否する（#344）

- **exit code は `oe-refute` の `refuted`（3）と衝突しない値にする。** `oe-refute` / `oe-review` は `refuted` のとき exit 3 を返す（`bin/oe-refute` の help・`lib/so-verdict.sh:119-125`）。**入力拒否が「設計が反証された」として上位に届く経路を作らない。**
- 型付きの理由は先例 `cli_version_for()`（`scripts/so-compare.sh:562-597`）の作法に揃える。`invalid:not-found` / `invalid:empty` / `invalid:not-utf8` / `invalid:too-large` / `invalid:ambiguous-args` / `invalid:not-a-number`。
- **検査は1箇所ではなく境界ごとに置く**（§4 で撤回済み）。

| 位置 | 何を見るか |
|---|---|
| 引数解析の直後 | `-c` の各ファイル（実在・非空・UTF-8）／`-f` のファイル（実在）／`-w` のパス（実在） |
| 引数解析の直後 | `-c` が問いを食っていないか（ハイフンなしの引数を全部取る癖・`scripts/so-compare.sh:211-217`） |
| 環境変数の入口 | `PREV_MAX_BYTES` などの数値（`SO_TIMEOUT` はすでにここに在る） |
| プロンプト組み立ての完了時点 | 最終的な本文が UTF-8 として妥当か・上限内か（取り逃しの最後の網） |

- **拒否の経路は母集団側から列挙する。** 思いついたものを並べるのではなく、実際に不正が入りうる引数と環境変数を洗い出してから決める。
- **基準は「その入力の権威がどこにあるか」。** 利用者が明示的に指定したもの（`-c` / `-f` / `-w`）は拒否する。ツールが自分で作った参考情報（`--prev` の切り詰め）は修復してよいが、**全損したときは拒否に倒す**（現状は警告だけで続く）。

**受け入れ基準**

- [ ] 不正な入力を意図的に作り、**経路ごとに**拒否が発火する
- [ ] **正当な入力が今までどおり通る**（陽性対照。既存の SO を1本実際に回して緑）
- [ ] `so-compare -c a.md "問い"` が `invalid:ambiguous-args` で止まる
- [ ] `--prev` の警告つき修復が回帰していない。**ただし全損時は拒否に変わる**ことをテストで固定する
- [ ] **終了コードを経路ごとに実際に走らせて確かめ、結果を PR 本文の表に書く**
- [ ] **`oe-refute` / `oe-review` が拒否を「反証」と取り違えない**ことを実機で確認する
- [ ] 誤ったときの revert 手順が PR 本文にある（#344 の受け入れ条件）
- [ ] `shellcheck` が緑・既存テストが緑・gate 4・Copilot
