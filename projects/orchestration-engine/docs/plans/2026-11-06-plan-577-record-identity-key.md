# #577 engine の記録の鍵を tmux のペインから切り離し、こちらで作る ID にする

## 背景

owner と統括が #355（統括の復帰）の見取り図を読む中で、統括の復帰がいつも手作業になるのは、engine の記録が tmux のペインの番号（と tmux server の pid）を「誰か」の鍵に兼ねているためだ、という見立てになった（2026-11-06・#577 の背景）。2026-09-09 から 10-30 までの5回の復帰は、どれも人と統括が登記・統括の席・子の宛先を手で張り替えた。この plan は、こちらで作る ID（席の ID と代の記録）を鍵にし、ペインを観測する属性に下げる。

## この plan の範囲

- 委譲は**設計まで**である（brief の終端は P3、分身レビューの指摘を直す指示が来たら P4）。実装（I1 以降）は、ゲート3 の承認のあとに統括が送る実装の追補の書面で始める。
- 範囲の外: engine の `oe`（WezTerm の道）・復帰のスキル（#355）・統括のセッション名（#576）・全統括をまとめて戻す形・board の frontmatter への移行・セッション間の文を送る機能で送る道を替えること（owner の答えによる・DJ-10）。

### 実機の確かめ

- **R2（statusLine が環境を受け継ぐか）**: PR-2 で、`OE_SEAT_ID` を入れて起こしたセッションの拍動の sidecar に、席の ID が載ることを見る。R1 と同じ使い捨てのセッションで見る。載らなければ、DJ-3 の「session_id の並びで絞る」だけで動くことを、PR-2 のテストで固定する。
- **R3（前面のプロセスグループが claude を指すか）**: PR-3 で、子が自分のペインについて、入力待ちのときと、Bash の道具で長いコマンドを動かしているときの2つで、ペインの端末の前面のプロセスグループの番号と `CLAUDE_PID` を読んで比べる（自分のペインだけを読む）。道具の実行中に外れるなら、送る側は「確かめられない」で止まり、少し待って確かめ直す形にする。
- **R1（issue の「resume したセッションが自分の ID を知る道を決め、実機で確かめる」）**: PR-2 のあとに、使い捨ての claude のセッションを1つ、`OE_SEAT_ID` と一時ディレクトリの state を入れて起こし、終了し、`claude --resume <id>`（id を付けて）と、id を付けない `claude --resume` の両方で戻して、環境の `CLAUDE_CODE_SESSION_ID` と名乗る verb の結果を見る。claude を起こすのは owner の手を1回借りる（子は自分でセッションを起こさない）。生きている統括と子には触れない。
