# register-metrics — 会話面の応答レジスタを転記から測る

Issue #348 のために作った測定スクリプト群である。Claude Code の転記（JSONL）から、人間宛の応答だけを取り出し、読みづらさの代理指標を数える。

## 何のためにあるか

owner が「会話面の応答が読みづらい」と観測した。output style で直せるかを、合成した題ではなく**実運用の記録の前後比較**で測る。計画は `docs/harness/plans/2026-09-05-plan-348-output-style-observation.md` にある。

## 構成

| file | 役目 |
|---|---|
| `metrics.py` | 応答1件の指標を出す。層（散文 / 箇条書き / 表 / コード）を分け、記号と体言止めは 1,000 文字あたりに正規化する |
| `corpus.py` | 母集団を作る。セッション単位の除外規則（委譲子 / agent 間のレーン / 計測 probe）と、介入前の変数による層別を持つ |
| `aggregate-arms.py` | 腕別に集計する。前 / 後 v1 / 後 v2 をセッションの開始時刻で分け、凍結した閾値でフラグ率を出す |
| `runners/run-one.sh` | headless の1 run を走らせて記録する |
| `runners/run-fork.sh` | 実文脈の fork 対比。`--fork-session` を必ず付けて元のセッションに書き足さない |
| `runners/run-fork-batch.sh` | 上をまとめて流す |
| `runners/extract-assistant.py` | 転記から assistant の応答本文だけを抜く |

## 使い方

腕別の集計（R-2 で最初に打つコマンド）:

```bash
cd projects/orchestration-engine/scripts/register-metrics
python3 aggregate-arms.py \
  ~/.claude/projects/<転記の置き場> \
  --exclude-ids ../../../../docs/harness/measurements/348-fork-exclude-ids.txt \
  --out /tmp/348-arms
```

**`docs/harness/measurements/` の中身は committed に置いていない**（owner 裁定・2026-09-10）。#348 を測った本人の手元にはあるが、clone しただけの環境には無い。**無ければ `--exclude-ids` を外して回せる**（fork で生まれたセッションが母集団に混じるだけで、集計器そのものは動く）。測った数値は `docs/harness/episodes/2026-09-07-episode-348-measurements.md` の散文にある。

応答1件だけを測る:

```bash
python3 metrics.py --prompt <題のfile> --required <required.json> <題名> <応答のfile>
```

## 凍結した閾値（2026-09-05 の HG-2 承認時に固定）

| 軸 | 閾値 |
|---|---|
| 強調記号（`⚠ ❗ ‼ ★ 🔴 🚨 ✅ ❌`） | 1 個以上 |
| 内部語の種類数 | 4 以上 |
| 文の数 | 37 以上 |
| 英語語の密度（1,000 文字あたり） | 26.52 以上 |

1軸でも超えたら「フラグ」を立て、**フラグ率**を腕の間で比べる。閾値は後の腕を見てから動かさない。

内部語の**拡張リスト**（`jargon2_*`）は参考列であり、**採用ゲートには使わない**。指摘された文から語を拾って足すと、その文に合わせた物差しになるためである。

## 分かっている限界

- **指標は会話の応答に当てるものである。** 閾値は応答の分布から取った。手順書のような文書に当てると意味の無い警告が出る。
- **指標は取り逃す型がある。** owner が「理解しづらい」と名指しした 146 字の応答に対して、凍結した4軸はフラグを1つも立てなかった。原因は語彙ではなく言い方（人が会話で言わない言い回し）だった。言い方は数えられないので、判定は人の読み評価に残してある。
- **内部語は語彙リスト方式である。** 読者が定義を渡されていない語は文脈に相対的なので、固定リストでは原理的に追いつかない。
- **体言止めの検出は文末の飾りに弱い。** 括弧の注記・インラインコード・強調記号・コロンで終わるラベル行を剥がしてから判定するが、8回直した経緯がある。新しい型が出たら直す前提で使う。
- **構造（見出し・箇条書き・表）は JSONL からしか測れない。** terminal の export は markdown 記法を落とす。
- 層別は近似である。介入前の変数（直前の owner 発話）で切ると、多くが「その他」に落ちる。ゲートには使わない。

## 捨てたもの

`run-batch.sh`（合成した題を 45 run 走らせる v2 の駆動器）は、v2 の設計ごと捨てた。合成した題では測りたい病理が再現しなかったためである（計画の §1 参照）。合成 run を足すときは、計画の §7 の隔離（`--setting-sources ""` と `--model` の固定、fixture を被験セッションの cwd から見えない場所に置く）を当てる。
