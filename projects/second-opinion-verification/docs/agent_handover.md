# Agent Handover Interface: Second Opinion Verification

このドキュメントは、**将来のAIエージェント（またはあなた）** が、このプロジェクトの検証成果を「最小限のコンテキスト」で理解し、さらに拡張・オーケストレーションへ発展させるためのインターフェース定義書です。

## 1. Context Loading Strategy (最小コンテキスト読込戦略)

この検証成果を利用・拡張する場合、全てのファイルを読み込む必要はありません。以下の順序で情報を取得し、必要に応じて詳細へドリルダウンしてください。

1.  **Level 0 (Overview)**: `README.md`
    - プロジェクトの目的（セカンドオピニオン検証）とディレクトリ構造のみを把握する。
2.  **Level 1 (Core Logic)**: `docs/decisions/ADR-001-shell-timeout-pattern.md`
    - 「結論として何が正しいとされたか」だけを理解する。
    - ※ここに書かれているコードパターンは「検証済み資産」として信頼してよい。
3.  **Level 2 (Deep Dive)**: `docs/episodes/*.md`
    - **Level 1** の結論に至った「議論の経緯」や「却下された案」を知りたい場合のみ参照する。
    - 通常の実装タスクでは読み込み不要（意図的圧縮の効果）。

## 2. Orchestration Protocol (拡張時の指示プロトコル)

この検証をベースに、さらに複雑なタスク（例：自動修復エージェント、マルチエージェントオーケストレーション）へ拡張する場合、以下のプロトコルに従って指示を出してください。

### 指示出しの基本原則
- **役割の明示**: Primary（実装）と Second（監査）を分離する構造を維持する。
- **Artifactの継承**: 新しい検証を行う際も、`episodes/` にプロセスを記録し、`decisions/` に結論を昇格させるフローを踏襲させる。

### Prompt Template (拡張用プロンプト例)

あなたが次のエージェントに指示を出す際は、以下のテンプレートを利用・改変してください。

```markdown
# 依頼: 検証成果の拡張と適用

## 前提コンテキスト
`projects/second-opinion-verification` の成果（特に `ADR-001`）を参照してください。
ここでは「セカンドオピニオンによる品質担保」と「意図的圧縮」が確立されています。

## 今回のタスク
この検証モデルを拡張し、[新しいターゲット、例: Pythonスクリプトの自動リファクタリング] に適用してください。

## 制約と振る舞い
1. **Context**: `ADR-001` のシェルスクリプト知見は参考にしつつ、言語固有の違いは吸収してください。
2. **Process**: 今回も Primary (実装) と Second (監査) の役割を演じ分け、議論プロセスを `docs/episodes/` に記録してください。
3. **Output**: 最終的な成果物は `docs/decisions/` に新しいADRとして圧縮してください。
```

## 3. Future Expansion Points (次の検証テーマ)

このプロジェクトから派生できる検証テーマの候補です。

- **自動化されたオーケストレーション**:
  - `claude` CLI を使って、Primary AI と Second AI が人間の介在なしに相互レビューするスクリプトを組む（`src/orchestrator.sh` の作成）。
- **多言語展開**:
  - `ADR-001` の「Watchdogパターン」を Python や Node.js 等のランタイムがない環境（Go/Rustバイナリ等）にも適用できるか検証する。
