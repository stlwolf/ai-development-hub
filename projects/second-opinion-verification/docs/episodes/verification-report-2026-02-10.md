# claude-safe 疑似オーケストレーション検証レポート

> **実施日**: 2026-02-10
> **検証目的**: Cursor Agent と Claude Code CLI の同期的コミュニケーションによるマルチエージェント協調の実用性検証

---

## 検証概要

実プロダクトのバグ修正タスク（5件のdeprecation警告修正、8ファイル変更）を題材に、`claude-safe` 経由で Claude Code CLI をセカンドオピニオンとして活用する疑似オーケストレーションを実施した。

### 実施フロー

```
Cursor Agent (親)
  │
  ├── 1. Issue/エラー監視情報収集・プラン策定
  │
  ├── 2. claude-safe → Claude Code (プランレビュー v1)
  │     └── 指摘2件 → プラン修正
  │
  ├── 3. claude-safe → Claude Code (プランレビュー v2)
  │     └── 問題なし → 実装GO
  │
  ├── 4. コード修正・コミット・PR作成
  │
  ├── 5. claude-safe → Claude Code (PRレビュー /review)
  │     └── Approve判定
  │
  └── 6. claude-safe → Claude Code (Copilotレビューの妥当性検証)
        └── Copilotのレビュー指摘3件を検証 → 1件却下、2件スコープ外
```

## 検証結果

### 各ステップの実行結果

| ステップ | コマンドパターン | 所要時間 | 結果 |
|---------|-----------------|---------|------|
| プランレビュー v1 | `claude-safe -p "$(cat file)"` | 約82秒 | 有効な指摘2件（スコープ拡大、説明修正） |
| プランレビュー v2 | `claude-safe -p "$(cat file)"` | 約33分 | 問題なし確認 |
| PRレビュー（失敗） | `claude-safe -p "PRをレビューして..."` | 18分→ハング | **ツール承認問題で停止** |
| PRレビュー（成功） | `claude-safe -p "/review #N"` | 即座 | Approve with minor suggestion |
| Copilotレビュー検証 | `claude-safe -p "/review ... に対する指摘..."` | 約100秒 | 3件の妥当性検証完了 |

### 実際に得られた価値

**1. スコープ判断の補完**

Cursor側の「最小スコープ」原則で除外していた同パターンの関連ファイルについて、Claude Code が「将来のバージョンでエラー昇格リスクがあるため含めるべき」と指摘。この指摘を採用し、修正対象を拡大した。

- **効果**: 将来の再作業を防止。修正コストは極めて低かった
- **教訓**: 単一エージェントの原則に縛られた視点を、別エージェントが補完できる

**2. 技術的正確性の検証**

演算子優先順位の変更に伴う計算結果の同値性を数学的に検証。プラン説明文の不正確な記述を修正した。

**3. Copilotレビューのトリアージ**

GitHub Copilot のレビューコメント3件について、Claude Code が独立した視点で妥当性を検証:
- コメント1: **Copilotの誤り**を検出（ガード条件の見落とし）
- コメント2-3: 指摘自体は正しいがPRスコープ外と判定

## 発見した問題

### 問題1: 非インタラクティブモードでのツール承認ハング

**症状**: `claude-safe -p "PRをレビューして。gh pr view と gh pr diff で確認して..."` が18分以上ハング

**原因**: Claude Code が `gh` コマンドを実行しようとしたが、非インタラクティブモードではBashツールの承認プロンプトに応答できず、無限リトライループに陥った。

**証拠**（`claude -c` で確認したセッションログ）:
```
⏺ Bash(gh pr view 5081)
  ⎿  Error: This command requires approval

⏺ Bash(GH_PAGER=cat gh pr view 5081)
  ⎿  Error: This command requires approval
```

**回避策**: `/review #N` のようなスラッシュコマンドを使用すると、Claude Code 内部で異なるコードパスが使われ、ツール承認を必要としない形でPR情報を取得できる。

**重要な知見**: `-p` のプロンプト内で外部ツール実行（`gh`, `curl` 等）を暗示する指示は、承認ループのリスクがある。プロンプトで「〜を実行して」と書くのではなく、スラッシュコマンドに処理を委ねるべき。

### 問題2: 実行時間のばらつき

| ケース | 所要時間 | 備考 |
|--------|---------|------|
| プランレビュー v1 | 82秒 | 安定 |
| プランレビュー v2 | 33分 | API待ち? |
| /review | 即座 | キャッシュ? 前セッションの結果? |
| Copilotレビュー検証 | 100秒 | 安定 |

v2の33分は異常に長い。API側のレイテンシまたはレート制限の可能性。

### 問題3: `-p` でのスラッシュコマンドの挙動が不透明

`claude-safe -p "/review #N"` が即座に結果を返した（249ms）理由が不明:
- `/review` がClaude Code内部で特別なパスで処理される可能性
- 前セッション（`-c`で入ったインタラクティブセッション）の結果がキャッシュされていた可能性
- `claude-safe` の nohup 出力ファイルに前回の結果が残っていた可能性

→ 再現性の確認が必要。

## 改善点

### claude-safe コマンドの改善

**P1（高優先度）:**

- **ツール承認対策**: `--dangerously-skip-permissions` フラグ対応を検討。非インタラクティブモードではツール承認がボトルネックになるため、明示的にスキップするオプションを提供
  ```bash
  claude-safe -p "..." --skip-permissions  # claude --dangerously-skip-permissions に変換
  ```
- **タイムアウト設定**: ハング検知と自動kill。デフォルト300秒、設定可能に
  ```bash
  TIMEOUT=300 claude-safe -p "..."
  ```

**P2（中優先度）:**

- **スラッシュコマンド対応の明文化**: `/review`, `/diff` 等のスラッシュコマンドが `-p` モードで正しく動作するか検証し、ドキュメント化
- **セッション継続の制御**: `-c` オプションとの組み合わせ検証。前セッションのコンテキストを活用したいケースがある
- **実行ログの保存**: 各実行の入力プロンプト・出力・所要時間をログファイルに記録
  ```
  ~/.claude-safe/logs/YYYY-MM-DD_HHMMSS_review.log
  ```

**P3（低優先度）:**

- **並列実行対応**: 複数の claude-safe を並列で走らせた場合の出力ファイル競合防止
- **リトライ機能**: タイムアウト時の自動リトライ（最大N回）
- **JSON出力モードの最適化**: `--output-format json` の結果をパイプラインで使いやすくする

### Cursor コマンド / ルールへの組み込み

**新規コマンド案:**

1. **`/claude-review`** - PR番号を受け取り、claude-safe でコードレビューを実行
   ```bash
   claude-safe -p "/review #${PR_NUM}" --output-format text
   ```

2. **`/claude-second-opinion`** - 現在のプランや修正方針をClaude Codeにレビュー依頼
   ```bash
   claude-safe -p "$(cat $PLAN_FILE) 上記のプランをレビューしてください" --output-format text
   ```

3. **`/ai-review-triage`** - Copilot等のレビューコメントを取得し、Claude Codeに妥当性検証を依頼するワンストップコマンド

**既存コマンドの拡張:**

- レビュー応答コマンドにClaude Codeへの転送オプションを追加
- エラー監視CLIの分析結果をClaude Codeにもレビューさせるオプション

## 教訓サマリ

| # | 教訓 | 詳細 |
|---|------|------|
| 1 | **スラッシュコマンドを優先** | `-p` でツール利用を暗示するプロンプトはハングリスク。`/review` 等の組み込みコマンドが安定 |
| 2 | **単一エージェントの原則バイアスを別エージェントが補完** | 特定の原則に縛られた視点を、別視点から指摘できた |
| 3 | **Copilotの指摘は鵜呑みにしない** | コンテキスト不足による誤指摘がある。セカンドオピニオンが有効 |
| 4 | **非インタラクティブモードの制約を理解する** | ツール承認、ファイル権限等、インタラクティブモードと挙動が異なる |
| 5 | **実行時間のばらつきに備える** | タイムアウト・リトライ機構が必要。82秒〜33分の幅がある |
